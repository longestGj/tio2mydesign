# D23 ↔ D22 文章工作线与 Gate 1 接收合同 V1.0

日期：2026-09-08。状态：USER_APPROVED / ACTIVE_PROJECT_SOURCE。
批准来源：用户明确“同意，把这条文章工作线纳入总控。文章写完以后，也是从gate1开始。不用管Gate2.”。本合同接入既有文章工作线，不启动具体文章或页面，不修改 Gate 2。

## 1. 责任与路由

`D23选题 → 用户方向批准 → D22研究与写作及独立审查 → D23接收 → 用户正文批准 → 按授权从Gate 1开始页面流程`

| 对象 | 责任方 | 边界 |
|---|---|---|
| 选题与归属 | D23文章选题 Controller，由网站总控承担或明确指派 | 判断买家问题、意图差异、证据可行性和内容归属；不以选题登记新增页面或URL |
| 正文制作与专业审查 | D22写作 Controller 组织执行及不同身份审查者 | 消费冻结Brief，按D22当前有效流程研究、写作、编辑、审查和关闭；不决定网站架构或发布 |
| 跨项目接收与协调 | D23网站总控 | 核对身份、范围、有效审查链、开放项和可用性；不再完整执行D22专业审查 |
| 方向、事实及正文批准 | 用户 | 按已有批准范围继承；文章内容批准不等于页面Gate关闭或启动授权 |
| 页面承接 | 获授权的Gate 1执行者及其审查者 | 从Gate 1开始核对页面意图与研究缺口，不把文章写完视为Gate 1已通过 |

文章选题 Controller 是工作职责，不新增上级审批层或自动创建运行Agent。既有Application选题职责与计划继续有效；扩大到其他内容体系须有相应范围授权。

## 2. 总控调用与最小派发输入

沿用 STATUS、PREPARE、START、RESUME、ACCEPT_RESULT。文章任务使用 `work_type=ARTICLE`、稳定 `article_id` / `research_unit_id`，页面任务继续用 `work_type=PAGE_GATE`。文章无页面时 `page_ids`、页面Manifest及 `gate_scope` 可不适用，不填造Page ID；`content_owner` 只表示内容归属。

从既有Brief及派发记录解析以下字段，不另建重复台账：

- 对象：article_id、research_unit_id、content_owner、语言、篇数、工作范围、原始授权。
- 冻结Brief：精确路径及身份，读者、核心问题、必要覆盖、与邻近内容差异、事实/声明边界。
- 可复用输入：研究、证据及批准决定的路径、身份、用途与局限；动态事实的时效要求。
- 调度：dispatch_id、D22实际接收任务、执行/独立审查责任、读写范围、交回入口、停止点。
- 变化：初次或定向返修、受影响陈述/证据/审查范围、已有有效结果。

恢复既有在途任务，不同名重发。默认遵守现有逐题串行计划；用户明确授权例外时，在原控制记录列明对象、并发/顺序及停止点，不把例外推广为全队列授权。跨任务发送须有该具体任务的派发授权，本次治理修订不构成发送授权。

## 3. 研究与审查复用

D23研究回答“是否值得写、归谁、解决什么问题”；D22研究回答“正文论证由什么准确证据支持”。D23提供已有原始来源及局限，D22独立判断其适用性；来源可访问、身份可追溯且时效与范围满足时可复用，不因来自D23就重新检索或下载。具体补查须对应论证缺口、变化或时效要求，不降低D22专业标准。

本合同约束D23派发和接收，不声称已经修改D22内部Agent、Skill或流程；发生冲突由两侧Controller明确受影响范围，不能静默跳过有效内部审查。

## 4. D22交回与D23接收

复用现有交接入口，绑定六类权威对象：最终正文及读者Sources、声明/来源追踪、交接Manifest、读者质量结论、最终独立专业审查、D22 Controller关闭记录。保留D22实际名称（如A06/RQR、A00）和初审/定向复审完整链，不要求为同一结果复制新报告。

还须能解析作者/审查者实际身份、冻结Brief身份、开放项、未验证范围、声明限制及返修变化。D23核对文件存在和精确身份、链条绑定、独立性、批准范围及交接可用性；阅读正文以确认符合选题和网站范围，不逐条重建专业论证、重新联网验证全部引文或追加一个正文质量Gate。

| 异常 | 返回责任与最小处理 |
|---|---|
| 缺文件、索引错误或身份不一致 | D22 Controller补齐具体对象；核对字段与绑定，不默认重写正文 |
| 审查缺失、错版本或身份不独立 | D22安排适用的独立审查；不由D23冒签 |
| 具体正文错误或越界疑点 | D23列出陈述、依据、影响及REVIEW_CHALLENGE，由D22定向判断/返修和复审 |
| 题目、事实或范围需要新决定 | D23向用户呈现具体差异；暂停受影响部分 |
| 接收条件满足 | 直接提交用户正文决定；已有同一对象有效批准则继承，不重复询问 |

只有记录修正且正文及证据身份未变时，复核修正字段及链条；读者可见内容改变时生成新身份并按D22适用路径定向复审，不沿用旧审查证明新稿。总控不默改精确批准文章。

## 5. 批准文章交给 Gate 1

文章内容批准单独绑定精确稿件及用户决定。随后由总控核对页面登记、关键词/职责归属、批准Brief、原页面组合（如存在）、Gate 1启动授权及明确暂停。缺少新页面准入时先解决登记和范围，不能为绕过准入直接创建页面；文章ID不等于Page ID。

Gate 1输入为：批准文章及身份、用户批准、D22有效审查链、已有研究/来源与局限、内容owner及邻近主题边界、目标页面有效身份/Brief、开放项和启动依据。只引用既有成果，不重新包装整套文章档案。

Gate 1仍负责本页买家问题、意图、证据和页面职责确认，复用有效文章研究，只补本页缺口；既有有效Gate 1成果按实际变化定向核对，不因新增路由全量重做。文章完成、D22专业PASS和用户正文批准均不自动关闭Gate 1。后续按现行页面工作流及授权执行，本合同不规定或修改Gate 2交接。

## 6. 记录与迁移

沿用各研究单元的Brief、派发、接收和用户批准记录；页面开始后由该页唯一Manifest绑定文章输入。文章状态与页面Gate状态分别记录，不另建平行全站台账。

既有主文章、R01/R02及有效批准/审查不重做，不补造新的接收Gate。当前进度从Index指向的原记录恢复，本合同不硬编码已完成数量或下一篇。正文批准不自动授权HTML、开发、外发、部署、索引或发布。
