## 2. Semantic structure contract

- One `h1`: `Explore Titanium Dioxide by Application`.
- Page regions use ordered `h2` headings matching the seven retained body sections.
- Global navigation, breadcrumb and Footer navigation use distinct labelled navigation landmarks.
- Application quick navigation is a same-page list of six anchors.
- Application cards are labelled sections or list items; their grade collections are semantic lists.
- Desktop/Tablet Process data may use a table with explicit row/column headers. Mobile may expose the same data as three labelled lists without a decorative column header.
- FAQ question controls are buttons associated with answer panels.
- Footer markup must consume the approved shared component without APP-000-specific text, columns or entity expansion. The Production SVG Logo binding and approved visible Footer copy must not be replaced by raster fallback or page-level content.

## 5. Interaction and ARIA contract

### Links and CTA

- Linked pills, anchors and CTAs must be keyboard reachable.
- Hover and focus-visible states must be distinguishable; the visual state board uses a 3px focus reference.
- 390px buyer-visible `RFQ` retains the accessible name `Request a Quote`.
- No link uses `click here`.
- Minimum logical target is 44px for Mobile Header controls, menu rows, linked grade pills and accordion buttons.

### Accordion

- Each question uses a button, not a generic clickable container.
- Each button exposes `aria-expanded` and `aria-controls`.
- Each answer panel has the matching unique ID and is associated with its control.
- Enter and Space toggle the current item; Tab follows document order.
- Focus remains visible after toggle; collapsed content is removed from the accessibility tree.

## 6. What was and was not checked

Checked in planning assets/specifications:

- one intended H1 and rational heading order;
- meaningful link labels;
- visible focus references;
- 44px Mobile controls;
- full copy, contrast direction and no horizontal visual overflow;
- unique planned anchor IDs;
- exact Grade/Application/Process data and route-safe plain-pill state.

Not checked because no actual implementation was supplied:

- emitted DOM element types and heading count;
- duplicate IDs in runtime DOM;
- sticky-header anchor offset;
- keyboard event handling;
- actual ARIA values and state transitions;
- computed contrast and focus CSS in browser;
- real route responses.

These items remain mandatory Gate 9 read-only QA after external implementation.
