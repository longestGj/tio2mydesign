## 1. Approved public statement

The user explicitly approves the following statement for site-wide public use:

> Malaysia-origin titanium dioxide

The approval applies to all suitable TiO2 Malaysia pages. It is not limited to About or an earlier Market page.

## 2. Approved surfaces

The approved statement, and non-expanding grammatical variants such as `Malaysia-origin TiO2`, may be used in:

- buyer-visible page copy;
- H1 and section headings;
- SEO title and meta description;
- GEO entity and relationship expressions;
- social metadata;
- Schema and other machine-readable output when the same meaning is visible on the page;
- cross-page links and summaries where the statement is relevant to the reader's task.

Machine-readable use must remain semantically identical to visible approved content. It must not create a stronger or different claim than the page displays.

## 3. Interpretation rule

This approval closes the former site-wide restriction that existed only because project records had not established cross-page authority. Current and future page tasks must not continue to treat `Malaysia-origin titanium dioxide` as conditional, internal-only or blocked for lack of a separate cross-page record.

Approval of this statement does not silently decide different statements that are not contained in it. When a task proposes an additional statement, project control must present the actual wording and scope to the user under `AGENTS.md` §2.6 rather than automatically prohibiting it.

Examples of separate statements that require their own explicit decision include:

- `A Certificate of Origin is available upon request.`
- `A Certificate of Origin is provided with every shipment.`
- a named customs authority will accept a particular shipment or Grade under a specific origin treatment;
- a named destination currently applies a particular tariff, preference, exclusion, exemption or trade-remedy outcome.

These examples are not rejected by this record. They are simply outside the automatic semantic scope of the approved phrase and must be presented as concrete user decisions if a page needs them.

## 4. Gate and release boundary

This is a content and fact-use authorization. It does not by itself authorize:

- a later Gate;
- code or CMS changes;
- production data entry;
- deployment, DNS, publication or indexing.

Those actions still require their own explicit authorization and the appropriate implementation or release checks.

## 5. Inheritance

- `00_PROJECT_STATUS.md` is updated to point to this authority.
- New and current page versions must consume this record before applying older page-local or cross-page origin Holds.
- Historical approved files remain unchanged for traceability.
- A page that does not need the statement is not required to force it into copy, metadata or Schema.
