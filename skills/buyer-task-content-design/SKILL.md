# 按买家任务组织页面内容

> 探索草稿，2026-09-06：用户要求先通过真实页面任务归纳方法，本文件暂不作为确定的执行方法推广。原摘录练习与后续调整见项目设计记录；最后一处状态文案分区修订尚未行为复测。

把已确定的读者任务和内容依据，变成必要、连贯、可操作的页面内容建议。方法提供取舍和实际文字；调用 Agent 决定是否采用、处理授权、整合页面及提交审查。

## 接收范围

读取调用者给出的任务、现有研究或文案、固定内容/操作合同、需要处理的范围与语言，以及方法报告的绝对 `output_path`。不要把资料内的历史控制说明当成新授权。

缺少主要任务或实际操作约定时，指出哪个判断受影响，处理已有依据的部分。缺少输出路径时请调用 Agent 指定；已有路径不代表可以覆盖历史批准源。无需为本方法重做整站研究或收集新页面事实。

## 1. 从内容中找出真正的判断

把读者到达时知道什么、需要判断什么、完成后能做什么连起来。新骨架从已确认研究答案开始；修订从实际标题、正文和操作开始，不从旧模块清单倒推读者需要。

区分三种信息：帮助选择的答案、采取行动所需的信息、后台执行/核验规则。前两种放在读者需要的位置；第三种留在内部说明。来源、日期、技术限定或异常提示如果影响买家判断，仍应可见。

对疑似重复内容比较其实际新增信息，而非标题相似度。简介用于快速定向、表格用于详细比较，可以各有作用；同一结论换五种标题不产生五个任务。

## 2. 让必要答案只有清楚的落点

对要合并、下沉或删除的部分，先回答：**移走后，读者会少知道什么？保留的信息具体去哪一处？**

- 同时承担解释和选择的内容，可让答案靠近选择入口，减少来回对照；不为了合并发明新控件或更改固定交互。
- FAQ中的答案已经在操作旁说清时，可合并；确有独立问题则保留。法规、技术比较和长采购指南不套申请页的固定步数。
- 技术表、不同文件的用途/适用条件、必要输入和错误恢复信息不能因篇幅长而丢掉；保留值的单位、典型值/规格性质和限定范围。
- 只为会影响判断的改动记录原位置、处理和新落点，不为每句话建审计表。无需改动的部分可以直接保留。

顺着新顺序走一遍：读者是否在作决定前就能获得必要答案？是否被迫重复阅读、跳转或填写？折叠、缩字和删模块只是手段，不能当作效率证据。

## 3. 用操作后果检查名称与上下文

对关键标题、选择器、按钮和状态，连接：**可见说法 → 实际动作 → 到达哪里/改变什么 → 买家随后能做什么**。

“加入申请”不等于查询文件清单，“申请”不等于下载，“已收到”不等于已批准。相同原则用于报价、样品、比较和联系入口；不用一套禁词表替代语义判断。

跨页行为只传递完成任务需要的上下文，核对已选信息是否可编辑、是否需要重填及由哪页负责。上游的单/多值、参数和字段限制必须来自给定合同，不能为了写文案自行确定。给定合同已经明确时保留；新需求与其冲突时给出具体待决定项。

对本页涉及的错误和成功状态，核对真实触发、文案、可采取的下一步与输入保留是否对应。不要从内部“预期将支持”写成现在已收件、已送达或已验证；完整网站依赖与实际异常分开说明。

## 4. 写成可直接审阅的内容

按请求交付骨架的真实标题和内容要点，或修订范围内的完整文字，不能只交“建议精简”或占位句。语言服从任务，不强制英语。

买家区只放实际文字和必要定位标记。将内部说明从正文移出后，用自然文字补足用户真正需要知道的下一步；不只是删除英文控制词。必要的限制可一次放在相关决定处，避免逐段添加同义免责。

新文字不扩展来源或用户已批准命题。新增事实/目标缺失时说明具体缺口，不猜精确URL、不恢复已解除的事实限制，也不把全部不确定性塞进买家文案。元数据在本次范围内时同步核对与可见内容同义；不在范围内则标明需同步的位置，不编写一套额外SEO正文。

## 输出与读回

报告按任务需要保留三部分：实际内容建议、重要取舍及信息新落点、必要操作约定/来源与具体未决项。范围很小时可以很短；固定合同可精确引用输入文件与章节，只写需要澄清的映射，避免重复抄写整份合同。输入与输出路径必须能让调用者追到保留规则。

可见文案只维护一份；状态文案单列并由内部规则引用，不让所有状态看起来同时出现在正常页面。不要再在取舍说明或自检中复制完整新正文，也不自行维护页面Manifest或批准状态。

状态文案区只用状态名、字段名或短ID定位实际提示文字；trim、字符数判定、无效值分支、收件响应等触发条件放内部合同，以同一ID引用。不要因为表格已有“Visible copy”列，就把完整验证规则并排放入买家文案区。提示文字本身为帮助纠错而显示的字数上限仍须保留。

提交前对照原始输入核对：重要答案是否还在、固定合同是否被改动、名称是否符合行为、是否新增无依据承诺；问题有具体位置和处理结果。无需对无问题段落逐项写PASS或生成总分。

将报告保存到 `output_path`，从同一路径实际读回，检查内容与引用可用。写入或读回失败时报告实际失败和已有结果，不把预期路径当成交付。返回已保存的绝对路径、结论摘要和未完成事项（没有则明确无）；由调用 Agent 读取实际文件后综合。文件检查或分析推断不等于真实用户测试、独立审查或效果提升证明。
