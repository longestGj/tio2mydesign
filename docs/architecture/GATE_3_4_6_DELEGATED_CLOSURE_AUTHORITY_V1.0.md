# Gate 3、4、6 总控常设关闭授权 V1.0

日期：2026-09-07。决定ID：`G346-DELEGATED-CLOSURE-20260907`。状态：`USER_APPROVED_STANDING_AUTHORITY / ACTIVE`。

## 1. 用户决定与覆盖范围

用户明确“Gate3，gate4和gate6都已经成熟了，不需要我审核了”，随后批准所列修订方案：“按照你这个方案，进行修改。”本决定取消这三关的常规逐页用户审核与批准等待，由总控在满足以下条件后依常设授权关闭。适用于未来获准执行及当前在途的Gate 3、4、6，包括已独立审查通过、仅等待用户批准的成果。Gate 1、2、9、10及其批准方式不变。

本决定优先覆盖旧规则、Agent、Brief、批次合同、交付包中仅因三关常规成果批准而要求等待用户的文字。旧文件不改写；旧用户亲自批准记录继续有效，不伪造新的逐页用户审阅。

## 2. 关闭条件及职责

执行者完成制作、自检、冻结和提交；不同于相应成果作者的审查者完成独立审查。所有本阶段必修Finding关闭、证据覆盖完整且身份匹配、当前合同无未解决冲突、后置依赖有责任方和接受条件后，由总控登记`APPROVED / CLOSED`。Gate 6还必须完成新增交付合同的独立复核与唯一交付包，随后可登记`APPROVED_FOR_HANDOFF`。

Gate 3继续按结构范围审查；Gate 4保持4A内部检查和4B完整冻结后的一个最终独立审查环节；Gate 6继承有效上游，仅按变化、缺口或冲突展开复核。自检不能替代独立审查；换角色名称不能审自己的作品。返修由执行方完成，独立复验锁定新组合；未通过时继续返修，不自动放行。

三关状态流：`DRAFT_FOR_PROJECT_CONTROL_REVIEW` → `PROJECT_CONTROL_REVIEW_PASS` → `APPROVED / CLOSED`。不再进入常规`PROJECT_CONTROL_REVIEW_PASS_PENDING_USER_APPROVAL`。保留执行、审查、关闭三个事实；总控不得把方法PASS、文件存在或hash一致直接当成阶段通过。

## 3. 记录方式

关闭记录与当前页面Manifest至少记录：Page ID、Gate、`approval_basis=USER_STANDING_AUTHORITY`、本决定ID/路径、独立审查者与报告、精确冻结组合及身份、必修Finding状态、关闭人和日期、后置依赖、下一阶段授权。常规逐页用户审核记录为`NOT_REQUIRED_BY_STANDING_AUTHORITY`，不能写成用户已亲自审阅本页。沿用`APPROVED / CLOSED`，不要求新建一套生命周期状态。

Gate 3关闭后形成正式Gate 3→4交接；Gate 4关闭后形成Gate 4→6接收；Gate 6关闭形成就绪包。以精确引用组织，不复制正文，不重画未变资产。Skill只负责方法与证据，不登记阶段批准。

## 4. 连续执行与例外

已获准连续执行的页面可在Gate 3→4→6范围内直接推进，不再在三关等待用户确认。只有单关执行授权时，完成该关关闭与交接就绪后停在原启动边界；本决定不自动启动全部页面或恢复明确暂停的任务。旧文件单纯写“待本关用户批准”的停止项由本决定覆盖；明确的暂停、未授权下一关和范围排除仍保留。

普通布局、视觉参数、既有合同内的交付整理由Agent判断和独立审查，不升级为用户决策。新增事实、改变页面职责/URL/主关键词、重大品牌或共享合同变化及其他超出既有授权的决定仍按原权限处理，只暂停受影响部分，继续不受影响工作。不能用本授权批准新的企业事实或取消未解决合同冲突。

Gate 6关闭只表示交付就绪。外发、Gate 8开发、部署、发布、DNS、索引保持独立授权；有既有明确授权则按其范围执行，不重复索取。未获外发授权不发送消息。Gate 9只读验收及Gate 10发布条件保持。

## 5. 在途迁移

总控读取当前Manifest、独立审查及原始冻结身份，重新核对证据身份和未决项。仅剩常规用户批准等待的，依据本授权生成新关闭记录及新版当前Manifest；不要求用户补点批准，不重做有效审查。不具备独立审查、必修尚未关闭或身份不匹配的，继续原审查/返修流程，不能批量替换状态。

规则生效不等于每页自动通过。历史候选、审查报告和旧批准包保留原文及hash，由新版关闭记录覆盖其过时的等待状态。当前迁移结果与校验见[实施记录](GATE_3_4_6_DELEGATED_CLOSURE_IMPLEMENTATION_V1.0.md)。
