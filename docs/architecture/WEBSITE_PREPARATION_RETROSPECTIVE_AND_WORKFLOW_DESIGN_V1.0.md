# Gate 1之前工作复盘与网站级准备流程设计 V1.0

日期：2026-09-11。状态：DESIGN_PROPOSAL / PENDING_ACTIVATION。
用户认可前次复盘方向并要求“同意，执行下一步。”，本次授权为编写正式设计和本项目映射。设计产出不自动修改现行Gate、Agent、Skill、页面批准或新网站执行权限。

## 1. 目标与结论

为批量建设工业品B2B独立站建立可重复的网站级准备过程。复用工作方法、行业适配和已有有效资料，不复制其他企业事实、网站批准或固定TiO2架构。

现有页面流程较明确；网站级目标、资料、研究、架构及生产准备散落于对话、PRD、表格和增补。应在现有Gate 0之前补充网站级准备工作流，保持Gate 0具体页面准入、Gate 1本页研究与意图确认的职责。

本复盘为文档证据分析，不是全库逐文件审计、独立运行试验或市场效果评价。没有统一历史计时，不能量化前期浪费或承诺提速比例。历史法律、市场与SERP观察仅说明当时工作，不作为今天的事实验证。

## 3. 方案比较与选择

| 方案 | 好处 | 代价/风险 | 选择 |
|---|---|---|---|
| 全部塞入Gate 1 | 少一个流程名称 | 每页重复全站准备，职责过大 | 不采用 |
| 全部塞入Gate 0 | 一个入口覆盖全部 | 网站一次准备与逐页准入混合 | 不采用 |
| 网站级准备＋现有逐页Gate流程 | 按频率、对象分工，后续可复用 | 需明确交接与维护责任 | 推荐 |

建议链路：网站级准备 → Gate 0具体页面准入 → Gate 1三路径 → 原有后续流程。五个工作包不是五个新Gate、五次审批或五个新Agent。

## 4. 五个工作包及完成边界

| 包 | 输入 | 关键工作与结果 | 就绪/停止条件 |
|---|---|---|---|
| W1 商业与站点定位 | 用户需求、已有站点、业务和资源约束 | 定位、客户、产品/市场范围、主要行动、站点分工、成功观察方式 | 重要方向可供用户决定；不无限扩展策略或保证询盘效果 |
| W2 企业产品事实 | 用户资料、产品目录、技术文件及有效决定 | 实体、产品/服务模型、命题证据、关系、许可用途及缺口 | 首批核心命题可追溯；缺口有owner和影响，不要求所有产品资料先齐备 |
| W3 买家与需求研究 | W1方向、W2实际供给、初始架构假设 | 采购问题、意图、搜索/竞争观察、语言市场、需求局限及候选机会 | 重要架构决定有依据；新搜索不改变决定则停，无词数/查询数配额 |
| W4 架构与完整旅程 | W1–3有效结果 | 页面分工、关键词归属、导航/主要内链、转化和系统路径、共享owner、品牌方向及首批范围 | 首批职责不冲突，入口/动作/后续结果有归属；不提前写全站正文、视觉或完整开发包 |
| W5 生产准备 | W4架构、既有技术与设计资产、角色/权限 | 网站基线引用、首批Brief输入、批次/依赖、复用能力和验收范围方向 | Gate 0可准入首批页面；不要求所有页面或生产服务先实现 |

W2/W3可在方向明确后交叉推进；W3/W4允许有界迭代，研究可推翻初始架构假设。发生方向、事实或范围变更时提出具体决定，不静默扩大。研究排序同时显示商业判断、证据充分性及数据缺失，缺失不等于没有需求。

## 5. 全站准备与后续阶段的边界

| 对象 | 网站级准备 | 后续阶段 |
|---|---|---|
| 页面内容 | 任务、范围及已知答案 | Gate 1补本页研究；Gate 2完整正文 |
| 品牌/视觉 | 已有资产、品牌方向和共享owner | Gate 3结构；Gate 4完整视觉，不提前批量做图 |
| 转化 | 主要行为、接收责任、成功/失败旅程和能力约束 | Gate 2/6细化合同；Gate 8实现；Gate 9验证 |
| 技术复用 | 开发方确认既有WP/Next能力和限制，登记复用候选 | Gate 6页面交付；Gate 8实施，不由策划修改开发仓库 |
| 质量 | 确定必要验收范围及环境责任 | 不在准备阶段实际完成全站运行验收 |
| 内链 | 页面关系、主要入口和目标owner | 页面设计落实；集成后专项运行检查 |

WordPress＋Next.js作为当前团队默认方案；通用工作流不硬编码其实现细节。法律、设备、接收和时效标准按站点合同与实际风险确定，不把本项目最重矩阵无条件复制给所有新站。

## 6. 三层复用结构

| 层 | 保存内容 | 变化范围 |
|---|---|---|
| 通用流程 | 角色、输入、方法、交接、独立审查、批准和停止规则 | 方法变化单独迭代，不修改网站事实 |
| 行业适配 | 采购逻辑、产品/服务模型、参数单位、资料类型、关系及常见风险 | 新行业先适配，不强套TiO2目录 |
| 单站基线 | 公司、品牌、产品、市场语言、域名、scope、目录、批准和技术能力 | 一站一套身份；不得跨站继承企业承诺或权限 |

行业示例仅作模型说明：化工可用型号—应用—工艺—资料；设备可用设备—工况—产能—选配—售后；加工可用工艺—材料—公差—图纸—报价。模板必须容纳无标准型号、无商业主词、没有市场子页等情况。

同企业第二站可以复用已获授权且当前有效的企业资料，但另行确认品牌、市场分工和公开用途；不同企业只能复用方法。新站不因复制模板获得旧站批准。

## 7. 责任与审批

总控组织W1–5、识别在途任务、接收准确成果、协调跨包冲突、维护一个网站基线入口，并按授权派发首批页面。总控不能默认亲自重做全部研究、逐句编辑或生产实现。

执行者对专业结果、自检及明确缺口负责；独立审查者按真实不同身份检查关键结果、原始依据及接口。已有效审查按身份/范围/时效继承，不增加同范围重复审查。具体Agent/Skill数量留待职责设计，不因五包自动创建五角色。

用户决定商业方向、企业事实、网站范围和重大取舍。相关决定可合并展示，不能把每包强制变一次审批。内容批准、网站准备可用、页面阶段启动和发布权限分别记录，未知批准不得推导。

## 8. 最小交付与Gate 0→1接口

网站级基线是来源索引，不复制PRD、研究和全站正文。应可从既有文件解析：

- site_id、企业/品牌、语言市场、域名及环境配置的准确来源；
- 定位与范围决定、事实资料及适用用途；
- 买家/研究结论、原始来源、日期与局限；
- 批准架构、页面归属、候选与暂定状态；
- 共享owner、技术复用边界、依赖与首批范围；
- 当前版本组合、审查、批准和开放决定。

Gate 0接收具体页面ID/范围/URL资格、关键词职责、Brief、相关网站来源、缺口、启动依据及停止点，沿现行规则建立准入。不强制重写所有网站研究或填满未来Gate的详细字段；有缺口写责任和阻断范围。

Gate 1接收准入页的买家问题、继承答案、证据及本页缺口，仍按[三路径合同](GATE1_THREE_PATH_EXECUTION_CONTRACT_V1.0.md)选择方法。网站级研究完成不等于本页Gate 1关闭；本页新增发现也不自动重开全站研究。

## 9. 就绪、异常与增量维护

首批可启动的判断：目标/主体/读者/行动明确；页面职责无未决严重冲突；核心命题有有效依据；共享路径与依赖有owner；Gate 0能取到准确输入。就绪结论只覆盖指定批次，不伪称全站所有条件齐备，也不自动授予下一阶段权限。

| 异常 | 处理 | 阻断范围 |
|---|---|---|
| 企业事实缺资料 | 准备具体命题交用户确认 | 受影响表达，不自动全站禁止 |
| 时效或技术反证 | 原owner定向补查、独立核对 | 受影响研究/页面决定 |
| 研究候选与批准架构不同 | 记录差异并按新决定同步 | 不静默新增页面 |
| 共享功能未实现 | 登记实现/验收owner与时间依赖 | 不自动阻断Gate 1–4 |
| 新站复用旧批准 | 分离事实适用性、公开用途与新站权限 | 无有效权限不得推进 |
| 已有站点新增页面 | 只补该页及受影响共享部分 | 不重做W1–5 |

变更从原责任源修订，基线只更新引用和影响。历史原件保留，目录/角色不要复制实时进度。预算和时间记录使用实际活动与等待；不得设固定产物数量作为完成标准。

## 10. 本项目映射验证与局限

| 设计结果 | 本项目可复用入口 | 本次结论 |
|---|---|---|
| W1 | PRD§1–5及原始用户定位决定 | 已有材料，不重问定位 |
| W2 | 产品关系审计、技术资料和用户决定 | 可映射；具体命题仍按当前页批准源 |
| W3 | 关键词研究与证据、实施主表 | 可区分研究/执行权威；不升级历史研究批准 |
| W4 | PRD＋架构增补＋登记册＋共享合同 | 可组合，不需重写为单一PRD |
| W5 | Brief模板、现有总控及Gate合同 | 可定位；通用化需拆出项目固定值 |
| Gate 0 | 404/Thank You准入记录 | 能证明逐页准入与后续授权可分离 |
| Gate 1 | 三路径合同及Context | 已有继承机制，前置基线可供其消费 |

静态反例检查：全新企业无资料→W1/W2先处理核心缺口；同企业第二站→继承有效事实但重核站点分工；无标准型号行业→替换行业模型；仅新增页面→增量准入；无搜索量→保留不确定性；共享表单未实现→登记后续依赖；批准源反证→定向处理；网站基线就绪但无页面授权→只准备不启动。均有上述规则覆盖，但未进行独立Agent试跑或新网站验证。

## 11. 后续实施与验收建议

本设计获确认后，再修订总控网站级准备职责及共同交接合同，建立最小单站配置/来源索引模板，并从实际职责缺口决定是否新增执行角色或方法。现有Gate 0–2及文章工作线只做接口适配，不重新编号或重做已批准页面。

先用本项目作只读映射，再用一个获授权的新站/不同行业案例验证。验收看：无需重读全库即可定位输入；通用模板无TiO2固定事实；能交出可用首批Gate 0输入；无重复专业审查；关键冲突不会漏掉；实际工时和返修可记录。尚未验证前不得称适用于任何工业品网站。

回退：本轮仅新增设计，不改变当前运行规则，无页面状态需要回退。未来实施需另存受影响源快照并同步基线。
