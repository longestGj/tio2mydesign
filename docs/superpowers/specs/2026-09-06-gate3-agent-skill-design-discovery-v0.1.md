## 2. 对项目和本次目标的理解

这是服务国际 B2B 采购判断和请求行动的网站。项目已有定位、产品资料、研究、页面架构、完整文案、线框和大量审查记录。标准化应继承已有成果，把可重复的判断和操作提炼出来；不重新做网站定位，也不把所有页面做成同一个模板。

Gate 3 要验证真实内容的结构、优先级和交互。完整文案与模块顺序由 Gate 2 确认；视觉语言在 Gate 4 细化，完整视觉在 Gate 5 验收。既有页面不因本设计自动重做。开发项目的实现代码与本地设计用源文件分属不同范围。

## 3. Gate 1 的设计方式可以怎样继承

阅读入口：[已批准角色 V0.7](2026-09-06-gate1-execution-agent-design-v0.7.md)、[正式角色源](../../../agents/gate1-execution/agent.md)、[项目 Skill 目录](../../../skills/README.md)、[搜索意图方法](../../../skills/search-intent-evidence-analysis/SKILL.md)、[方法验证 V0.3](2026-09-06-search-intent-evidence-skill-validation-v0.3.md)、[文件交接 V0.4](2026-09-06-search-intent-evidence-skill-validation-v0.4.md)。

| 已有做法 | Gate 3 的继承方式 |
|---|---|
| 先明确负责人要回答的问题，再设计输入、判断、交付和返修 | 先设计结构负责人的责任，不先堆检查清单或建目录 |
| Agent 负责选择方法、综合结果和提交 | 布局方案取舍、整页可用性判断和返修归属由 Agent 负责 |
| Skill 只承担有意义的可复用方法 | 布局转换、核验等方法不维护页面批准状态，不代替负责人决定范围 |
| 项目资料保存事实、版本和决定 | 不把某页模块数、产品数、具体 CTA 或当前共享版本写死进方法 |
| 四项核心交付先定义职责，历史等价文件可映射 | Gate 3 先定义交付职责，不机械照搬四个文件或要求历史改名 |
| 方法先保存并读回，返回路径、摘要和未完成项；Agent 实际读取后综合 | 线框方法除文字报告，还需让 Agent 检查实际源文件、图像和状态证据 |
| 验证区分结构、行为、工具、角色试跑与启用 | 有文件、有截图或结构校验通过，不足以证明线框内容完整或角色已可用 |

Gate 1 第一项方法经历了范围收窄与真实失败驱动修订；不能把最早提出的三个方法名都当成已完成能力。其研究验证的小样本和历史试跑不证明 Gate 3 方法有效，也不自动授权本轮启动子代理。

## 5. 建议的 Agent 定位

建议名称：**Gate 3 响应式结构负责人**，候选角色标识 `agent-gate3`。

目标：把已确认的完整内容和交互语义，转化为可供买家阅读、比较和操作的三端完整线框，并用实际资产和验证证据证明布局成立，为 Gate 4 提供明确的结构基线。

| 责任 | 必须作出的判断 |
|---|---|
| 承接有效输入 | 当前是哪份完整文案、顺序、CTA、条件及共享合同；授权到哪里；有没有影响布局的冲突 |
| 确定信息层级 | 在批准顺序内，首屏突出什么，各模块内部如何分组，主次行动如何辨认 |
| 决定响应式转换 | 什么保持表格、什么转卡片、何时叠放；转换后信息和关系是否完整 |
| 安排操作与状态 | 控件、帮助、错误、反馈和展开内容放在哪里；状态变化是否破坏阅读和操作 |
| 组织方法并检查成果 | 方法输出是否真用批准文案，三端与状态是否齐全，图像是否能支持结论 |
| 处理返修并提交 | 哪些是布局问题，哪些需 Gate 2 内容决定，哪些归共享 owner；需重验哪些资产 |

权限区分：在现有合同内可作布局判断并制作候选；改变已批准文案、模块顺序、字段语义、事实、CTA 目标或页面职责时，先提交具体变更。模块顺序在 Gate 2 确认，Gate 3 锁定其响应式呈现，不产生第二套相互竞争的排序权威。

执行 Agent 自检；总控独立读取原要求和实际成果后审查；用户作最终批准。未来如建立独立审查角色，其核验可复用同一底层方法，但不能只接收执行方的 PASS 数字。本草案不把设计者自身检查称作独立审查，也不创建审查角色运行任务。

## 6. 与正在设计的 Gate 2 对齐

已读[Gate 2 角色草案 V0.1](2026-09-06-gate2-execution-agent-design-v0.1.md)。它仍待用户审阅，不当作已经批准的接口标准，不改写其文件。

现行 Gate 标准已足以确定交接语义：

- 完整真实正文、标题、表格、技术字段及模块顺序，连同 `FULL_COPY_AND_MODULE_ORDER_CONFIRMED` 的真实记录。
- CTA 文案、目标、预填、内链和面包屑。
- 适用控件、条件和状态文字；请求流程提交后的结果含义。
- SEO/GEO/Schema 与可见内容的对应边界，供检查折叠、隐藏和条件展示是否破坏既有合同。
- 当前 Manifest、批准范围、Gate 3 授权及共享组件引用。

Gate 2 决定“说什么、行动是什么意思”；Gate 3 决定“怎样排、怎样在屏幕上操作”。输入缺口应具体定位到模块、字段或状态，继续完成不受影响的部分；只有骨架时不能冒充完整文案已经进入正式 Gate 3。

文件数量、字段模板及命名由后续两边合同协调，允许映射已有文件/章节。连续授权按已批准范围执行，不增加重复确认环节。

## 7. 建议的两项方法边界

下述均为候选，尚未创建或验证；不因本表存在宣称已调用 Skill。

| 方法候选 | 输入 | 方法工作与输出 | 留给 Agent 的判断 |
|---|---|---|---|
| 响应式线框设计 `responsive-wireframe-design` | 确认文案与顺序、行动/状态合同、共享基线、视口、任务输出位置 | 建立内容至布局映射；完成栅格、堆叠、表格转换、控件和状态布局；保存可编辑设计源、三端完整导出与必要状态证据及说明 | 选择适合本页的方案、判定冲突、接受输出并综合为整页交付 |
| 布局与交互核验 `layout-interaction-verification` | 权威输入、候选源与导出图、应测状态和视口 | 对照内容与关系，测量可得几何/行为，检查实际图像；输出可定位问题、证据、未覆盖项及复验结果 | 判断缺陷影响、分派返修、提交独立审查或用户决定 |

表单、长文、技术表格分别作为适用方法分支；不要求每页全部运行。导出、尺寸检查与哈希可以在重复需求证实后形成辅助脚本，不先为截图动作单建第三个 Skill。

方法不维护页面当前批准状态，不替 Agent 增删正文或改变职责。两项方法可以供执行自检与独立审查复用，后者应重新检查原始要求和实际资产。

文件交接建议继承 Gate 1：Agent 指定绝对输出位置与允许覆盖范围 → 方法保存并读回/打开核验 → 返回路径、结论摘要、未完成项 → Agent 实际读取并查看后综合。线框方法需交实际资产，不能仅交文字报告或预计路径。

## 8. 交付和质量建议

按职责组织，暂不锁定新文件数量。既有文件按当前 Manifest 映射，不另建竞争入口。

1. **响应式与交互规格**：模块到三端的映射、信息优先级、布局转换理由、状态与共享组件消费关系。
2. **可复核线框包**：可编辑设计源、1440 Desktop / 768 Tablet / 390 Mobile 完整资产，移动菜单与适用关键状态。780 物理导出明确为 390 logical @2x。
3. **验证与返修证据**：内容及关系对照、实际测量、图像检查、问题定位、未测范围和定向复验。
4. **本页当前 Manifest 与送审信息**：组合版本、源和资产路径、逻辑/物理尺寸、字节数与 SHA-256、开放项及实际授权。

主要检查问题：

- 全部批准内容是否在三端可用，而不只是存在于源文件或 DOM 中？折叠内容有可操作入口和展开证据。
- 表格转卡片后对象、指标、单位、限定条件和比较关系是否仍然明确？
- 长标题、字段、隐私链接、错误提示和操作反馈是否完整且处在读者需要的位置？
- 各视口有无横向溢出、裁切、碰撞、触控不足或异常空白？触控最小要求继承项目 44px 标准。
- 菜单及适用控件的操作、焦点和状态变化能证明到什么程度？静态状态板不能声称运行时键盘行为已测。
- Header/Footer 是否按当前共享合同组装，Logo 与导航是否正确，正文至 Footer 是否闭合？
- 是否混入内部治理文字，或借受限状态、图片、按钮暗示新增事实？

验证采取“内容/结构对照 + 可取得的几何/交互检查 + 实际图像检查”。只做字串扫描、只看缩略图、或仅报告零横向溢出，都不足以说明完整可用。记录工具和字体等实际渲染条件；无法验证的项目说明影响，不伪造 PASS。

视觉输出优先使用本地可复核设计源和导出流程，遵守现行工具边界。具体渲染工具和复用脚本在方法细化时检查可用能力；本轮未建立或测试工具链。

## 9. 共享基线与历史风险

新任务从当前索引消费[视觉标准](../../../brand/visual/TiO2_Malaysia_Visual_Standard_V1.0.md)、[CTA 增补](../../../brand/visual/TIO2_MALAYSIA_PRIMARY_CTA_ACCESSIBILITY_ADDENDUM_V1.0.md)、[Global Chrome](../../architecture/GLOBAL_HEADER_FOOTER_SPEC_V0.5.md)、[生产 Logo Manifest](../../../brand/logo/production/PRODUCTION_SVG_LOGO_MANIFEST_V1.0.md)、[法律共享区](../../architecture/GLOBAL_FOOTER_LEGAL_UTILITY_ADDENDUM_V1.0.md)和[No-Terms 决定](../../architecture/LEGAL_PRIVACY_NO_TERMS_TITAN_PATTERN_DECISION_V1.0.md)。上述路径是本轮阅读快照，不把版本写死为未来方法权威。

主要风险及处理：

- 历史线框带入旧文案、旧 Footer 或旧限制：先核对当前组合来源，历史仅取方法；不恢复已关闭 Hold。
- 为适应屏幕删改内容：先调整布局；确需文案/顺序变化，展示精确变更、原因和影响并提交决定。
- 把共享功能尚未实现当作本阶段失败：按完整网站呈现，登记 Gate 7 依赖、Gate 8 实现和 Gate 9 验证责任；发布条件保持。
- 固定模板压倒页面任务：方法按内容与关系选择模式，不固定卡片数、模块数或页长。
- 验证流于数字：查实际导出和交互证据，明确静态设计与运行行为的证明范围。

布局变化后重新检查三端及受影响状态。保留历史批准源；未受影响资产可继续引用，不能用旧自检数字覆盖新增改动。未获新批准时原批准基线保持权威，新候选明确待审。
