# Gate 3 制作上限与审查边界标准 V1.0

母版版本：0.1.0（提取候选，尚未安装/发布验证）。运行前读取[实例绑定合同](instance-bindings.md)；本站事实、授权与进度不随方法复制。

## 1. 制作上限

交付目的：结构已解决，完整视觉由Gate 4完成。此处“视觉尚待完成”不是要求把已有合适样式去色、降质或故意留下可读性缺陷。

| 对象 | 本关必须完成 | 本关不得追加 |
|---|---|---|
| 内容 | 完整批准全文、模块顺序、对象/字段/来源关系 | 改写文案、补造内容、重新策划；确有缺口交内容owner |
| 响应式 | 1440/768/390真实全文至Footer、列数/重排、长内容及操作区域可用 | 为漂亮反复调字号、间距、页高，增加无结构风险的断点稿 |
| 视觉 | 沿用有效基础样式，满足批准品牌/共享合同及基本可读性、无障碍 | 配色探索、阴影/装饰/卡片风格变体、视觉方案比较 |
| 媒体 | 按批准内容定义位置、空间和响应关系；使用已有批准素材 | 搜图、生成图片、制作视觉资产、反复调裁切；缺少素材时记录Gate 4依赖，仍遵守完整内容和Buyer Clean要求，不把未批准占位当正式内容 |
| 交互 | 适用控件的位置、状态关系、必要实际操作与焦点/键盘可用性 | 动画、过渡、非必要微交互打磨；既有批准行为不得擅自删除 |
| 共享组件 | 消费正式共享源，核验本页组装和适用操作 | 重设计Header/Footer/Menu/Cookie外观、另建分叉 |

用户或既有页面合同明确要求的结构/行为/品牌约束必须继承；遇到与本增补冲突的专属交付要求，记录具体冲突及责任方，不静默免除、不自行扩大制作。

## 2. 每次修改的归属判定

在既有Finding或设计说明中写清“违反哪项要求 → 具体位置/视口/状态 → 对结构、内容关系、可读性、操作或合同的影响 → 消除缺陷的接受条件”。普通制作取舍无需每次另写报告，但新增返修或额外资产必须可追溯到要求或风险。

- 内容丢失、对象关系错配、裁切、碰撞、难以阅读、44px目标不足、不可见焦点、键盘障碍或批准合同偏差：Gate 3实质缺陷，按责任修正并复验。
- 仅“更精致、更协调、更有品牌感”：Gate 4视觉建议，不列Gate 3必修、不生成返修图。
- 同时涉及结构和视觉：只修到缺陷接受条件满足，剩余视觉建议交Gate 4。不得因修改的是CSS而一律判成视觉，也不得把审美偏好包装成可读性缺陷。
- 缺少关键证据：补足验证；没有发现问题不等于已完成验证。

## 3. 证据和停止

保留硬预检、冻结后的正式三端图、必要菜单与本页结构/操作关键状态、真实操作证据、自检及不同于执行者的独立审查。不固定图片数量上限，也不以历史每页图数为配额；每张额外图关联具体要求或风险，不制作风格备选图。

预检通过后才冻结并导出正式资产，不能直接把失败或冻结前诊断图改称正式成果。源/依赖/渲染条件或行为变化须按影响重新验证、建立正确冻结身份并更新受影响证据。未变证据按精确身份和实际覆盖继承，不把旧观察挂到新源。

完整内容三端成立、适用结构与操作验证通过后，完成冻结和自检，立即提交独立审查，不继续视觉打磨。独立审查发现本阶段实质缺陷则定向返修；必修关闭、身份匹配后，总控按本站已核实的常设授权（如有）关闭，是否免逐页批准由本站有效授权决定。Gate 4启动仍按页面原授权。

## 4. 审查与交接同样受约束

Reviewer检查全部规定范围及实际证据，但不要求最终视觉质量、额外风格稿、视觉建议清零或重新设计共享组件。每个必修写具体要求与读者影响。审查者不得编辑冻结候选，也不得把执行自检当成独立结论。

交接沿用[Gate 3→4合同v0.3](2026-09-07-gate3-to-gate4-handoff-contract-v0.3.md)，分清结构约束和当前视觉参数。剩余视觉事项写入既有交接章节，不建立第二份正文或Manifest。Gate 4可调整非锁定视觉参数并复验，不因此自动重开Gate 3。

## 5. 兼容与验证

只适用于Gate 3。布局核验Skill的通用入口和Gate 4/6/9检查能力不变；共享继承资格、本页实测、44px、完整长内容及无障碍不减免。历史页面及原始批准不重做，旧基线保留；已获单关或串行授权不自动变成连续/并行授权。
