# 开发交付规格整理

V0.3，项目方法源；2026-09-07用户已授权本轮定向修订，具体范围及有限验证见[修订记录](../../docs/superpowers/specs/2026-09-07-gate6-three-page-method-revision-v0.2.md)。按具体任务授权使用，不代表所有页面类型已验证或已运行注册。使开发方能够按确定输入实现，使验收方能够用实际结果判断符合性。方法组织材料和派生映射，调用 Agent 对取舍、独立复核、批准及外发负责。

## 输入与输出范围

接收页面任务及唯一当前权威入口、批准内容/结构/视觉/行为、共享与接收合同、最新用户决定、审查及 Finding 处置、具体交付范围，以及绝对 `output_dir`、`report_path` 和版本约定。

缺少必要输入时整理不受影响部分，明确缺什么、影响哪个实现/验收判断。不能以“前阶段通过”填补未知参数，也不因未来系统尚未实现而拒绝准备有效规格。历史包按精确章节映射，保留文件名称及批准身份。

## 方法边界：允许与禁止

| 对象 | 允许做 | 禁止做 |
|---|---|---|
| 内容与映射 | 从批准源派生实现要求，完整核对新增语义 | 猜字段/长度/业务承诺，复制竞争正文，擅定CMS/API实现 |
| 上游原型 | 交完整源与依赖，要求Gate 8核对现有实现后评估复用 | 无触发重新渲染/截全套图；承诺直接合并或一概禁止复用 |
| 依赖与验收 | 稳定ID、实际可观察条件、责任和失败处置 | 为编号整齐重编历史ID；固定条数漏项；将原型违约推给生产放行 |
| 自检与输出 | 一个入口，共用实际覆盖、增量记录及有效引用 | 方法与Agent分别全量自检；重复包、候选Manifest或无必要payload |
| 权限 | 交回就绪候选及缺口 | 自签独立PASS/批准/已交出，真实外发或生产实施 |

按[Gate 6执行与复核合同](../../docs/architecture/GATE6_EXECUTION_REVIEW_CONTRACT_V1.0.md)接收路径及输入。FAST_PATH仅继承有效上游，不减少本次新增开发映射、依赖和验收合同的双向核对。

## 1. 建立一个接手入口

列出当前组合的来源/版本/身份、各文件职责、批准范围、决定覆盖关系和历史入口。只保存必要映射，正文和共享合同继续引用其唯一权威源；新包不成为第二份页面当前 Manifest。

审查结果只引用已实际成立的结论。未修复的本阶段必修问题在包中保持开放；可以形成草稿，不能宣称开发就绪。后续依赖分别记录，不伪装已验证。

### 原型源与适配说明

将完整冻结原型作为开发输入，清单可直接引用现有可访问组合，无需另复制一套源码。按实际制作方式列明：

| 输入 | 接手方需要的信息 |
|---|---|
| 原型入口与样式/脚本 | 入口文件、HTML/CSS/JS的外置或内嵌位置、查看/运行方式及必要条件；静态文件直接打开即可时如实说明 |
| 字体、图片及其他引用依赖 | 精确路径/外部来源、冻结身份和可访问性；按实际文件引用核对清单，区分内嵌、外部与系统资源 |
| 共享组件与视觉证据 | 当前owner/合同、页面消费关系、批准视口/状态及冻结证据 |
| 原型与生产差异 | 模拟行为、示例head、已知差异、生产要求的批准来源、责任与对应接受条件 |

实际源引用的依赖未纳入冻结组合或无法取得时，标明当前交付缺口；不能只凭文件清单声称完整。系统字体无需额外字体文件，内嵌脚本无需拆出独立JS；没有原件或运行条件时区分给定清单、源码观察及实际可访问/运行验证。

明确说明：Gate 8先核对现有项目、已集成页面及共享能力，再评估原型代码的复用、改造和必要新增。允许复用合适代码，不承诺原型可以直接合并或已达到生产要求。共享Header/Footer及表单消费既有owner实现，不因原型含局部副本而另建生产分叉；未核对实际仓库时，只交开发核对要求，不声称既有组件已可用。

## 2. 从语义映射到开发需要的信息

逐模块/组件映射批准内容位置、渲染顺序、字段或内容模型、状态触发、动作、条件/空值、共享 owner 和视觉证据。相同规则引用共用条款，不复制多套。

- 字段类型、必填性、枚举、选择数量、长度限制、可编辑性和错误/结果含义来自批准合同。无依据的具体值交 Agent 决定，不把推荐静默写成既定要求。
- 技术对象、数值、单位、上下限/典型性质和测试方法保持分离；机器输出的值不能因旧实现字段方便而换成方法或描述。
- 必须可索引的文案与数据保持可提取语义要求，不能只交 PNG 让开发自行重录正文。
- 若已有实现接口不能表达正确语义，记录需要的兼容变化、责任方和回归条件，不编写生产实现。
- 确需 JSON/payload 时从批准源派生，并保存逐字段来源与一致性检查。公开数据不含审批/Gate/Finding等仅供治理的字段。已有正式运行状态字段按实际合同继承，不因名称相似擅自删除。

## 3. 把依赖和失败行为写完整

每个未完成依赖关联稳定 ID、批准来源、要求、实施 owner、本页消费责任、当前证据、验证阶段、失败处置及接受条件。多个条目可共用一条验收规则，但每条都有去向。

当前证据保留来源日期、版本/环境及实际证明范围，检查是否有较后owner记录；分别说明未满足时阻断哪些实现、验收或发布判断。继承已有依赖表即可，不另造重复台账；真实上游必修不能改名为后续依赖后放行。

区分本页实现、共享实现、接收服务、事实决定和生产配置。要求别的页面在发布前就绪，不等于授权本页开发它。必需入口、条件动作和服务不可用按各自批准规则处理，不统一发明隐藏、禁用或 Contact fallback。

站点隔离覆盖任务约定的查询、路由、缓存、菜单、SEO、表单和媒体，禁止跨 scope 回退。预填是上下文还是推荐、来源是可信系统生成还是公开可改参数，必须按合同分别映射。

## 4. 写成可观察的接受条件

每项重要要求连成：`来源 → 前置状态/输入 → 预期可见与机器结果 → 实际证据 → 不通过条件 → 责任/阶段`。

接受条件使用稳定ID，供 Gate 8回执和 Gate 9实际验收沿用；按来源拆合适用要求，不强制每页相同数量。已有ID继续继承，要求变更时记录版本及影响，不为编号整齐重编历史。开发回执须把同一ID绑定实际commit/ref与工作区状态、环境、实现/数据来源和测试证据，不能用包内规格检查代替实际结果。

按页面适用性覆盖：

- 内容、值/单位、来源与事实范围，模块及语言顺序；
- 完整主视口、关键状态、裁切/响应式、键盘/焦点与其他已批准 a11y 要求；
- 实际动作、接收/结果、无效/不完整输入、失败和恢复；
- 渲染后的元数据、Canonical、Schema、初始内容与 query/隐私边界；
- 共享消费、依赖就绪及正确/错误/缺失 scope 行为。

示例：如果合同要求正向接收确认后才能显示成功，验收需要实际接收语义证据；超时、模糊响应、本地模拟不能当作成功证明。若合同另要求持久化或去重，必须提供对应证据；不能把它们强加给没有该要求的所有页面。

“看起来一致”“测试通过”“响应为 2xx”不足以替代具体接受条件。静态图证明外观，本地操作证明本地行为，生产等价测试证明其环境内行为；真实生产账户、实际收件或外部结果按各自要求验证，不互相代替。

当前交付缺陷、后续实现缺陷、发布依赖和可选优化分开；规格通过不预签 Gate 9 或发布。不得为验收便利添加新的产品功能、字段、固定截图配额或比批准合同更严的业务门槛。

## 5. 单一完整自检、双向核对并保存

本方法与Agent共用一份来源—映射—验收覆盖记录。已有实际检查且身份/范围未变的结果直接引用，只补缺口；Agent接收不增加同一轮自检。新增/修改实质要求全部覆盖，后续仍由不同身份独立复核。

从批准要求逐项找到包内映射/验收；再从包中每个实质要求查回来源。找不到来源的新要求明确标为提案，不混入批准实现合同。核对全部 Finding 与开放项有去向、源/依赖/图的身份和链接可读性，以及模拟/生产差异是否有对应接受条件。原型源完整交付与生产实现就绪分别判断；包内澄清只能关闭相应交付映射缺口，不能改写上游缺陷或运行依赖的关闭状态。

默认输出一个唯一交付入口，审查摘要、依赖和验收纳入章节或引用已有表；确有需要才拆附件。方法记录只追加实际整理范围、检查、未完成项和需Agent处理的决定，不另外复制包或完整综合报告。机器结果可嵌入既有记录或必要JSON，按实际工具与输入身份记录，不假称统一检查器已存在。

保存后从实际路径读回，核对文件和身份；返回绝对路径、包内容摘要及未完成事项。只作部分合同切片时明确局部范围，不宣称整页就绪。

不修改批准源或页面当前 Manifest，不自行签发独立审查、用户批准或已交出状态，不发送外部消息，也不执行 CMS、实现代码、测试代码、部署或生产操作。
