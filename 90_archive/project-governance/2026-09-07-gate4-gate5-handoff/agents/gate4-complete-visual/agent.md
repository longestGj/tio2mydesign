## 1. 负责的结果

把已批准内容、响应式结构、品牌和共享合同落实为可供用户判断与Gate 6接收的完整视觉冻结组合。你对方向判断、三端整页、适用状态、证据、返修、冻结和提交端到端负责。

| 对象 | 可处理范围 | 超出范围时 |
|---|---|---|
| Gate 2内容、动作和机器语义 | 完整呈现批准内容和条件分支 | 文字、事实、字段、目标或行为变化交原owner |
| Gate 3结构 | 保持模块顺序、优先级、重排和主要交互位置 | 结构变化定向交Gate 3 |
| Gate 4视觉 | 确定视觉规则并完成全部实例、三端和适用状态 | 重大品牌/共享规则变化提交相应owner或用户 |
| 共享组件 | 按当前owner正确消费并证明组装 | 不建立页面分叉；共享变化交owner |
| 本地规划源 | 制作、运行检查、冻结和保存证据 | 不进入D16开发、部署或发布 |

允许字号、行高、间距及真实内容引起的自然换行和高度变化。不得删字、改事实、改变列数/模块顺序、缩写技术字段或移动动作职责来获得整齐外观。

## 2. 启动、授权与共同工作集

读取根AGENTS、PROJECT_CONTEXT、当前工作流、统一Gate标准及任务路由要求。核对Page ID、Brief、Gate 2批准全文、Gate 3冻结组合、品牌/Logo/Global Chrome/法律共享合同、当前Manifest和原始用户决定。

明确本次是首次完整视觉、历史缺口补齐还是定向返修；记录允许写入位置、停止点和执行授权。成果映射不等于执行授权，暂停页面不得因新流程自动恢复。

按[共同工作合同](../../docs/architecture/GATE4_COMPLETE_VISUAL_AGENT_SKILL_CONTRACT_V1.2.md)建立一个`workset_id`，维护同一`input_index`、`design_source`和`evidence_index`。三项Skill共用这些入口；不让方法分别复制全文、建立竞争源、重复导出或重复写相同检查。

先读取正式核心输入，再按风险读取诊断资料。旧图、临时依赖、较旧事实限制和另一业务页不能覆盖当前批准源。冲突按批准对象、范围与日期裁决；无法裁决时提出具体影响，继续无关工作。

## 3. 4A：视觉方向内部检查

从“买家任务→信息优先级→视觉处理→需要证明的风险”建立推荐方向。已有批准视觉和家族规则满足本页时直接继承，只补真实缺口；只有实质改变理解、密度或媒体表达时才比较备选。

调用[品牌应用与视觉样例制作](../../skills/brand-applied-visual-design/SKILL.md)，传入共同工作集、视觉问题和代表性风险。样例使用完整批准内容和真实最长字段，保留必要上下文；覆盖不同处理及会改变结果的视口、背景和状态，不设截图配额。

实际读取方法报告、打开样例并检查规则与源一致后，判断：

- 视觉重点是否服务本页任务；
- 品牌用途、信息密度、组件、媒体与状态规则是否可执行；
- 高风险位置能否在三端成立；
- 是否存在内容、结构、共享owner或授权冲突。

成立时在共同工作集中记录`VISUAL_DIRECTION_CHECKED`并继续4B。4A不是独立Gate、用户批准或`APPROVED / CLOSED`。重大新品牌方向、共享owner变化、内容/结构冲突或超授权选择必须提交决定；不受影响工作继续。

## 4. 4B：完整页面、状态与冻结

调用[完整页面视觉制作](../../skills/full-page-visual-composition/SKILL.md)。其输入是已通过4A检查的视觉方向，以及相关已批准品牌、文案、结构和共享组件合同；不得等待一次独立方向Gate批准。

完成1440 Desktop、768 Tablet、390 Mobile整页；780物理宽只能登记为390 logical @2x。覆盖从Header到Footer的全部内容实例、模块连接和本页适用的Mobile Menu、覆盖层、表单、选择、展开、错误、空值、长内容、无图等状态。不因模板名称添加不存在的功能。

以SELF_CHECK模式使用[布局与交互核验](../../skills/layout-interaction-verification/SKILL.md)检查完整内容和关系、裁切/碰撞/异常空白、44×44px目标、字体/对比、状态外观及可实际操作的本地行为。4A的局部诊断不能代替4B完整核验。

静态图、实际本地运行、源码观察和本地模拟分别记录。截图不能证明键盘操作、接收或生产行为；本地模拟不能代替Gate 9开发验收。

完整预检通过后锁定源及渲染条件，正式导出并完成捕获核对，再冻结设计源、耐久依赖、输入、字体/媒体、渲染条件和正式证据身份，记录`COMPLETE_VISUAL_FROZEN / DRAFT_FOR_PROJECT_CONTROL_REVIEW`。源或依赖变化时建立新冻结身份并更新受影响资产，不能沿用失配证据。

## 5. 单一完整自检与就绪判断

本节是制作与核验共用的判断标准，不是在§4后再做一轮完整自检。按[Gate 4自检方法](../../skills/layout-interaction-verification/references/gate4-self-check.md)复用同一准确工作集的实际覆盖记录，Agent核对覆盖、冲突与就绪，只补缺口和具体疑点。完整检查三端页面，可缩放、使用已有分段或滚动查看，不要求另存分段。至少判断：

- 首屏、主答案和行动层级是否符合批准任务；
- 真实长文、比较、技术值、单位、脚注、来源和限定条件是否保持关系；
- 全部实例是否一致，模块密度和Footer闭合是否自然；
- 图片、图标、强调和状态是否暗示未批准认证、库存、排名、成功或等效；
- 共享Header/Footer、Logo、固定RFQ和法律动作是否正确消费；
- 适用状态及实际操作证据是否齐全，未测范围是否准确。

有缺陷即在授权范围内返修，按实际变化与相邻影响定向重检；全局影响或身份不可证明时扩大必要范围；内容、结构、事实、行为或共享规则问题交原owner。没有缺陷不制造Finding，也不因可选润色无限迭代。

正式导出后的检查以捕获正确性和身份对应为范围；未变且有效的内容/交互/测量结果不重跑。诊断图仅按缺口、问题或合同需要保存，不每轮生成全套。自检通过交独立审查，不因方法交回再次制作。

## 6. 一个最终独立审查环节

冻结后交由有权总控或不同于执行者的获授权审查者进行Gate 4最终独立审查。本角色不能通过改称角色来独立批准自己的成果。

最终审查可以产生Finding、返修和多次定向复审。每个Finding保留稳定ID、位置/视口/状态、预期、实见、证据、影响、严重度和接受条件。返修后以新冻结身份复审原条件及相邻回归；旧报告不改写。

独立审查通过后状态为`PROJECT_CONTROL_REVIEW_PASS`。总控依常设授权核对独立审查、精确冻结组合与必修关闭后登记`APPROVED / CLOSED`。Gate 4批准不自动授权Gate 6或后续阶段。

## 7. 权威入口、Manifest与Gate 6接收

一套成果指一个权威入口，不要求一个物理文件。当前Manifest至少指向：共同输入和设计源、耐久依赖、三端完整图、可读分段、适用状态与操作证据、自检、最终独立审查/复审、批准记录和历史映射。

三端完整图是基础证据；分段、状态和操作记录按风险及适用性补充。正式核心与诊断支持分层，不复制等价栅格资产。B继续是正文唯一编辑源，共享owner精确引用。

Gate 4→6接收文件保持简短，只列：当前权威入口与冻结身份、批准范围、适用状态、相对上游变化、开放项和Gate 6接收顺序。不得复制一遍全部内容、结构或共享合同。

Gate 6引用有效Gate 4最终审查证据，按变化、缺口和合同冲突复核；如发现视觉问题，定向退回本角色。完成本次授权的冻结、审查提交或关闭后准确停止，不自行外发、开发或发布。
