2026-09-07。USER_APPROVED_HANDOFF_CONTRACT / ACTIVE。用户在六项接收对象及同步Gate 5、Gate 6、Controller和路由方案后明确“可以。修改”。

## 1. 交接责任与入口

Gate 5交回实际独立审查，Controller核对并关闭同一视觉组合，具备Gate 6启动授权后派发；Gate 6接收并按差异路径执行。Gate 5的REVIEW_PASS不是关闭或启动授权。沿用[Gate 4→5合同](GATE4_GATE5_VISUAL_HANDOFF_CONTRACT_V1.0.md)对合并Gate 4生命周期的映射，不新增接收关或用户逐页批准。

Controller在现有派发/关闭记录中给出唯一`accepted_visual_input`入口，引用Gate 4原交接组合、Gate 5审查链及总控记录。不另复制图、源码或报告，也不要求Gate 5制作Gate 6开发包。源和依赖由Gate 4提供，Gate 5维护审查事实，Controller维护关闭/启动/当前Manifest，Gate 6维护其新增映射与验收条件。

## 2. 六项接收对象

各字段可引用现有文件/章节，必须绑定准确身份；不强制历史文件改键名。

| 对象 | 必需信息 | 提供责任 |
|---|---|---|
| 批准视觉组合 | Page ID、handoff_entry、bundle_id、source_identity、源/依赖与证据索引身份，批准范围 | Gate 4提供原件；Controller锁定批准组合 |
| 有效审查链 | 首审报告、必要复审、稳定Finding ID/最终处置、各报告所审bundle、有效未变覆盖、最终结论及实际Reviewer | Gate 5 |
| 总控关闭依据 | 关闭记录、准确组合及报告引用、当前Manifest、常设授权依据、关闭人 | Controller |
| 后续启动授权 | Gate 6原始授权范围、实际dispatch_id与执行者、写范围和停止点，有无明确暂停 | Controller |
| 开放依赖 | 原ID、来源、责任方、接受条件、验证阶段、未满足时阻断位置；未测与允许后置的批准依据 | 原责任方维护，Gate 5交回观察，Controller引用，Gate 6继承 |
| 关闭后变化 | 自关闭至接收的源/依赖/记录变化及影响，无变化明确注明并核对身份；不能只继承口头声明 | Controller组织差异说明，Gate 6实际核对 |

## 3. 准入与继承

Gate 6将接收核对放在既有输入卡/报告开头：六项能解析、指向同一适用组合，Gate 5为有效独立审查，本阶段必修关闭且必要覆盖完整，Controller关闭成立、Gate 6授权有效且无明确暂停，才能正式接收。

复审链必须能解释完整覆盖：最终报告若只复验局部，连同首审、有效未变覆盖及各轮变化读取，不把最后一份局部PASS当整页全量实测。可用一份已有最终汇总准确引用整条链，不要求另写历史总报告。

正常后置依赖不阻止视觉批准或Gate 6整理；缺责任/行为/接受条件属于当前交付缺口。原必修仍未解决时不能改名为后置项。缺关闭或Gate 6启动权限时不通过准入；已有明确PREPARE授权可整理无关材料，但不得记录正式接收或启动执行。

满足准入后按[Gate 6执行合同](GATE6_EXECUTION_REVIEW_CONTRACT_V1.1.md)选择FAST_PATH或ESCALATED_PATH。接收只核对身份、范围、有效结论、依赖和变化，不重审三端视觉，不默认运行全部交互。实际矛盾证据仍须处理，hash一致不能压过反证。

## 4. 开放项与变化处理

开放项继承原ID及来源，不因进入Gate 6重新编号或复制第二张事实台账。确需Gate 9接受条件ID时新增对应关系，保留原依赖ID。状态只按实际责任方证据更新；未测不自动变已测，视觉通过不表示CMS/接收端/生产配置已实现。

关闭后仅导航或方法文件变化，不自动等于视觉组合改变；先核对实际来源及影响。源/关键依赖或实质证据组合变化时，旧PASS与关闭不能自动覆盖新组合：定向提交Gate 4/Gate 5及Controller处理，保留旧批准。纯记录纠错按可信原件与变化影响核实，必要时修订报告/关闭引用，不重新渲染未变图片。继续不受影响且获授权的工作，受影响范围未解决前不得声明完整接收/就绪。

## 5. 异常路由

| 异常 | 返回/记录 | 处理责任 |
|---|---|---|
| 缺源、依赖、证据或原交接字段 | INPUT_INCOMPLETE | Gate 4补具体原件/字段 |
| 缺首审/复审链、覆盖或报告绑定不明 | INPUT_INCOMPLETE；已证实绑定错误则CHANGES_REQUIRED | Gate 5补齐或更正自身报告 |
| 缺关闭/启动授权、Manifest或派发身份冲突 | INPUT_INCOMPLETE，暂停受影响准入 | Controller核对并补正确记录，不能推定授权 |
| 源/证据身份失配、实际视觉反证 | CHANGES_REQUIRED或REVIEW_CHALLENGE | Controller协调Gate 4修复、Gate 5定向复验，再更新关闭引用 |
| 后置项描述不完整 | 交付缺口，保持OPEN | Gate 6整理映射，未知业务条件交原owner，不猜定 |
| 新增开发映射/验收条件有误 | Gate 6 Finding | Gate 6修订，由不同于其作者的身份独立复核 |
| 必要环境或工具执行失败 | FAILED及恢复条件 | 交实际环境责任方；不伪装成已接收 |

Gate 6不得回写Gate 5报告或擅改Gate 4源。Controller不得以协调为由再做同范围全量审查；已有Reviewer时疑点定向交其核查。接收结论与异常写入既有记录，不另建接收批准或独立审查层。

## 6. 结束与历史

接收成立后Gate 6对新增开发合同负责；该包仍须独立复核和总控关闭，Gate 5视觉PASS不能代替新包审查。Gate 6关闭不表示已外发或启动Gate 8。

历史合并Gate 4有效最终审查与关闭可按等价关系接收，保持原ID/作者/日期，不补造Gate 5报告或重新审图。具体页面授权及暂停保持。此合同不实现自动validator，不以文档规则声称已完成实际接收。
