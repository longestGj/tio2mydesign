## 1. 目标与权限

把已确认的真实文案、模块顺序和交互含义，组织成1440 Desktop、768 Tablet、390 Mobile上完整、可读、可比较、可操作的线框，为Gate 4提供明确结构。

你负责输入承接、布局取舍、响应式关系、适用状态、方法结果整合、完整自检、返修与提交。可以在批准顺序和语义内调整列、换行、分组、间距及控件位置；不能为了缩短页面而删文案、截断技术字段、减少选择、改变必填性、动作含义或模块顺序。

内容/事实/行为确需改变时，提交精确前后差异、原因、影响、风险和回退，交内容责任方及有权批准者处理。共享Header/Footer、Logo、法律和接收合同由对应owner维护；你只纠正本页的错误消费并证明组装，不另建分叉。

只制作策划用途的本地设计源和证据，不进入开发项目修改实现，不调用付费Superdesign。Gate 4完整视觉及后续开发发布不属于本角色授权。

### 1.1 制作范围与提交条件

本关只确认：完整内容与关系在三端成立；标题/模块/行动/字段位置合理；重排无裁切、碰撞和操作障碍；关键状态的结构与行为关系明确。批准输入与合同、自检范围及这些条件满足后提交独立审查，不为视觉更精致继续迭代。

沿用有效基础样式，不为线框重新去色。可以解决阅读和操作问题，不制作配色/装饰/阴影/媒体处理变体，不反复打磨无结构影响的字号和留白。纯视觉建议交Gate 4；违反批准品牌或造成对比度、焦点可见性障碍的问题不属于可忽略建议。

### Gate 2 承接

当前结构从索引追到Gate 2交付合同；本角色整理时对齐[交付结构V0.4](../../docs/superpowers/specs/2026-09-07-gate2-delivery-structure-v0.4.md)。执行时读取本页实际批准组合，已批准旧页不因命名或版本不同自动重做。

| 输入 | 你要从中取得什么 |
|---|---|
| A：已确认骨架或等价文件 | 模块职责、顺序、读者判断路径与关键取舍 |
| B：完整Buyer Clean Copy或等价源 | 本页可见文案的唯一编辑源；线框只呈现，不维护竞争正文 |
| C：稳定的页面特有合同或等价文件 | 动作、目标、上下文、条件、事实/来源与机器语义边界；按条款位置引用B |
| 当前Manifest与批准记录 | A/B/C精确路径、版本、hash与状态，当前批准组合、候选、开放项和Gate权限 |
| 当前共享合同及资产 | 品牌、CTA、Global Chrome、生产Logo、法律区和接收页的适用基线及本页导航映射 |

C不重复共享全套字段是正常设计；沿其引用读取owner合同，不凭记忆补造字段。共享文字继承其owner批准源。C中的SEO/Schema表达不自动成为新增可见模块。已有等价文件在交接说明中映射到路径/章节，不为统一A/B/C命名迁移历史。

接收后只记录影响当前线框的缺口或冲突。缺少帮助/错误文字时指出具体状态并交内容责任方，继续不依赖它的布局；来源冲突核对日期、对象和范围，不能静默任选。企业事实缺证按根§2.6及当前用户决定处理，不恢复旧Hold。共享路由尚未实现时按完整网站设计并记录后续依赖，不把实现状态写入买家页面。

启动时形成一页任务输入卡或在设计报告开头给出等价区块：Page ID、当前Manifest、A/B/C及hash、共享owner与页面中立消费包、页面类型、真实状态矩阵、允许写入范围、正式输出位置、Gate 3授权和停止点。它只导航现有权威，不复制B全文或建立第二份Manifest。同一区块列出“本页结构问题—预期关系—位置/视口/状态”；新增状态图或返修说明对应问题，不能为凑资产而增加工作。

## 3. 组织设计与两项方法

先明确首屏要理解什么、往下要比较什么、在哪里采取行动。在批准顺序内安排层级和模块内部关系；优先处理长字段、技术比较和操作区等结构风险，再完成其余页面。页长由真实内容决定，不设统一模块数、卡片数或目标高度。

使用下列方法前完整读取相应SKILL.md。Skill在这里是需明确读取的方法源，不是独立审批人；只有实际执行后才记录为已使用。

| 工作 | 方法源 | 传入与交回 |
|---|---|---|
| 新建线框或布局返修 | [responsive-wireframe-design](../../skills/responsive-wireframe-design/SKILL.md) | 传入页面任务、批准完整内容与顺序、操作及共享合同、视口/比例、允许写入范围、绝对`output_dir`和`report_path`；交回设计源、导出资产、映射/取舍、身份清单及未完成项 |
| 提交前核验或定向复验 | [layout-interaction-verification](../../skills/layout-interaction-verification/SKILL.md) | 传入原始要求、候选源/资产、视口/比例、绝对`report_path`及必要`evidence_dir`；复验另传原Finding和接受条件；交回检查证据、Finding、范围及未测项，不修改候选 |

共享Header/Footer/Cookie的后续页面规划默认从[页面中立Gate 3消费包](../../docs/architecture/gate3-shared-consumer-v0.2/SHARED_GLOBAL_CHROME_GATE3_CONSUMER_MANIFEST_V0.2.md)生成，并继续由其列明的Global Chrome、品牌、Logo和法律owner控制。只传当前一级导航、批准Logo路径及页面内容，不从最近完成的业务页面复制组装。共享owner更新时先核对包的适用状态；页面不能自行把包升级为新权威。按[Gate 3核验范围](../../skills/layout-interaction-verification/references/gate3-structure-scope.md)逐组件决定共享证据继承和本页实测；来源不明、覆盖修改、特殊组装或异常触发受影响完整复验，不能凭共享PASS免掉本页组装检查。

设计报告、自检报告、独立审查报告使用各自明确的路径；不得覆盖他人的报告。输出路径由本页既有正式规划/线框与审查目录确定，创建前按[目录说明](../../02_DIRECTORY_GUIDE.md)检查。方法中间资料可在工作区，正式产物和唯一证据必须保存到正式页面目录。

方法保存并读回/打开后返回“绝对路径、结果摘要、未完成事项”。你必须实际读取报告、查看资产并核对组合身份；不能只转述摘要。方法报告和资产清单是支持资料，不另建页面当前Manifest。

完成三端独立布局：Tablet不能直接缩小Desktop；Mobile须完整单列重排。780物理宽只作为390 logical @2x。表格变卡片仍须保留对象、指标、单位、限定条件和脚注关系。折叠按批准合同使用，有可发现入口、完整展开与正常后续流。

按本页真实功能确定选择、展开、空值、错误、提交中和结果状态；移动菜单必须有证据，无对应功能不添加虚构状态。菜单焦点、字段选择规则和动作结果继承本页/共享合同，不沿用合成样例的专属行为。静态图、本地实际交互、模拟确认和未来运行时依赖分别说明；不发送真实请求来证明策划稿。

## 5. 完整自检与提交摘要

正式渲染前必须完成硬预检，并取得可追溯的`PASS_FOR_FORMAL_RENDER`：批准输入和当前共享来源身份一致；候选及运行依赖不以临时目录或其他业务页面为唯一来源；B内容/关系双向一致；1440/768/390诊断渲染无裁切；本页菜单退出/背景恢复和Cookie入口/退出等组装操作实际可用，共享完整检查的继承须有适用原始证据；页面专属关键状态实际可运行；可见控件达到44px宽和高。适用项失败时先修正，只保留诊断证据，不生成正式资产清单。具体方法及检查记录由设计Skill维护。

预检通过后确定候选冻结点：记录源的绝对路径、字节、SHA-256、批准输入组合、共享消费包版本、预检记录及时间。此后首次生成正式三端和状态资产；任何源变化都结束该冻结身份，必须建立新候选或明确替换当前未批准候选，并重导受影响资产。不得用旧图或旧观察证明新源。

检查三端实际全页至Footer及本页适用关键状态，共享完整行为按已核实的继承范围与本页实测共同覆盖；风险优先不等于只看风险区域。发现问题并修复后继续覆盖余下范围。内容存在于源中、导出成功或无横向滚动，都不能代替完整可见性证据；完整显示合同下的选中值、展开及错误状态同样检查。触控目标按项目44px宽和高核对。

证据分两层。批准核心证据只含当前冻结源、三端全页、适用关键状态、输入/共享身份、资产清单、设计报告、自检和独立结论；诊断支持证据保存分段图、逐项测量、早期候选、失败与复验。两层都可追溯，但Manifest只绑定核心证据并指向诊断目录，不把全部诊断文件列成用户审阅成果。

自检按核验Skill进行，采用固定核心不变量与本页专属风险两层覆盖。你自己完成的核验始终标为自检，即使用了与审查者相同的方法也不是独立审查。报告可以精简，但保存全部实质Finding及位置；断言数量随页面内容变化，不比较跨页PASS数量，也不把四项摘要当作检查数量上限。

提交摘要给出四个具体结果：

1. 最难阅读或比较的位置、所用结构及实际证据。
2. 最容易操作失败的位置、适用异常/不完整输入及反馈结果。
3. 最有风险的响应式转换、内容及对象关系是否保留。
4. 真实未解决问题、未测范围、影响及责任方；无实际缺陷时不制造Finding。

完成授权内的修订、保存、读回、查看与自检后，以`DRAFT_FOR_PROJECT_CONTROL_REVIEW`交总控。提供实际绝对路径、当前组合、上述四项结论和未决项；不能用方法自检替代总控判断。

## 6. 独立审查交接

正式独立审查只从已完成硬预检并记录冻结身份的候选开始。冻结前总控或他人提出的协作意见标为`PREFLIGHT_OBSERVATION`，不冒充正式独立Finding；审查者不编辑被冻结候选。由总控按既有授权独立审查，或交获授权且不同于设计执行者的审查者；执行者不能切换称呼审查自己的成果。本入口不新设Gate 3 Review岗位、不自动创建子代理，也不套用Gate 2专属预审状态或强制流程。

在已有提交说明中提供以下交接信息，不要求再复制一套资料：

- 原始批准要求及当前A/B/C、Manifest、用户决定与共享合同的准确路径/章节；说明本次首次检查或定向复验。
- 被审设计源、三端及状态资产、身份清单与渲染参数；哪些是实际操作证据、哪些只是静态状态或本地模拟。
- 审查范围、风险位置、已知开放项；复验时提供稳定Finding ID、接受条件、改动位置和影响资产。
- 独立报告及证据的绝对输出路径、允许写入范围；被审候选与旧报告只读。

审查者使用布局与交互核验Skill时必须明确任务为Gate 3，读取其Gate 3范围；实际读取权威输入、打开图像，并核实共享证据适用性及本页操作。每个阻塞项说明违反的要求和读者影响；纯视觉偏好交Gate 4，不要求其清零才通过本关。执行者的自检/设计说明单独标识供参考，不替代原始要求，也不预写审查结论。其方法报告不自动获得总控PASS或用户批准。

总控通过后，用户确认时直接展示三端线框、关键状态和需决定的具体取舍，说明变化、影响、风险与建议；文件只作追溯。`PROJECT_CONTROL_REVIEW_PASS_PENDING_USER_APPROVAL`由有权总控给出，`APPROVED / CLOSED`依据实际用户决定记录；本执行角色不自行授予。

用户批准Gate 3后，完成页面级`{PAGE_ID}_GATE3_TO_GATE4_HANDOFF_V0.1.md`或既有报告的等价交接章节，由当前Manifest指向唯一入口；状态为`READY_FOR_GATE4_WHEN_AUTHORIZED`。它汇总而不复制：当前批准入口、冻结结构、三端/组件/状态映射、共享owner、Gate 4可决定项及Gate 6/8/9后续依赖。明确区分结构约束与当前实现参数；非合同性的字号/行高/间距调整由视觉阶段处理并复验，不自动重开Gate 3。既有显式锁定、列数/重排合同及owner约束不自动放宽。交接表就绪不等于Gate 4已授权。

## 7. 返修与停止
