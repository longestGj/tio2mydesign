## 3. 标准交接表内容

### A. 身份与权限

- Page ID、页面名称、语言、URL与 `site_scope`。
- 当前Gate 3批准Manifest、用户批准记录、冻结线框源及hash。
- Gate 4状态：未授权、已授权或定向返修；明确停止点。

### B. 结构锁定清单

- 批准模块顺序、每个模块的读者任务和信息优先级。
- Header、Footer、CTA、目录、表单、表格、FAQ、来源或媒体等实际组件的位置。
- Desktop、Tablet、Mobile的列数、重排、折叠和关联关系。
- 主要交互的位置与结果语义；哪些行为由共享或接收页owner控制。

这里记录位置和关系，引用B/C原文，不复制整页正文。

### C. 组件、视口与状态矩阵

| 区域/组件 | 1440结构 | 768结构 | 390结构 | 必要状态 | 正式证据 | owner/继承 |
|---|---|---|---|---|---|---|
| 页面实际区域 | 锁定关系 | 锁定关系 | 锁定关系 | 仅列实际适用状态 | 对应全页或状态图 | 页面、Global Chrome、法律、接收页等 |

矩阵用于Gate 4选择代表样例。它不规定视觉颜色、阴影或表面处理，也不要求每个模块单独出图。

### D. Gate 4可决定与不可决定

Gate 4可在批准品牌系统内决定：

- 颜色用途、字体层级、行高、间距尺度和表面层级；
- 卡片、表格、按钮、表单、引用、图标及适用状态的视觉表达；
- 代表性媒体方向、裁切、替代文本方向和无图片回退；
- 不改变结构关系的自然换行与内容高度；
- 哪些真实区域最适合证明视觉方向。

Gate 4不可自行改变：

- 正文、事实、模块顺序、列数与响应式重排关系；
- 控件所属区域、CTA目标、字段类型、必填性、选择数量或结果语义；
- 页面职责、URL、关键词、Schema事实边界及共享owner合同；
- 用视觉暗示未批准的性能、推荐、认证、来源或运行状态。

若视觉制作确需改变不可决定项，按问题归属定向交回Gate 3或内容/行为owner。

### E. 视觉风险与代表样例建议

只写会影响Gate 4取样的真实风险，例如最长技术字段、最密集比较、复杂选择、来源归属、深浅背景切换或无图片分支。每项说明：风险位置、需证明的视觉问题、建议视口/状态。它是任务输入，不预先指定视觉答案。

### F. 共享与后续边界

- 当前品牌、Logo、Global Chrome、法律/CMP及适用同类页面的owner入口。
- 本页导航当前项、固定CTA和共享组件连接规则。
- Gate 3未验证的生产路由、接收、真实设备、读屏等后续事项。
- Gate 5仍需完成的全页视觉验证；不得把Gate 4代表样例当成完整页面。

## 4. 支持证据不作为默认成果包

下列资料必须保留并可追溯，但Gate 4默认不需要逐份加载：

- 执行自检全文、总控独立审查全文和原始测量JSON；
- 分段查看图、焦点过程图、逐链接检查和身份复算明细；
- 已修复attempt、旧候选、失败截图和返修过程文件；
- 与最终冻结组合重复的独立重渲染图片。

当前Manifest和交接表必须给出这些资料的位置及仍有效Finding。Gate 4遇到身份争议、结构疑问或相关风险时再打开。历史资料不删除，也不进入买家页面或被包装成视觉要求。

## 5. 交接完成标准

Gate 4执行Agent只读核心成果后，应能明确回答：

1. 哪个Gate 3源和哪些三端/状态图已经批准？
2. 本页模块顺序、信息优先级和响应式关系是什么？
3. 哪些组件及状态必须由视觉方向覆盖，哪些规则可复用？
4. 哪些文字、事实、行为和共享组件不能改变？
5. 哪些视觉决定尚未作出，Gate 4应拿什么真实区域来证明？
6. 哪些是Gate 5整页工作或后续实现/验收事项？

任何一项只能通过翻查历史尝试或猜测得到，交接尚未完成。缺少关键输入时Gate 4指出具体缺口并继续不依赖部分，不自行补造结构或视觉事实。

## 6. 版本与变更

- Gate 3候选送用户前可先准备交接表草稿；只有用户批准对应冻结组合后，才标记 `READY_FOR_GATE4_WHEN_AUTHORIZED`。
- Gate 3批准后发生结构变化，旧交接表保留历史，按受影响范围升版并重新获得所需批准；未获新批准前旧批准基线继续有效。
- Gate 4只产生视觉方向规则和代表样例，不反向覆盖Gate 3源。
- 当前Manifest仍是页面唯一阶段入口；交接表是工作导航，不建立第二个状态权威。
