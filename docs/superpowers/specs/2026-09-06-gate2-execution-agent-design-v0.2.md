## 2. 岗位定位

### 2.1 核心目标

把 Gate 1 已确认的读者任务、研究结论和事实边界，转化为连贯、完整、可供买家使用的页面内容，并让 CTA、链接、SEO、GEO、Schema 与正文保持一致，为 Gate 3 提供无需重新猜测文案的内容基线。

对读者而言，页面应说明：这与我的需求有什么关系、我可以据此判断什么、依据和适用条件是什么、下一步可以做什么。涉及请求或提交时，还要说明提交后会发生什么。

Agent 对整页的内容取舍、顺序、表达质量和交付一致性负责。它需要把多个研究答案组织成一条阅读路径，而不是按研究报告章节逐段改写。不同页面类型依各自读者任务和已批准 Playbook 组织内容，不预设统一模块数或文章长度。

### 2.2 六项职责

| 责任 | 必须作出的判断 |
|---|---|
| 承接已确认方向 | 哪些结论与用户要求必须继承，哪些局部问题仍需补查，当前允许推进到哪里 |
| 确定内容重点 | 首屏应让读者理解什么，哪些问题需要完整回答，哪些只作简要说明并引导到其他页 |
| 组织阅读顺序 | 每个模块解决什么判断，为什么放在这里，与前后模块如何衔接 |
| 完成真实文案 | 标题、正文、表格、问答、按钮及适用状态是否具体、清楚、有依据且没有机械重复 |
| 对齐行动与机器表达 | CTA、目标、预填信息、内链、SEO、GEO、Schema 是否与可见内容及批准范围一致 |
| 整合、自检与返修 | 方法输出是否解决问题，整页能否交给下一阶段，修改是否同步覆盖受影响位置 |

### 2.3 判断权限与相邻职责

- Gate 1 提供读者、问题优先级、研究答案、依据、职责边界及行动建议；Gate 2 对据此提出的实际 H1、模块顺序、完整文案与内容关系负责。上游建议若已获具体批准，按其范围继承。
- 在页面合同内可以提出表达、内容组织和行动路径方案；改变已批准方向、身份、URL、主关键词、事实或跨页职责时，按项目变更流程处理。
- 新出现的局部内容问题可定向补查；发现核心方向或关键研究结论不足时，交回具体问题、影响与建议，继续完成不受影响的部分。不能无故重开整套 Gate 1，也不能为写完文案自行补造事实。
- Gate 3 负责响应式线框。Gate 2 定义内容和交互语义，提供真实文字、顺序与条件；不提前决定像素布局，不以短占位掩盖长内容。
- 执行 Agent 自检并提交；独立审查与用户批准由相应责任方完成。本任务设计自己提出的角色时，也不将自身检查称为独立审查。

## 3. 输入承接建议

执行时先按根规则读取适用资料，并从当前索引和页面 Manifest 定位权威输入，不在通用角色里固定某页事实或版本。

| 输入 | Gate 2 需要得到什么 |
|---|---|
| 页面身份、完整 Brief、关键词归属、Playbook | 为谁写、负责什么、必须包含与排除什么、语言与页面类型要求 |
| Gate 1 综合研究与意图确认 | 重要问题、结论与理由、内容重点、下一步行动及尚未解决的问题 |
| 命题证据登记与用户决定 | 每个拟用事实的准确含义、来源、日期、适用范围和已批准表达 |
| 当前 Manifest 与阶段授权 | 实际有效组合、历史关系、已确认骨架或文案，以及本次停止点 |
| 相关共享合同与相邻页面 | 可用的内链、CTA 与预填约定、共享导航及法律内容责任；只读取本页涉及部分 |

接收后区分“直接继承”“局部补查”“存在冲突或需决定”。Gate 1 报告已保存不等于内容充分；应实际阅读其结论及所引用的关键依据。历史等价成果可以按文件与章节映射消费，不要求重做为新格式。

正常进入 Gate 2 的依据是有效页面合同、Gate 1 确认/批准记录及 Gate 2 授权。已存在的连续授权按原范围执行，不再次索取相同许可；不把研究内容认可自动解释为下一阶段授权。

## 4. 两次交付的工作建议

两次确认来自现行 Gate 标准，不新增 Gate 编号；以下细化其内容负责人职责。

### 4.1 先提交内容骨架

形成可在对话中直接判断的骨架：

- 拟用 H1 与 Hero 核心信息。
- 完整模块顺序、每个模块的一句话目的及其要回答的问题。
- 主次 CTA 的具体文案、目标 URL 和所需上下文；无次 CTA 时明确无。
- SEO Title、Meta Description 与 Canonical 方向。
- GEO / Schema 拟表达的实体与关系。
- 会影响取舍的具体事实待决项、条件模块与必要内部限制。

Agent 解释先后顺序和取舍理由。模块应帮助读者形成判断或完成行动；某项批准内容必须保留时，安排合适位置而不擅自删除。不能先套固定模块再倒推问题，也不能因尚缺完整正文而禁止骨架送审。

骨架确认后才完成整页正文。已确认骨架仍有效时直接复用；如需改变已批准核心信息、模块顺序或职责，说明具体影响并按范围重新确认。

### 4.2 完成全文与内容合同

在已确认骨架上完成：

- H1、Hero、所有模块标题与真实正文，以及适用的表格、简明答案、FAQ、来源和日期。
- CTA 文案与目标、预填字段、上下游内链、面包屑及必要帮助说明。
- 表单页所需标签、必填/选填说明、验证提示、提交中、成功与失败文案；其他页面按实际交互需要处理。
- 最终 SEO Title、Meta Description、Canonical、索引和语言方向；沿用批准策略，新增变更另行提出。
- GEO 实体、关系和答案表达；Schema 类型、字段来源、可见内容对应及条件规则。这里交付内容规格，不实现 Schema 代码。
- 正常、空值、事实受限、路由未就绪等适用条件下的内容处理。内部依赖与限制单独记录；只把帮助读者理解与操作的说明放入可见文案。

对企业事实继承用户已有批准，缺证按根规则提交具体事实确认。核对命题的对象、限定条件和关系，不能把一个型号的说明扩成全部产品能力，或在标题、按钮、Meta、Schema 中暗中扩大正文含义。

按完整网站的最终体验设计。共享页面或路由未完成应登记后续交付依赖，不自动删除合理 CTA，也不承诺尚未批准的响应时限、库存、文件或服务。

### 4.3 成果组织建议

| 交付职责 | 内容 |
|---|---|
| 内容骨架 | 页面核心信息、模块目的与顺序、行动和 SEO/GEO 方向，以及对应确认记录 |
| 完整买家文案 | 所有实际可见内容与适用状态文字，使 Gate 3 能直接使用真实内容 |
| 内容关系与一致性合同 | CTA/URL/预填、内链、SEO/GEO/Schema、事实对应和条件规则 |
| 当前基线导航 | 在本页唯一 Manifest 中映射有效成果、批准范围、历史版本、开放项与下一阶段权限 |

这是职责划分，尚不锁定文件数量、命名或字段模板。内容关系合同可以是现有内容架构文件中的明确章节；不为凑文件复制正文和证据。原有 Brief、命题登记及共享事实源按需要更新或引用，不能重建竞争权威。正式内容进入页面规划目录，实际位置依页面当前合同和目录规则确定。

## 5. 质量评估建议：依据实际内容作出可复核判断

本节为本轮提案，尚未批准。Agent保留结果责任、检查维度及返修判断；详细分析步骤、测试样例或评审方法以后按复用需要放入Skill，不在角色中扩写成审稿教程。

### 5.1 评估依据与底线

先从已批准Brief、Gate 1结论、用户要求和本页职责确定必须帮助读者完成的判断，再阅读实际交付。不能让执行者通过降低自己的目标，使作品在自定标准下合格；审查者也不能临时增设无依据的页面任务或个人风格偏好。

在现有合同内核对事实与授权、页面职责、关键内容及行动语义。错误事实、扩大批准范围、遗漏核心任务、按钮或成功状态误导读者等问题，不能靠其他部分写得好抵消。文件齐全、篇幅和形式只能说明交付结构，不能证明内容质量。

没有资料不等于命题错误或禁止使用。已有用户批准按范围继承；未决事实仍走具体命题确认。未来路由未实现按依赖管理，不等同于本轮内容设计不合格。

### 5.2 六个质量维度

| 维度 | 可观察的合格表现 | 如何支持判断 | 典型不足 |
|---|---|---|---|
| 任务与答案 | 首屏清楚表达本页用途；本页必须回答的问题有足以支持判断的答案；归其他页的问题有合适承接 | 将批准的重要问题对应到实际标题/正文，检查答案而非只检查术语出现 | 有“选型”标题，正文却只说“选择合适产品很重要” |
| 内容组织 | 重要答案易于找到；必要解释先于依赖它的结论；模块衔接、主次与页面任务相符 | 说明实际阅读顺序怎样帮助判断；指出重复、缺口或被埋没的关键信息 | 多个模块反复讲同一优势，关键条件却很晚才出现 |
| 表达与具体性 | 语言自然清楚，术语适合目标读者；有足够具体的对象、条件和解释；每段有信息贡献 | 引用具体段落，解释读者由此知道了什么；技术术语和中性共享表达不因“不独特”而扣分 | 抽象宣传占据主文，换任意产品名仍说得通；长句掩盖主旨 |
| 事实与说服依据 | 重要主张有适用来源或用户批准，利益与理由相连，限定条件准确 | 对照原始依据、适用对象及批准范围；优先检查影响采购判断的主张，所有实质事实均须可追溯 | 用一款型号的指标证明所有型号性能，或只说“质量卓越”不给理由 |
| 行动与流程 | 读者知道可做什么、去哪做、需要提供什么；涉及提交时清楚说明结果及失败处理 | 从实际入口文案走查到目标与预填/状态合同；区分内容走查和未来运行验证 | 写“下载”却只允许申请，或把提交成功等同样品已获批 |
| 一致性与可交接性 | 正文、模块顺序、内链、SEO/GEO/Schema及条件状态同义一致；Gate 3可使用真实内容 | 对照字段与可见内容、当前版本、关联目标和缺失项 | 正文是有条件说明而Meta作绝对承诺；关键状态只写“待补” |

不同页面共用这些维度，但依据各自任务判断。Hub的有效分类与选择路径、型号页的技术评估信息、转化页的清晰流程各有不同重点。适用性或合理例外必须说明，不为统一评分增加无用FAQ、表格、表单或模块。

### 5.3 结论如何记录和处理

每项结论采用“要求/读者任务 → 实际位置或原文 → 判断及理由 → 影响与处理”的最小记录。它可以放在现有自检或审查章节，不强制增加文件。判断需要足以让另一名审查者理解，不以PASS、分数或关键词命中替代依据。

各维度可记录为：

- **满足当前阶段要求**：实际内容足够支持对应任务；仍可有不影响完成的风格建议。
- **需定向修订**：明确指出不足、受影响内容及修好后的预期表现。修订是否阻止本次通过，依实际严重性判断。
- **需具体决定**：说明事实或方向冲突、已有依据、影响范围与建议；不伪装成写作问题，也不静默跳过。

问题严重性继续使用项目既有“阻塞、重要、建议”，不另造数值总分或统一及格线。阻塞项及尚影响本阶段核心判断的重要项解决后，才可建议通过相应范围；非关键开放项按现有规则明确负责人和后续处理。发现问题可以提交草案或决定请求，不要求先获批准才能送审。

“我更喜欢另一种说法”通常是建议；若认为必须改，应说明它怎样造成误解、遗漏、事实偏差或其他实际影响。已经满足要求时停止无实质收益的改写，不把质量检查变成无限润色。

### 5.4 骨架与全文分开评估

**骨架阶段**判断核心信息、重要问题覆盖、模块目的与顺序、行动方向及拟表达事实是否合理。此时不要求每段正文已经写完；骨架可通过不代表未来完整文案自动通过。

**全文阶段**检查全部实际买家文字和适用状态，确认答案充分、语言质量、事实支持、行动与元数据一致。不得用骨架确认代替全文核对。阶段关闭须有真实用户确认与规定审查记录；进入Gate 3前核对 `FULL_COPY_AND_MODULE_ORDER_CONFIRMED` 及下一阶段授权。

### 5.5 谁来评估，以及评估能证明什么

执行Agent按上述维度自检并修订。独立审查者从原始任务、当前权威输入及实际成果重新判断，不能只接受执行方的总结或自评数字，也不能由作者换一个角色名授予独立PASS。两方可使用相同方法，仍各自承担判断责任。

可以先仅凭买家可见内容尝试完成Brief规定的读者任务，再对照内部证据与合同检查正确性；不能用内部研究替页面回答本应在页面中回答的问题。AI或审查者的读者任务走查属于检查方法，不是假装真实客户测试。

Gate 2内容审查能判断任务覆盖、表达、事实及交付一致性，不能单凭文案证明真实客户理解率、转化率或SEO/GEO效果。真实使用表现以后通过获得授权的用户研究或运行数据评估，不作为本阶段必须先取得的数据。

### 5.6 后续如何验证评估方法

在后续方法设计与获授权试跑中，用原始任务及材料让执行者产出真实作品，再由独立审查依据相同任务判断，保留具体遗漏、误导、冗余及返修结果。不能只测试报告有没有规定标题或PASS字段。

可用带有已知缺陷的材料校准能否发现问题，同时保留满足要求的作品检验会不会无端要求返修；校准案例不替代从原始材料到完整交付的试跑。比较有无Skill时尽量保持任务、输入和条件相同，如实记录差异，不把五次或某个样本数写成所有方法的固定规则。

本轮仅提出评估设计，未进行独立审查、行为测试或页面试跑。详细案例、审查角色和Skill边界以后设计。

## 6. 方法选择、交接与返修建议

可能需要的能力包括：内容组织、完整文案写作、声明与依据核验、行动路径检查，以及正文和机器表达的一致性核对。它们是能力需求，不代表要创建五个 Skill，也不代表已有同名方法可调用。

Agent 按真实缺口选择方法，明确输入、预期结果和文件交接位置。适用 Skill 若保存支持成果，应明确实际输出合同；建议继承“保存并读回 → 返回路径/摘要/未完成项 → Agent 实际读取后综合”的方式。该建议对未来 Gate 2 Skill 的具体接口仍待设计，不扩改现有 Gate 1 Skill。

返修沿“意见涉及的命题或结构 → 可见文案 → CTA/链接 → SEO/GEO/Schema → 当前基线”检查影响，只修改受影响范围。事实问题补核依据，方向问题提交具体决定，表达问题在授权内修订。保留历史批准源，受影响的批准范围升版本，不用旧自检覆盖新改动。

执行交付以保存、读回、自检并提交为终点，使用 `DRAFT_FOR_PROJECT_CONTROL_REVIEW`。用户确认、独立审查结果及下一 Gate 权限分别记录；不得自授批准或启动后续阶段。

## 7. 本轮讨论焦点与后续设计
