# Gate 4 → 新Gate 5视觉交接合同 V1.0

母版版本：0.1.0（提取候选，尚未安装/发布验证）。运行前读取[实例绑定合同](instance-bindings.md)；本站事实、授权与进度不随方法复制。

## 1. 当前流程和授权映射

本次把现行合并Gate 4的最终独立审查明确交由新Gate 5 Reviewer承担；这就是原来那一次审查。执行顺序：Gate 4制作/自检/冻结 → 新Gate 5独立审查及定向复审 → 总控关闭 → 获授权的Gate 6。禁止保留另一次同范围“Gate 4内部最终独立审查”。4A仍只是方向内部检查。

为兼容既有页面Manifest，当前生命周期仍记在合并Gate 4项下，同时记录`review_stage=GATE5_INDEPENDENT_VISUAL_REVIEW`。新Gate 5不是恢复历史gate5-execution制作职责，也不对历史成果补造审查。该技术阶段映射不要求全库改编号或补一份用户逐页批准。

原已授权Gate 4完整流程中的独立审查，由此角色承接；明确只授权制作、不含审查或明确暂停的任务仍按原停止点。总控依[按本站有效授权关闭授权](instance-bindings.md#authority)对同一视觉制作/审查组合关闭一次，不增加一轮批准。下一阶段、外发、开发和发布授权保持分开。

本合同补充[当前工作流](GATE_WORKFLOW_V3.2.md)、[共同工作合同V1.2](GATE4_COMPLETE_VISUAL_AGENT_SKILL_CONTRACT_V1.2.md)及[总控派发合同](../agents/project-orchestrator/references/handoff-contract.md)。旧“新Gate 5路由待统一”说明自本合同起由上述明确映射取代；其他条款保持。

## 2. 一个入口，原件引用

Gate 4制作方提供`handoff_entry`：可用现有冻结记录/索引的明确章节；仅缺少可用入口时新建一份简短交接文件。不得另复制源码、图片、正文或全部报告。不把交接入口当第二个当前Manifest。

以下字段必须可从入口直接解析或沿明确引用取得；表中字段是共同语义，不强制把历史JSON键批量改名。引用提供准确路径与对象/版本，文件身份用实际SHA-256等现行记录核对。跨机器不能访问的本机路径必须指出，不伪称可用。

| 字段组 | 必需内容 | 提供责任 |
|---|---|---|
| 任务身份 | `page_id`、`workset_id`、原执行/本次审查`dispatch_id`、实际作者、角色/方法基线、原始授权、停止点 | 执行方提供制作事实；总控补审查派发身份及不同Reviewer |
| 批准依据 | `authority_manifest`、`input_index`；完整批准文案/结构、品牌、共享组件与相关决定的精确引用 | Gate 4 |
| 冻结对象 | `source_identity`、`bundle_id`、冻结记录；设计入口、实际样式/脚本、字体/媒体、关键依赖及owner引用 | Gate 4 |
| 运行入口 | 查看/启动方式、必要本地条件、实际浏览器/字体/视口/DPR等渲染记录；实际运行与模拟边界 | Gate 4 |
| 正式证据 | `evidence_index`，1440/768/390完整图、长页可读入口、合同要求的适用状态图及运行记录；证据到源/视口/状态的对应 | Gate 4 |
| 视觉规则 | 实际采用的视觉规则及4A方向检查引用；不另做一套方向文件 | Gate 4 |
| 自检及机器结果 | 完整自检覆盖、正式捕获核对、路径/尺寸/bytes/SHA检查、真实DPR依据；工具/命令、输入身份和局限 | Gate 4 |
| 开放项 | 必修Finding、未测、允许后置项及其批准依据/责任/接受条件；无则明确为空 | Gate 4 |
| 审查任务 | 首审或定向复审、可写报告/证据路径、实际Reviewer及独立性、输出/停止边界 | 总控 |
| 复审增量 | 原报告/Finding、执行方响应、变更清单、修订后组合与未变证据引用 | Gate 4；仅复审必需 |

长页入口可以是可读原图、现有分段或可复核的滚动检查记录，不强制另做contact sheet。状态列表按真实合同，不创造不存在的功能。运行步骤只说明已有原型怎样查看，不要求Gate 5编写环境或验证平台。统一validator尚未交付时用实际既有脚本/原生命令等价检查，不能虚报统一工具PASS。

## 3. 就绪和接收条件

Gate 4只有在批准输入明确、完整自检无剩余本阶段必修、正式捕获正确、源和关键依赖可取得、机器结果与证据组合匹配、必需覆盖完整后，才能声明`READY_FOR_REVIEW`。允许后置的生产行为保留依赖，不视作当前未完成的视觉检查；不能把真实上游违约改名为后置项。

Gate 5先核对上述入口和输入：身份/授权/作者独立性、冻结与证据对应、必要文件可读及运行条件。通过准入不等于质量通过；接收核对直接写入独立报告开头，不新增接收Gate、接收批准或完整接收报告。不得要求Gate 4在交接时提供尚未产生的Gate 5报告或Gate关闭记录。

| 情况 | 返回与责任 |
|---|---|
| 缺交付材料、字段或运行说明 | `INPUT_INCOMPLETE`，Gate 4补具体项 |
| 缺授权、Reviewer身份或写入范围 | `INPUT_INCOMPLETE`，总控补派发；不自行推定权限 |
| 已有材料核验失配或确认缺陷 | `CHANGES_REQUIRED`，列证据与接受条件交相应责任方 |
| 必要环境/工具故障导致无法完成 | `FAILED`，列实际失败、已完成范围和恢复条件 |
| 输入有效 | 继续同一次独立审查，不单独关闭“接收关” |

Gate 5不替执行者补整套证据；不以缺某个固定工具名退回等价有效结果。可继续不受缺项影响的检查，但必需未测不能PASS。

## 4. 冻结、返修与写权限

源/依赖先锁定→采集正式证据→捕获及机器检查→冻结证据组合。`source_identity`与`bundle_id`分别表达源身份和完整交接组合；记录修改可能改变组合而不改变HTML。

提交后Gate 4不原地改动已交审原件。返修由Gate 4产生明确修订源/索引及组合，保留旧版；未变有效资产引用原件。页面变化复验受影响视口/状态与相邻回归；纯记录错误核实可信原件、字段和引用，不重新渲染未变图；采集错误补受影响图，原因及范围写在同一变化响应中。

Reviewer只写独立报告、必要运行记录及触发明确的局部证据；冻结源、执行索引、页面Manifest只读。总控写派发、接收和关闭记录及唯一当前Manifest；执行者不因交审或每次局部返修创建候选Manifest。当前Manifest不等于待审候选，审查以派发指定的准确`bundle_id`为对象，二者无需伪装同一状态。

## 5. 技术状态与闭环

| 事件 | 技术结论 | 当前生命周期解释 |
|---|---|---|
| Gate 4交付就绪 | `COMPLETE_VISUAL_FROZEN / READY_FOR_REVIEW`，可兼容旧`READY_FOR_GATE5`别名 | `DRAFT_FOR_PROJECT_CONTROL_REVIEW`，尚未批准 |
| Gate 5发现问题/缺项/运行失败 | `CHANGES_REQUIRED / INPUT_INCOMPLETE / FAILED` | 保持未关闭，定向返回，不进入Gate 6 |
| Gate 5完整审查或有效增量复审通过 | `REVIEW_PASS`，报告绑定bundle和原有效覆盖 | `PROJECT_CONTROL_REVIEW_PASS`，由总控接收，不冒充已关闭 |
| 总控关闭 | 核对权限、真实独立性、身份、审查范围、必修及依赖后关闭一次 | 合并Gate 4 `APPROVED / CLOSED`，同一记录注明新Gate 5审查已完成 |

旧`REVIEW_INPUT_INCOMPLETE`映射`INPUT_INCOMPLETE`，不改旧报告。总控已有有效独立结论时不再完整审图，疑点发`REVIEW_CHALLENGE`由Reviewer定向处理。若总控作为符合独立性的实际Reviewer，则只执行该次Gate 5审查，不再叠加另一审查者的同范围工作。

关闭后Gate 4→6接收入口引用同一视觉交接组合＋Gate 5报告＋总控关闭记录及开放依赖，不重新打包资产或再做视觉审查。Gate 6按现行差异路径接收。已关闭历史页面只继承有效原审查；不补造Gate 5编号、作者或执行记录，不因本合同重做。
