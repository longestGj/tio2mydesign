## 2. 岗位定位：页面视觉方向负责人

建议角色名：`agent-gate4`。

目标：**让已经确认的内容与响应式结构，获得适合本页买家任务、延续全站品牌且能够被 Gate 5 一致展开的视觉语言。**

交付后，用户能从真实样例看清这页将呈现怎样的视觉效果；Gate 5 能知道标题、正文、比较区、行动和状态怎样统一处理，不必重新猜测视觉方向。

Agent 对以下判断负责：

1. 买家首先应注意哪里，哪些信息需要连续阅读或比较，哪里采取行动。
2. 怎样沿用品牌和同类页面，同时表达本页已有的内容重点。
3. 字体、色彩、间距、表面和媒体怎样服务这些判断，是否有不必要的装饰或错误强调。
4. 哪些真实区域与状态足以检验方向，哪些差异还需要样例证明。
5. 方法产物是否符合原始要求，如何返修、独立送审和交给 Gate 5。

“技术、专业、可信”等形容词不能单独构成方向。方向必须说明可见做法及其用途，例如：用统一对齐的指标、清楚的单位和低干扰表面支持比较；不能只给整套方案起一个英文名称。

## 3. 输入承接与权限

从当前索引和页面 Manifest 获取有效组合，按根任务路由实际读取资料，不凭文件名最大版本、旧图或目录名称判断批准。

| 输入 | 取得的约束 |
|---|---|
| Page ID、完整 Brief、任务授权与当前 Manifest | 本页任务、允许修改范围、当前批准组合和停止点 |
| Gate 2 A/B/C 或已批准等价文件 | 模块职责与顺序；B 是本页可见文案唯一编辑源；C 定义本页动作、上下文、来源与机器语义边界 |
| Gate 3 批准源、三端线框、状态和审查记录 | 已确认结构、信息优先级、主要交互位置、响应式关系及未测范围 |
| 当前品牌、CTA增补、生产Logo、Global Chrome与法律合同 | 固定品牌语言、共享组件所有权、实际功能颜色及资产 |
| Home、Products及适用同类页面的批准组合 | 可复用的视觉做法与页面差异；按其批准范围参考，不继承旧事实或旧限制 |

正式页面执行须核对 Gate 3 批准和本次 Gate 4 授权；已有连续授权直接继承。某页结构获批不自动等于其视觉工作已授权。

可在批准结构与层级内细化字号、字重、行高、颜色角色、边框、阴影、圆角、间距、媒体呈现和状态外观。字体带来的自然换行和内容驱动高度变化可以在该范围内调整并核验。

改变模块顺序、列结构、交互位置或信息优先级时，须识别为 Gate 3 结构变化；改变文字、字段、动作或事实时交回 Gate 2/相应 owner。不能借视觉修订删文案、隐藏必要帮助、改变必填性或重定义 CTA。

共享 Header/Footer、Logo、菜单与法律区按 owner 合同消费。可以纠正本页错误消费；不能新建页面专用分叉。真实输入缺口只影响依赖它的部分，先完成其余工作。历史缺证 Hold、旧工具方案与旧运行状态不自动继承。

## 4. 组织视觉方向

### 4.1 先决定重点，再制作样例

说明本页的主要阅读、比较和行动任务，以及需要延续的共享语言。默认提交一个有理由的推荐方向；只有存在会实质影响阅读、媒体或密度的取舍时才比较备选，不强制做三套换色方案或额外设立“选方向 Gate”。用户要求多个方向时按其范围制作。

同品牌不等于所有页面长得完全一样，也不要求每页刻意不同。长文可强化标题与来源层级，产品比较可强化对齐和指标关系，申请操作可强化字段、帮助与反馈；采用何种处理须来自本页已确认任务。

### 4.2 形成能执行的规则

方向规格必须覆盖以下适用项；没有对应组件时注明不适用，不为补齐清单增加页面功能。

| 规则 | 需要落到的具体程度 |
|---|---|
| 色彩 | 背景、文字、主次动作、链接、边界和状态分别使用什么；依据当前增补解析，不只列色板 |
| 字体与阅读 | 标题/正文/标签/技术值的字体、字号、字重、行高及长标题处理；在真实长度上成立 |
| 间距与密度 | 组件内、组件间、段落和模块间的尺度与三端差异；服务内容关系，不固定整页高度 |
| 卡片、表格、列表和表面 | 哪些内容需要容器或分隔；圆角、边框、阴影如何表达层级；可点击与纯信息不可混淆 |
| 按钮、链接、表单 | 主次行动及本页实际存在的选择、帮助、错误等外观；维持批准行为和44px触控要求 |
| 图片、图标与图表 | 内容角色、来源/用途、比例与裁切、安全区域、替代文本方向及无图片回退；数据图使用已批准数据与关系 |
| 状态与动效 | 适用的默认、悬停、焦点、选择、展开、错误、处理中及结果表达；只写本页真实状态，动效克制且非完成任务的必要条件 |

直接引用共享 token 和 owner 合同，只记录本页使用位置及必要细化，不复制另一份全站品牌标准。功能色必须检查实际背景和文字/边界组合；不能因单独一个 token 曾合格，就认定所有渐变、照片或交互状态都合格。

### 4.3 让样例证明规则

选择能覆盖本页不同视觉规则与风险的真实片段：通常包含首屏重点、最密集阅读/比较区、主要行动区及其关键状态；若一种新组件未被这些片段覆盖，则增加对应样例。数量由实际规则覆盖决定。

样例内使用当前批准 B 的完整相关文字、长字段和限定语，注明在整页的原位置。不是把整页截成一句短文再声称可读。所有新增视觉处理均须有规则或样例落点；未展示的区域说明怎样沿用已展示规则。

用 1440、768、390 逻辑视口证明代表区域的视觉密度与缩放。Tablet独立检查；780物理像素只记为390 logical @2x。这里不要求再制作三张完整页面冒充 Gate 5，但样例必须明确自身覆盖范围。

展示与实际共享 Header/Footer 的必要连接；移动菜单及共享状态优先引用准确的批准资产，验证本次视觉消费没有造成问题，不重复设计。未变化资产可精确引用，不强制每次重导。

### 4.4 媒体与信任表达

图片、图标和颜色会产生事实含义。普通文档图形不能让人误以为已经持有某证书；申请选择状态不能看起来像已获批准；装饰性工厂图片不能被表述为本公司厂址或产能证据。

从当前命题与用户批准读取可表达范围，区分企业实景、通用场景、示意图和装饰。无图片是有效设计分支：保留内容与行动的自然连接，不留下空框或买家可见的内部占位。缺少企业事实依据按根§2.6提出具体命题，不把所有工厂/港口图片一概禁止。

替代文本方向描述图片在本页的用途；装饰图不堆关键词。若需新增会表达事实的图片或替代文本，交相应内容/资产责任方确认具体内容。图表不新增排名、覆盖关系、认证或无法支持的数值。

## 5. 方法分工建议

本轮建议只新增一项方法，名称暂定 **品牌应用与视觉样例制作**（候选 `brand-applied-visual-design`）。该名称与接口未成为已批准 Skill。

| 工作 | 责任与方法 |
|---|---|
| 决定视觉重点、推荐方向、选择样例、处理冲突与判断就绪 | Gate 4 Agent；保留判断责任 |
| 将已给定品牌、内容和结构转成一致的视觉规则与真实组件/区域样例 | 候选新方法：品牌应用与视觉样例制作 |
| 检查内容完整性、裁切、比较关系、几何和实际交互 | 复用[布局与交互核验](../../../skills/layout-interaction-verification/SKILL.md)的适用范围，不改其源文件 |
| 判断本页视觉是否服务任务、品牌是否被误用、媒体是否误导、实际色彩/状态是否合格 | Agent自检和独立审查者；布局核验通过不替代这些判断 |

新方法的独立价值是反复处理“品牌规则 → 用途映射 → 真实样例 → 三端及状态检查 → 可追溯资产”这一制作过程。它可以支持后续视觉修订，而不维护某页方向、事实和批准状态。不再拆出色板、按钮、截图等微小 Skill；也不因有核验方法就自动建立一个 Gate 4 Review 岗位。

候选方法接口：

- 输入：推荐方向及原因、精确品牌/共享输入、批准内容和线框、样例范围、视口/状态、允许修改范围、绝对 `output_dir` 与 `report_path`。
- 输出：规则与使用位置、可编辑样例源、导出图和状态资产、身份清单、实际检查结果与具体未完成项。
- 方法在既定方向内提出局部视觉选择；若发现结构/文案/事实需改，交回 Agent 判断，不静默改变输入。
- 保存后读回说明、打开资产，再交回绝对路径、摘要和未完成事项。Agent实际读取与查看后整合，不仅转述摘要。
- 字体、资产、路径或渲染缺失时交回真实限制和已有结果；替代字体或示意图必须明确标识为候选差异，不能宣称原样还原。

核验方法另接原始要求、实际候选与输出路径，保持被审文件只读。自检和独立报告使用不同路径；方法输出不建立第二份页面 Manifest。工具采用当前可用本地规划源与渲染能力，不调用 Superdesign，也不进入独立开发项目实施。

## 6. 交付与 Gate 5 接口

| 交付职责 | 内容 |
|---|---|
| 视觉方向规格 | 本页视觉重点、规则与用途映射、三端密度、媒体与回退、共享一致性、需决定的实际取舍 |
| 真实样例与资产 | 可编辑源、代表区域三端图及适用状态；路径、源版本、逻辑/物理尺寸、比例、状态、字节数和SHA-256 |
| 自检与独立审查证据 | 被查对象、实际图像/测量/交互范围、全部实质Finding、接受条件、未覆盖范围和复验 |
| 当前页面Manifest及交接 | 上游批准组合、当前视觉候选/批准身份、共享引用、用户决定、开放项和下一阶段权限 |

规格与简短自检可分章放同一文件；资产清单可独立引用，不强凑文件数量。正式页面成果进入页面既有 `04_planning/` 或等价目录，审查进入 `05_review/`；正式成果与唯一证据不只存工作区。

Gate 5 应能据此为完整页面逐处应用规则，补齐全部三端、菜单和适用状态，并验证整页节奏、Footer闭合及长内容。Gate 4 样例未覆盖的整页组合检查属于 Gate 5 的明确工作；不将局部样例合格写成完整页面已通过。

原 B/C 与 Gate 3批准源保持唯一。纯视觉改动不升级 C；实际合同变化交 owner 同步。Manifest只在阶段权威或组合实质变化时升版；同一未批准阶段的局部返修更新工作指针，资产和审查保留各自版本。已批准基线不覆盖，Manifest不记录自身哈希。

## 7. 自检、独立审查与返修

完整检查所交样例的全部视口和适用状态，再精简报告。重点问题：

1. 首屏与主要行动是否维持已批准优先级；视觉有没有诱导错误点击或让装饰抢走注意力。
2. 最长/最密集内容在真实字体与三端密度下是否完整可读；单位、限定条件和来源关系是否仍可理解。
3. 所用功能色与状态在实际背景上是否满足适用对比度；焦点、选择与错误是否有清楚且符合合同的区别，不能只靠颜色表达含义。
4. 媒体、图标、徽章和按钮外观是否产生超出批准内容的预期；无图片时是否仍成立。
5. Gate 5接手后还有哪些必须猜测的视觉决定；哪些是已确定规则，哪些仍需用户选择。

缺陷须说明具体位置、预期/实见、证据、读者影响、严重度及接受条件。审美偏好可以是建议，不能冒充违反合同。发现一个问题后继续检查其余范围；无问题时不制造Finding。

自检完成后，以 `DRAFT_FOR_PROJECT_CONTROL_REVIEW` 交总控。独立审查由有权总控或获授权且不同于设计执行者的审查者承担：实际读取原始批准要求、查看样例、核对资产与必要源，不以作者解释或核验PASS代替判断。本设计不自动派发子代理，不套用Gate 2专属预审状态。

返修沿用Finding ID。纯视觉缺陷在范围内修复；结构、内容、事实或共享规范变化交回相应owner，并提交前后差异、原因、影响、风险、回退和需同步文件。改变字体/间距等影响布局时检查三个主要视口及受影响状态；由独立方复验其原Finding，不编辑旧审查报告。

总控通过后，在对话直接展示样例、具体取舍和风险，用户不必自行阅读规格才能判断。方向选中、具体样例/规则批准、Gate关闭和下一Gate授权按实际对象分别记录；已经明确批准的同一对象不重复询问，也不擅自扩大为未呈现成果。

## 8. 本轮设计依据与已知风险

以下为文档学习所得，不是本轮重新执行页面审查或像素核验：

- [CTA无障碍增补](../../../brand/visual/TIO2_MALAYSIA_PRIMARY_CTA_ACCESSIBILITY_ADDENDUM_V1.0.md)已修正早期视觉标准的功能色用法：方法必须解析当前用途和覆盖关系，不能直接从旧色板生成所有按钮/链接。
- [DOC-000 Gate 4定向返修](../../../pages/documents/04_planning/DOC-000_GATE4_PCR01_TARGETED_REVISION_V0.1.md)记录了平板选择框/按钮重叠及手机帮助遗漏，说明品牌方向成立不等于真实样例可用。
- [DOC-TDS方向](../../../pages/documents/tds-sds-coa/04_planning/gate4/DOC-TDS_GATE4_VISUAL_DIRECTION_A_V0.1.md)和[DOC-REACH方向](../../../pages/documents/reach/04_planning/gate4/DOC-REACH_GATE4_VISUAL_DIRECTION_A_V0.1.md)展示同品牌下按文档比较与监管阅读任务调整表现的实践。其历史Superdesign记录、旧事实Hold和条件路由规则不复制到新方法。
- [Gate 3角色](../../../agents/gate3-execution/agent.md)及其[方法验证](2026-09-07-gate3-skill-validation-v0.1.md)已明确源中有全文、导出成功、零横向滚动不能证明用户完整看得到；Gate 4继续使用此证据边界。

本设计的主要风险是方法和Agent重复、过度制作样例，以及把组件外观调整扩大为结构重做。因此方法只承担可复用制作步骤；样例按规则与风险覆盖选择；遇上游变化按归属处理。若后续实际任务表明新方法没有独立价值，应收窄或取消拆分，保留记录，不增加流程来证明其必要性。

## 9. 后续建设与验证建议

先据本轮反馈收束角色与方法边界，再整理正式角色源及具体方法。本文本身不预先授予这些候选细则批准状态。

实际验证应看交付行为而非文档格式：在隔离原始输入上验证长技术比较、真实字段/错误、图片或无图片分支、三端视觉密度；核对旧功能色误用、伪认证视觉、裁切和源图版本不一致能否被发现。正常样例与人为缺陷分别标识，保留失败和修订。

需要独立验证时使用适当授权和最小原始输入，不提前给评估者预期结论；行为试验与真实页面授权分开。方法验证后再在获授权页面验证从输入承接到独立审查的完整角色流程。有限样本不推导普遍效果，格式校验不等于视觉能力已经验证。
