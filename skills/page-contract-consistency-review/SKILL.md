# 页面合同一致性核验

V0.4，项目方法源；2026-09-07用户已授权本轮定向修订，具体范围及有限验证见[修订记录](../../docs/superpowers/specs/2026-09-07-gate6-three-page-method-revision-v0.2.md)。按具体任务授权使用，不代表所有页面类型已验证或已运行注册。对照原始要求和实际成果，找出足以影响读者理解、开发实现或验收的矛盾与遗漏。调用 Agent 决定问题处置、阶段和批准；方法只交核验依据。

## 接收范围

接收原始任务、批准内容/行为/视觉源、候选组合、当前决定与共享/接收合同、初审或复验范围，以及绝对 `report_path` 和必要 `evidence_dir`。复验另接原 Finding、接受条件及变化版本。

读取源文件，不能以提交摘要代替。缺少某类证据时继续可支持的检查，并指出哪个结论不能成立。只写报告和诊断证据，不修改被审源、用户决定、当前 Manifest 或他人报告。

## 方法边界：允许与禁止

| 对象 | 允许做 | 禁止做 |
|---|---|---|
| 上游 | 核对批准身份、接口及触发对象，继承有效覆盖 | 无变化或冲突时重审全部文案、完整视觉和行为 |
| 证据 | 读实际源与对应差异，明确未测和日期 | 将hash或作者PASS当作语义正确；把未测写成通过 |
| 问题处置 | 定位差异、责任与接受条件 | 修改被审源/当前Manifest；将上游违约改名后置依赖放行 |
| 输出 | 差异、Finding、有效引用与局限 | 复制全文、重建依赖台账、无差异堆逐项PASS |

Gate 6调用时必读[执行与复核合同](../../docs/architecture/GATE6_EXECUTION_REVIEW_CONTRACT_V1.2.md)，接收路径、继承覆盖及触发范围。其他阶段按其实际任务范围执行，不自动套用Gate 6的FAST_PATH；尤其不能减免Gate 9实际实现核验。

## 1. 先确定身份与有效规则

核对路径、实际文件身份及批准对象；hash 比较证明文件身份，不证明文件内历史状态仍有效。把后续用户决定准确覆盖到同对象/同范围条款，保留其他有效批准；版本最高或文件自称 current 均不能单独决定权威。

正文、结构、视觉、事实状态、生命周期、关键词状态、开发授权分别解析。旧已批准包可按等价文件/章节继承，不要求重命名。规则冲突无法裁决时写具体命题、来源日期、范围及影响，不暗选方便版本。

把有效上游审查的对象/身份、覆盖范围及本次复核触发写入现有报告。较后用户决定和带日期的实施/环境记录分别覆盖同对象、同范围的旧状态；历史探测只能证明其当时结果。相同hash下出现与上游PASS矛盾的实际证据，仍须定向复核，不能因身份一致忽略缺陷。

## 2. 从需求查到呈现，再从呈现查回依据

按本次范围读取实际内容和动作，再读作者解释。Gate 6先继承有效上游，完整覆盖本次跨合同接口及触发差异；不将下表当作重新执行全部上游审查的清单。发现第一项问题不结束规定范围检查，复验从原Finding与变化进入。

| 对照链 | 需要识别的差异 |
|---|---|
| 页面任务→真实内容 | 必答问题只存在研究/合同中却未让读者看到；其他页职责被带入 |
| 批准正文→结构/视觉 | 丢文字、值/单位/脚注失联、限定条件在重排后脱离对象；条件差异没有批准依据 |
| 命题→来源/用户决定 | 主体、谓词、范围、限定词或日期升级；链接存在却不能支持句子含义 |
| 可见含义→SEO/GEO/Schema/社交 | 机器关系更强、查询意图变事实、可见内容删去后机器关系残留 |
| 动作→目标→上下文→接收方→结果 | 页面请求用户执行的动作没有接收位置；预填数量/可编辑性与接收合同冲突；确认被写成批准或交付 |
| 依赖→owner→本页责任 | 把共享/兄弟页的实现交给本页；将必需最终入口擅自变成条件隐藏或 fallback |

下表各项按继承/本次检查/不适用标明覆盖，可合并记录，不新增逐项PASS表。只比较本次适用内容，未有表单/FAQ/媒体时不制造状态。字串命中不证明可见，图像不证明键盘行为；无法核验几何或操作时记录未测，不替代专门布局核验。

对合同明确规定的标题、限定条件、机器实体关系、预填、错误及成功状态，核对实际值和含义，不只查字段是否存在。对本次接口或触发对象分别读取批准文案/合同和原型中的相应内容；精确值仅按本页合同检查，不把某页的规则移植到另一页。差异保留“批准要求及适用阶段→实际位置和值→影响及处置依据”的可追溯链。

## 3. 按对象解析条件，避免套用一条故障规则

区分：批准内容本身允许的条件展示、必须保留但依赖未来完成的入口、接收服务不可用时的表单状态，以及缺少事实依据的具体命题。分别追到原合同。

例如，必需兄弟入口未就绪可以阻断发布，不能由检查者改成隐藏；另一动作若有明确批准的条件省略及机器关系同步规则，应按其合同检查。两者并不自动矛盾，也不能互相推广。

未来未实现不等于当前策划错误。但依赖未写行为、责任或验收位置，会使交付无法执行，应报告当前合同缺口。

原型与生产要求有差异时，先核对批准范围。若原批准明确将该项作为示例或把真实接入留待实现，可报告需澄清的生产映射和后续验证，不要求提前完成生产代码；若原型违反本阶段已批准的内容、视觉或行为要求，则是上游必修，交回原owner。不能仅因内容存在于HTML或已有视觉PASS，就把所有差异归为生产事项。

未找到企业资料不自动得出禁止；已批准事实不恢复旧 Hold。未知的实时外部结论不能写成已验证；记录实际来源日期与验证限制。

## 4. 形成有证据的差异与覆盖结论

每个实质 Finding 包含 ID、精确位置、预期/实际、依据、影响、严重度、建议责任方和可判断的接受条件。没有实质问题时不制造 Finding；偏好建议、未测项和确定缺陷分开。

报告覆盖范围与各类未测项。严重度沿用项目口径，同时建议本阶段必修、用户待决、后续控制或可选优化，方法不签阶段批准。

复验读取实际修订结果，沿用 ID 核对接受条件及相邻回归。事实、机器语义、结构或行为改变时扩大到连带表面；纯索引修正不重做未变内容。

每个关闭结论注明实际被关闭的对象和证据：交付合同澄清、上游原型修订、生产实现验证。只看到新包纠正说明时，最多支持交付映射问题的关闭；原型/生产的真实缺陷和实施依赖按各自接受条件保留。未提供原件或运行证据时明确结论来自给定摘录，不能描述为亲自实测。

## 保存与交回

Gate 6报告可作为唯一包的审查章节或既有记录增量；继承身份和覆盖精确引用一次。保留本次差异、全部实质Finding、证据类型/日期及未覆盖范围；同一自检记录交Agent消费，不要求Agent重新完整扫描。少量源文引用足以定位即可，不复制全文或堆逐项 PASS。

写入指定路径后读回，核对报告引用的证据实际存在且对应本次对象。返回已保存的绝对路径、主要结论、未完成/未验证事项。不能把预计路径或工具执行成功当成报告已交付；核验无差异也不等于整页已批准或可发布。
