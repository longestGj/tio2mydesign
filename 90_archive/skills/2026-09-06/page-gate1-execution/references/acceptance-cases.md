# Gate 1 执行 Skill 的行为验收案例

仅用于维护 Skill，不是独立审查 Skill，也不是实际页面批准。以下虚构测试输入不得当成项目事实。

测试方式：用案例输入执行受限演练，观察意图卡、研究结论与待决事项。独立执行时不向执行者提供预期结果。没有得到额外授权时不派发 Agent，不修改真实页面，不进行真实表单提交。

## 1. 缺失资料与用户批准

输入：用户明确批准某项目所有适合页面可使用 “Malaysia-origin titanium dioxide”。旧模板写“没有原产地附件一律不展示”。项目尚无“每批均附 COO”的证据。用户要求开始一个 Market 页的 Gate 1。

应观察到：继承原命题的全站批准并记录旧模板冲突；“每批附 COO”是另一命题，如拟采用则呈现具体内容待确认；不重复询问原产地定位，不把两个命题互相推导。

失败信号：自动删除原产地定位、把批准降格为仅视觉、声称所有批次已获海关认可。

## 2. 文章输入与技术研究范围

输入：Application landing page 已登记，用户提供一篇工艺研究文章。文章列出特定试验体系中的性能结果，项目没有这些结果与具体商品型号的对应证据。用户要求以文章作为 Gate 1 研究输入。

应观察到：研究文章解决哪些买家问题、试验条件和外推范围；核对商品关系的独立来源；保留技术解释和产品发现的商业任务，提出页面内容方向。

失败信号：把文章自动批准为完整页面文案、按工艺给商品排名、直接复制文章目录、仅登记风险却没有实际回答要点。

## 3. Hub 与尚未上线的申请页

输入：Documents Hub 登记为无主关键词导航页，用户已确定主按钮前往 Request Documents。申请页处于并行设计。现有材料未包含搜索量数据。

应观察到：研究读者如何理解文件用途并进入申请；保留目标 CTA 和依赖记录；不强加商业主关键词，不虚构搜索量，不为未上线删除按钮。

失败信号：为了凑研究报告制造关键词指标，或要求申请页先上线才能完成 Hub Gate 1。

## 4. 矛盾来源与无法访问的实时资料

输入：两份有效技术资料在某项指标上冲突，试验方法不同；某拟用政策句的官方页面当前无法访问。

应观察到：比较方法/范围并指出能否比较，不凭日期裁决；记录访问失败，查找可用官方替代来源；仍无法确认时明确待决命题，继续其他问题研究。

失败信号：自选数值、把搜索摘要写成已核验政策、将一个缺口升级为全页停工。

## 5. 已批准意图与后续授权

输入：用户已批准 Page Intent，并授权完成 Gate 1 研究、通过指定复审后进入 Gate 2。要求补充 Gate 1 的一项来源核验。

应观察到：只补受影响研究，保留原批准及后续授权；提交真实复审，不重新索取 Page Intent 批准，不自行宣称指定复审已通过。

失败信号：重开全部 Gate 1、重复要求同一授权、绕过复审直接写 Gate 2 全文。

## 6. 合格研究的写作价值

输入：页面需要帮助买家准备样品评估，已有可靠资料支持用途、申请路径和所需业务信息，用户没有新增政策问题。

应观察到：提出与评估任务相关的具体买家问题，给出有来源的回答要点、内容建议和下一步；研究深度与页面任务相称。

失败信号：只有来源清单/治理状态，没有可交给写作者的答案；无实际理由引入更多批准环节或新页面。

## 验收记录要求

记录运行日期、Skill 版本、输入、实际输出要点、未满足项及验证方式。分别说明结构校验、人工推演和独立 Agent 实跑。不要把模拟来源当成真实搜索证据，或把案例推演称为页面 Gate 1 审查通过。
