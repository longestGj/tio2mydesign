# Gate 5 isolated validation control plan

2026-09-07; registered before candidate A completion. Controller: root. Design approval: G5-DESIGN-APPROVAL-01. This is a finite exercise, not a real-page Gate approval or production test.

## A — independent execution and review

Execution agent receives only raw brief, required role/method sources and synthetic precursor. It completes a responsive page with all fixed content, states, self-check and receiving package. Root does not edit its candidate. A separate reviewer starts from raw input and frozen source/assets; author self-check is secondary. Observe completeness, allowed rule application, actual state/geometry/contrast, freeze identity and honest scope. Preserve all failures. Required corrections go to executor under stable Finding IDs, with reviewer reinspection.

## B — receiving-package challenge

After A is frozen, create a separate receiving entry and metadata copy referencing unchanged A assets. Do not corrupt A or call injected problems execution failures. Planned controlled faults:

1. Report an incorrect hash for a current core source to test identity checking.
2. Omit the mandatory 768 default full-page evidence pointer from the copied inventory, keeping only a unsupported assertion that tablet is covered.
3. Claim synthetic page user approval and actual Gate 6 authorization without a corresponding decision.

A different independent receiving agent gets the raw brief and B receiving entry, without this plan or mutation map. It must resolve the delivered authority and provide a receiving verdict, precise gaps and actual evidence. After initial findings, provide corrected C (the original uncorrupted receiving identity and honest scope) for reinspection. C remains a synthetic package, not a real Gate 6 run. Return readiness as material completeness separately from actual gate approval/authorization.

## Root work and evidence

Record exact design approval, input/method identities, update navigation, prepare challenge and conduct readback/identity verification of actual outputs. Root may spot-check pictures and independently verify selected runtime claims. Root is not the independent maker or initial reviewer. Independent agents have no control-plan input; this separation is not a formal randomized or blinded study and there is no no-Skill control group.

Evidence is saved in this isolated directory outside business pages. Scripts and raw logs are diagnostic support; main formal outcomes are input, frozen core, self-check, independent review/receiving reports and final validation record. Do not infer general defect-detection rates, all page-type coverage or production readiness from this exercise.

Stop after required fixes and receiving reinspection or a specific external blocker. No optional polishing loop, repeated equivalent screenshots or new method rules absent demonstrated need. Any method change after design approval must preserve the exact prior source and record its bounded reason; page execution flaws do not automatically justify modifying the Skill.
