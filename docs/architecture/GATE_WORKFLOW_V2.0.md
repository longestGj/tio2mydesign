## 3. Gate 6：策划总审与开发交付

### 3.1 输入及独立审查

接收当前页面Manifest、Brief、原始批准决定、Gate 1–5有效成果、共享合同与开放项。已有等价成果按路径和章节映射，不为改名重做页面。Gate 5审查批准与Gate 6综合审查是不同对象；执行自检不能改名为独立总审。

总控依据原始要求与实际成果，检查页面目标、事实与来源范围、完整文案、SEO/GEO/Schema、三端视觉、关键状态、CTA/表单、跨页关系及共享组装的一致性。风险驱动地复核，不能无理由重做已批准研究、文案或设计。发现问题交原责任方修订，独立复核其接受条件；只重开受影响范围。

### 3.2 唯一交付包

在同一Gate内整理并核对：

1. 当前身份、授权、准确版本和文件读取顺序；批准正文、源、视觉和相关合同可直接找到。
2. 页面完整内容与呈现要求、CTA目标/上下文、字段业务含义、必填性、基数、条件显示和适用异常行为；共享合同引用owner，不复制竞争版本。
3. WordPress管理需求、页面数据语义、Next.js呈现结果、SEO/GEO/Schema与`site_scope=tio2-my`隔离要求。
4. 依赖、已知冲突、责任方、哪些条件阻塞交付以及哪些留待开发/验收/发布；未完成依赖不隐藏，也不把内部状态放进买家页面。
5. 稳定编号的接受条件：输入/状态、期望结果、所需证据类别、适用范围。Gate 9沿用这些条件独立判断。

Gate 6说明必须实现什么，不猜测开发仓库中具体post type、字段API名、GraphQL resolver、组件路径、分支或缓存实现。既有批准技术合同作为输入保留；具体绑定与实现方案由Gate 8核对。产品详情等已有机器可读内容合同要求继续保留，不能以合并阶段为由省略完整payload。

正文保持唯一编辑源；交付包以引用和差异说明组织，不另抄整套B/C。交付整理须核对版本、hash、链接、批准范围及语义一致性，不能借整理改变方案。Gate 5提供的是Gate 6审查输入，不因此要求Gate 5承担开发交付包制作。

### 3.3 完成及交接

Gate 6完成要求：综合审查完成，阻塞项关闭，必要交付输入齐全且获相应批准，非阻塞项有责任人与边界，当前组合唯一且可定位。只做完总审而缺少交付输入时，不能宣称新流程Gate 6完整关闭或`APPROVED_FOR_HANDOFF`。

继续使用既有审查链：`DRAFT_FOR_PROJECT_CONTROL_REVIEW` → `PROJECT_CONTROL_REVIEW_PASS_PENDING_USER_APPROVAL` → `APPROVED / CLOSED`，有明确预授权的事项按原范围执行。编制交付索引不是对自己设计成果的独立批准。

`APPROVED_FOR_HANDOFF`只表示交付就绪；实际发送给外部开发任务需要已有明确派发授权。记录接收任务、包版本和真实回执后才可写`HANDED_OFF`，无需另设Gate 7。Gate 6批准不自动授权Gate 8或Gate 10。

## 4. Gate 8：由开发方完成技术承接

开发方在自己的项目规则及授权范围内：

1. 检查实际代码/工作区基线是否包含本页依赖的已整合页面、共享组件、数据接口和站点能力；不默认最新主分支必然是正确承接基线。
2. 将批准内容语义映射到现有WordPress内容模型、API、Next.js路由/组件、元数据、缓存与表单；确定复用、扩展和必要新增。不得因旧基线缺少代码而重复建立平行站点架构。
3. 确定受影响共享面、回归对象和技术验证方法，遵守查询、路由、缓存、菜单、SEO、表单、媒体的scope隔离及禁止跨scope fallback要求。
4. 完成实现、测试和开发回执。需要改变批准内容、行为或共享合同的问题交回策划责任方；普通技术选择由开发方决定。

回执绑定：开发任务、实现commit/ref及工作区状态、可访问环境、数据来源、实现位置、测试结果、三端/状态证据、已知差异、未测范围和回退说明。静态页面或本地JSON预览不能代替合同要求的真实WordPress/API运行证据。按当前合同要求提交，不为新流程无差别增加测试或固定文件数量。

D23本次只调整交付规则，不在D16实施代码、测试、分支、合并、部署或生产操作，也不向开发任务自动发送消息。

## 5. Gate 9：沿同一合同独立验收

Gate 9锁定Gate 6批准包（或有效历史Gate 7包）与开发回执的准确版本，独立读取要求、检查可访问结果并核验相应证据。开发自检只是输入，不直接等于Gate 9通过。

至少按本页适用合同检查：完整内容与技术关系、三端视觉、CTA与表单路径、元数据/Schema/索引边界、WordPress/API至页面的数据一致性、scope隔离、共享及既有页面回归、必要依赖。

明确区分静态图、本地模拟、真实运行，模拟数据与真实WordPress，界面成功与实际接收，预览结果与生产条件。关键验收范围没测不能写全面通过；允许后置的发布依赖单列，不能冒充已验证，也不自动把它们当成所有页面验收的阻塞项。

Finding使用稳定ID、位置、预期/实际、证据、影响、严重度和接受条件，交开发修复。修复后对新版本定向复验并检查关联回归；不得把旧证据挂到新代码。D23只读审核，不直接修实现。Gate 9通过不等于发布，Gate 10及生产依赖继续单独控制。
