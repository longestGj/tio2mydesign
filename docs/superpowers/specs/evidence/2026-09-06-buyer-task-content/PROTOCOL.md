# Gate 2 内容方法对照 · 首轮协议

建立时间：2026-09-06，基线输出读取前。用户要求继续Skill方法设计与对照验证。

## 设计

- 两个历史原文摘录案例：DOC-TDS说明页、CONV-RFQ表单页；不是当前页面审查，未注入缺陷。
- 每个案例先由全新上下文执行者读取相同Gate 2角色与案例，不读取新Skill；候选Skill写好后，另由全新上下文执行者处理相同案例并读取Skill。
- 共享输入：根规则、Context、分工标准、当前角色及案例。模型与推理设置继承当前任务，不另行指定；同案两组输出任务相同。执行者不看评估标准、其他组结果或设计讨论。
- 所有练习输出写入各自隔离目录，完整保存后由作者读取实际成果。核心报告仍使用report.md，允许附属文案文件；不得改页面、Manifest或实际Gate状态。
- 原文摘录和哈希在inputs/中固定。页面源文件只为追溯，练习不更新当前事实或外部法律结论，不联网。

## 判定标准（不交给执行者）

不给总分；逐项记满足、部分满足、不满足或无法判断，并引用真实输出位置。

1. 可用结果：交付可直接阅读的英文内容和必要内部说明，而非只有建议、短占位或内容重复副本。
2. 任务效率：关键答案在必要判断前出现；确有重复时合并，但不靠删掉必要答案、错误消息或导航出口缩短文档。
3. Buyer Clean：买家区没有控制语言和实施规则；操作规则仍在内部合同中有位置，不因清理买家文案而丢失。
4. 行为一致：入口只承诺实际操作；选择、跳转、提交和成功的语义相符，不臆造可用性、收件或履约承诺。
5. 固定合同保持：DOCUMENTS保留单主Grade、其他Grade文本上下文、多文件及可编辑交接；RFQ保持字段/选项/单位/自由文本国家、预填编辑和不推导Grade、首载/失败/成功及数据保留规则。
6. 交付真实性：文件实际存在、可读，正文与内部引用对应；来源未给的精确目标/规则标清待补，不猜测。

没有要求所有案例都改写，也不以模块数减少或换词数量作为成功。对已合理内容的保留属于有效结果。两个样本不能支持普遍增益或真实转化提升结论。

## 基线派发模板

执行一次隔离的内容方法验证。用户已授权继续Gate 2 Skill设计与对照验证；skill-creator要求适用时独立行为验证。这不是当前页面执行或Gate审查，不需重新研究真实页面。先读根AGENTS、PROJECT_CONTEXT、分工标准与agents/gate2-execution/agent.md。然后只使用inputs/CASE-{DOCUMENTS或RFQ}.md的任务和原始资料，完成其中要求。不要读取任何Skill、Gate 2设计历史、其他验证输出或页面源文件，不联网。未提供的事实或目标不要猜测。所有新文件只能写到指定隔离目录。主交付report.md，包含实际可用的英文文案、必要内部说明与中文重要取舍；不修改项目Manifest或页面。保存后实际读回，返回绝对路径、简短结果和未完成项。不要创建子代理。

使用Skill的组仅将“不读取任何Skill”替换为指定读取新Skill，加入绝对output_path，其余范围相同。原始派发消息另由验证记录记录任务名与实际差异。
