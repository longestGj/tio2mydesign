# Gate 2 通用交付结构 V0.3

## 1. 状态与来源

- 日期：2026-09-06。
- 状态：`USER_APPROVED / CURRENT`。
- 来源：PRODUCT-PROC-CL 与 MARKET-EU-PL 两次真实 Gate 2 实践。用户同意复盘结论并要求修改 Agent 与交付方式。
- 替代关系：V0.3 是新任务的当前精简结构；V0.2 保留两步交付、A/B/C职责和历史示例，不再作为输出详细程度的默认模板。
- 不改变：Gate 1–5流程、页面身份、事实、共享合同、批准权、开发或发布权限。

核心原则：**工作可以完整，保存只保留接手者真正需要的信息。审查深度不由报告长度证明。**

## 2. 两步交付保持

| 阶段 | 当前成果 | 用户决定 | 停止点 |
|---|---|---|---|
| Skeleton | A + 本阶段必要的 C | 买家路径、模块职责、顺序和核心候选文字是否成立 | 用户确认前不写 Full Copy |
| Full Copy | B + 完整但精简的 C | 全部真实文案和模块顺序是否确认 | 用户批准前不关闭 Gate 2；Gate 3另行授权 |

每一步仍由 Execution Agent自检、不同 Review Agent预审、总控独立审查和用户确认。局部问题定向返修；只有事实、行为、买家路径或结构变化才扩大复查。

## 3. A：Content Skeleton

A 只需让用户和审查者看清实际页面：

- 页面任务和必要买家路径；
- 实际 H1、Hero、模块标题与顺序；
- 每个模块承担的判断或行动；
- 足以审查方向、行为和语言的候选文字；
- CTA、目标和关键上下文；
- SEO Title、Meta、Canonical方向；
- 真正影响本轮决定的开放项。

不要在 A 重复完整 Brief、来源登记、共享合同、逐项自检或每个未采用模块的长篇解释。模块取舍只说明真正可能引起审查争议的决定。

## 4. B：Full Buyer Clean Copy

B 是买家可见文字的唯一编辑源，按最终阅读顺序连续呈现：

- breadcrumb、H1、标题、段落、表格、列表和公开来源；
- 实际 CTA、链接标签、帮助文字；
- 本页拥有的表单或状态文字；
- 页面确实需要的 FAQ、技术表或说明。

内部 Page ID、Gate状态、来源映射、字段键、路由就绪、Hold、验证数字和写作理由不得进入正文。没有真实买家任务时，不为模板增加模块。

## 5. C：页面特有内容与操作合同

C 只记录本页新增或改变的合同，不重述共享 owner 的完整规则。默认包含四部分：

1. **身份与当前组合：** Page ID、语言、URL、关键词、确认的 A 和当前 B。
2. **页面特有动作：** 正文位置、目标、此页传递的上下文、与默认行为不同的限制或决定。
3. **SEO/GEO/Schema：** 精确 Title、Meta、Canonical、实体关系及其 B 中可见依据。
4. **事实与开放项：** 只列 B 实际使用且需要追溯的命题，以及影响当前交付的未决问题。

对于共享 RFQ、Documents、Header/Footer 或法律合同：

- 引用当前 owner 文件或稳定标识；
- 只写本页依赖的差异，例如预填 Poland 且必须可编辑；
- 不复制 owner 的全部字段、验证、错误、成功状态、cardinality 和禁止项；
- 只有当 Buyer Copy 明确依赖某个已批准限制时，才用一句话记录该限制和来源。

Buyer 冷读在 C 或提交摘要中只保存四个风险优先结论：最危险行动句、最弱英文句、信息不完整路径、页面特有价值。不要再建立逐项 PASS 表。

## 6. 当前 Manifest

Manifest 只回答“现在用哪一组、批准到哪里、还有什么没完成”：

- 页面身份和当前 Gate状态；
- 当前 A/B/C 的路径、版本、hash和状态；
- 当前 Review、总控决定和用户批准记录的指针；
- 当前开放 Finding 与下一责任方；
- 上一个 Manifest 的路径作为历史入口。

旧 A/B/C、每轮 Finding全文和所有历史状态保留在原版本及 Review文件中，不逐行复制到新 Manifest。当前 Manifest 可以引用历史链，不重写整条时间线。

## 7. Review 与返修记录

Review Agent 实际读取全部 Buyer Copy，但无 Finding 报告默认比被审 Buyer Copy短。保存顺序：

1. 对象和 verdict；
2. 最危险行动/负担句；
3. 最弱 Buyer Copy句；
4. 页面特有价值和最重要的信息不完整路径；
5. Findings、保留项和下一责任方。

不要为每个标题、CTA或通过项建表。Finding仍需位置、买家解释、影响、严重度、要求和接受条件。

返修响应只写 Finding、前后文字、受影响合同位置和接受条件自检。Re-review只写实际新文字、接受结果和相邻回归；不重复初审全文。

## 8. 完成标准

- A/B/C各有一个明确职责，不维护竞争正文。
- 简单页面的合同和Review不因复制共享规则而远长于Buyer Copy。
- 风险句被实际挑战，不以“professional”“contract aligned”或大量PASS表代替判断。
- 用户在对话中直接看到待决定的模块或全文。
- 当前组合、批准范围和下一Gate权限可由Manifest快速确认。
- 历史版本保留，已批准页面不因V0.3自动重做。
