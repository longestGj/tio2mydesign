# 完整页面视觉制作

设计候选 V0.1，2026-09-07；尚未完成行为验证。范围与 Gate 6 接口见[首版设计](../../docs/superpowers/specs/2026-09-07-gate5-agent-skill-design-v0.1.md)。

把给定内容、结构和视觉规则落实到整页，检查真实实例与状态组合。Agent 决定页面取舍、授权和交付状态；本方法交回实际资产、检查与缺口，不维护页面批准或独立审查结论。

## 输入与路径

接收唯一全文源、批准模块/三端结构、视觉规则与代表样例、动作/条件及共享合同、媒体分支、可编辑上游源、视口/比例/状态范围、可用工具，以及绝对 `output_dir`、`report_path` 和允许修改范围。输入可以是文件/章节引用，不要求重新整理全文。

缺少会改变呈现的规则或行为时，指出具体实例及影响，交回 Agent；继续不依赖该缺口的部分。不用短占位句、猜测状态或新增 token 填补。已有批准源保持，候选使用新路径或明确允许更新的工作版本。

## 1. 把样例规则展开到全部实例

建立简短覆盖映射：`模块/实例 → 内容位置 → 批准结构 → 视觉规则 → 视口/状态证据`。相同模式可合并记录并列出实例范围；最长内容、不同背景、不同状态须单独确认适用性。

从本页批准源和共享 owner 来源制作，不复制其他业务页作为母版。已有可用视觉保留；把 Gate 4 未出图的实例和模块连接作为明确工作项。可编辑预览已有全文不证明整页视觉已完成。

按固定值、允许范围及响应规则应用字体、间距、表面、动作、媒体和状态。允许自然换行和内容驱动高度；超出规则的新视觉选择交回 Agent。不得通过隐藏、截断、改字、改列数或移动动作区域解决视觉问题。

## 2. 检查连续页面而非孤立组件

分别完成要求的全部逻辑视口。TiO2 Malaysia 使用 1440、768、390；780 仅作 390 logical @2x。遵循已批准的响应式内容差异，不机械要求三端像素或元素数量相同。

逐端检查首屏至 Footer 的完整阅读路径：主任务和主行动是否突出，标题与正文尺度是否连贯，模块边界是否清楚，重复组件是否一致，密集内容与行动之间是否自然衔接。页长由真实内容决定，不设置统一高度、模块数或截图配额。

技术对象与指标、数值与单位、脚注与范围、命题与来源必须保留关联。图表/图像不成为唯一正文来源；可编辑文本与语义位置可由核验者追溯，静态稿无法证明爬取或生产语义时说明局限。

媒体按批准用途、比例、裁切和无图分支执行，保留关键信息与替代文本方向。素材尚不可得时交回缺口，不默换成示意实景或留下买家可见空框。媒体改变事实含义时停止该项，交 Agent 判断。

## 3. 在页面上下文制作真实状态

按输入实际功能选择状态；不机械添加表单、FAQ 或失败状态。要求的移动菜单、共享对话框及页面专属状态应保留必要上下文，检查状态变化后相邻内容和 Footer 是否正常流动。

对表单/选择，保留完整标签、帮助、选中值、限定和错误关系；对展开内容，保留完整答案、来源和后续流。状态板用于比较，真实组件状态用于证明实际呈现；本地模拟反馈不表示已发送或接收。

覆盖实际存在的表面与状态组合：正常、hover、键盘 focus，以及选中/错误等适用状态。相同组合可复用核对，不按每个链接重复造报告。功能色需针对实际文字背景或边界相邻面计算；外侧焦点与外围表面、内侧焦点与控件表面分别判断，不能混用。透明/图片背景检查实际合成后的最弱位置，无法确认则如实标记。

共享文字、Logo、导航、固定 RFQ 和法律动作按 owner 消费。只修本页错误消费，共享行为改变交回 owner。不得为了测试向真实业务系统发送请求。

## 4. 预检、冻结和正式导出

先诊断渲染并实际检查，记录以下结果和证据：

- 原始内容/结构/视觉及共享来源身份明确；正式源和必要字体、样式、数据、脚本不以临时目录或另一业务页为唯一依赖。
- 内容/关系双向对应、三端完整可见、无裁切/碰撞/异常固定空白；TiO2 Malaysia 可见控件宽高均至少 44px。
- 实际字体/素材加载成功；视觉规则与实际值对应，颜色/表面/状态检查有依据。
- 本页适用菜单、覆盖层、展开/选择/反馈实际成立，关键操作与焦点可检查；静态、源码、实际运行和模拟分开记录。
- 截图范围正确；普通截图已清除非预期焦点/hover，状态截图在捕获时仍处于所述状态。

不适用项说明输入依据；适用硬项失败先修复。关键范围未验证时交回已有成果与缺口，不记录 `PASS_FOR_FORMAL_RENDER`。通过后记录该状态，冻结源/依赖路径、字节、SHA-256、输入、预检记录及渲染条件，再导出正式资产。详细几何和交互核验可由调用方提供的既有核验方法完成，不以记录存在代替实际检查。

2x 使用原生比例渲染，不把 1x 栅格放大后冒充高分辨率输出。菜单等视口状态按真实视口捕获，避免携带关闭背景的整页空白；全页图仍覆盖完整正文至 Footer。记录浏览器/渲染器、字体、视口、DPR、状态及必要裁剪边界。

源或依赖改变须建立新冻结身份，更新受影响导出。渲染差异先核对字体、视口、指针/焦点、状态及区域范围，再决定是否修改页面；采集错误与设计缺陷分别记录。未变资产精确引用原路径/身份并说明为何仍有效。

## 5. 查看、修订与交回

实际打开全部正式全页和关键状态。先看整体，再按可读比例分段覆盖全页与连接处，检查真实内容、视觉主次、长值和状态变化。零横向滚动、DOM 字串命中或导出成功都不能单独证明完整可见。

布局/交互核验按调用方实际使用的[布局与交互核验](../layout-interaction-verification/SKILL.md)进行；该方法只写问题与证据。本方法在允许视觉范围修订，超出内容、结构、方向或共享边界的问题交 Agent。全部实质问题保留，偏好建议与未测范围分开，不把自检写成独立 PASS。

保存 `report_path`：

1. 精确输入与范围、整页应用映射、必要取舍和上游差异。
2. 三端、状态、视觉检查及相关核验引用；Finding 和具体未测项。
3. 资产清单：源/依赖与导出路径、角色、逻辑/物理尺寸、比例、状态、字节、SHA-256及冻结/渲染身份。
4. 需要 Agent 决定或交后续 owner 的问题和影响。

把冻结源/依赖、正式三端/状态图、规格及最终检查列为 `approval_core`；原始测量、分段图、失败、旧候选列为 `diagnostic_support`。核心清单引用诊断入口，不复制全套重复截图。清单不是页面 Manifest，方法不编写 Gate 6 结论或生产交付合同。

读回报告、打开资产并核对清单后，返回 **已保存绝对路径、结果摘要、未完成/未验证事项**。保存、导出或读回失败时准确报告，不返回预期路径冒充完成。由 Agent 实际接收并组织 Gate 5 审查和 Gate 6 交接。
