# 网站级准备最小交接模板 V1.6

通用模板，不是已批准网站事实。使用[共同合同](WEBSITE_PREPARATION_HANDOFF_CONTRACT_V1.6.md)。允许现有等价来源映射；占位项须替换为实际值或明确缺口，不以空表宣称就绪。

## 对象与权限

- work_type：SITE_PREPARATION
- site_id：待填写；仅准备对象身份，不批准品牌/域名
- 模式、控制记录、准备范围、原始授权：待填写
- 总控owner、实际执行/独立审查身份：待填写
- 当前网站来源基线位置及版本：待填写
- 本次新增/变化、停止点：待填写

## 接收与下一步

- 原始成果及独立审查入口、作者身份、具体结论：待填写
- 已有用户决定与本次剩余决定：待填写
- readiness_scope：接收包/阶段、具体对象与可用用途、局限；W1–W4按本包交回范围填写，不要求页面批次。W5/网站汇总写当前准备批次及可核对输入；不得写成启动授权或全站发布通过
- unresolved_items：问题、证据、影响、owner、最小解决动作
- next_action：责任人、动作、allowed及对应授权
- recovery_entry：原控制记录位置
- 可选实际活动/等待时间：没有记录则明确未记录，不由文件时间推算

总控只维护来源与决定映射；页面Manifest继续由页面控制owner维护。准备完成不等于页面Gate通过或发布授权。

当前包序：W1企业产品事实 → W2市场/客户/竞争 → W3商业战略与网站定位 → W4架构与采购旅程 → W5生产准备。W1交回事实概览、来源映射、缺口/冲突，不强制三份文件。

W2适用交回：准确W1输入及局限、实际市场/客户/竞争样本与选择理由、六部分分析、事实/自述/推断/假设分类、机会适配条件与反证、W3可判断范围及未决项。可引用同一主报告，不重复建三份成果；不自动批准战略或启动W3。

W3适用交回：准确W1/W2输入、既有战略/可调整范围、选择取舍、网站定位、用户决定及假设验证安排；向W4传递客户/市场、供给、价值证明、主要行动、品牌分工和限制。已批准、建议、待验证明确区分，不把研究或审查PASS当用户战略批准。

W4适用交回：W3批准定位与W1/W2依据、页面职责/关键词/语言/URL资格、采购旅程/内链、共享能力/owner、异常恢复、审查及用户决定；区分未批架构与未实现依赖，向W5交明确可安排范围，不自动启动页面。

W5适用交回：W4准确批准范围、当前批次与后续顺序依据、代表页/复用与扩批条件、素材与共享依赖及owner/影响阶段、当前批次Brief及批准资格、容量依据/局限、审查与readiness_scope、原授权及停止点。可映射现有三类交付，不增加平行台账；计划建议由总控结合实时进度采用，未授权不启动页面。

标准与共享依赖复用原清单：适用Playbook/阶段标准、品牌基础、共享合同分别给出来源或待建立任务、提供/消费owner、消费阶段/需要时间、批准依据及缺口。缺项按消费阶段解决；不要求早期包提前完成这些标准。

后续批次增量准备记录在原控制记录：触发（下一批准入/代表成果可复用/关键输入变化）、当前获授权准备范围、复用来源、本次差额、停止点。已有结果足够时只引用，不重建任务包。W1/W2尚无页面时，Gate 0映射不适用，可省略，不填假Page ID。
