## 3. 核心设计选择

### 一个执行角色、一个新方法、一个复用方法

Agent负责完整页面是否成立以及能否交回。新 Skill 负责把批准视觉应用到完整页面，其新增价值是全部实例、连续节奏、状态与上下文、全页证据和可靠交回。现有布局核验负责内容关系、几何与实际操作，不复制第二套核验方法。

Gate 4 方法明确面向方向和代表样例，不能直接将其局部结论扩为完整视觉。本版暂不扩大其范围或另建视觉审查 Skill；实际颜色、品牌和整体视觉判断由 Gate 5 Agent及有权独立审查者承担。

### 三类修改边界

- 在批准规则内完成未展示实例、自然换行和内容驱动高度，属于 Gate 5。
- 新视觉规则交 Gate 4；列数、模块顺序、优先级或动作区域变化交 Gate 3。
- 正文、事实、字段、CTA/接收行为、SEO/GEO/Schema变化交对应 owner；共享改变交共享 owner。

问题只定向交回受影响对象，不自动重开全页。规则具体固定的值不能以“视觉微调”名义任意改动。

### 完成标准同时面向用户和 Gate 6

用户看到完整三端及关键状态，能判断最终效果；Gate 6能定位同一批准组合的源、图、规则、行为、证据与差异。不能用“图已导出”或“方法自检通过”作为完整完成条件。

## 4. 拟采用的工作流

1. 确认本页授权与 Gate 2/3/4 精确输入，形成简短输入卡。
2. 映射全部模块、实例及实际状态；明确 Gate 4 代表图未验证的位置。
3. 制作完整三端与关键状态，检查整页阅读、比较和行动。
4. 诊断预检通过，冻结源/依赖/输入，导出正式资产。
5. 完整自检及定向修复，区分视觉、采集、内容/结构和共享问题。
6. 冻结候选交有权独立方审查；处理全部必修 Finding，保持历史和原 ID。
7. 总控通过后直接向用户展示完整效果及变化，记录精确批准。
8. 完成 Gate 5→6 交接，单独核对 Gate 6 授权。没有授权时只交接就绪，不启动审查。

步骤表示责任关系，不要求另建八份文档。现有成果可按章节映射；检查数量、截图数量和文件数量不作为质量分数。

## 5. Gate 5 → Gate 6 接收合同（候选）

### 5.1 单一接收入口

建议页面级名称：`{PAGE_ID}_GATE5_TO_GATE6_HANDOFF_Vx.y.md`，放在该页既有 `05_review/`。当前 Manifest 引用它；它反向引用当前 Manifest，不成为第二份权威组合表。

Gate 5 送审前即可准备交接草稿；批准后补入正式决定与精确批准入口。交接是否完整、Gate 5 是否批准、Gate 6 是否授权分别记录，避免用一个 READY 状态掩盖差异。

### 5.2 最小内容

| 接收项 | 必需内容 | 不重复维护的内容 |
|---|---|---|
| 对象与权限 | Page ID/URL、当前 Manifest、Gate 5批准来源/范围、Gate 6授权来源或未授权 | 不从批准视觉推导后续阶段权限 |
| 原始要求 | Brief、登记/关键词、事实决定、Gate 2 A/B/C、Gate 3结构、Gate 4规则的精确路径/章节 | 不复制研究或全文，不把作者自检当原始依据 |
| 批准视觉组合 | 冻结源/依赖、全页/状态图与身份清单入口、最终视觉规格、渲染条件和复现入口 | 清单保存尺寸/hash，交接不再逐行抄清单 |
| 内容与状态落点 | 模块/组件映射、三端差异、状态触发与所示上下文、适用与不适用依据 | 不新写动作合同或造状态 |
| SEO/GEO/事实与行为 | 元数据/Canonical/索引/Schema、来源与日期、CTA/预填/接收/条件渲染的当前合同位置；视觉相关变化或冲突 | 不重做研究、另写Schema或建立第二份字段表 |
| 共享与隔离 | 品牌/Logo/Chrome/法律/接收方 owner、当前消费来源；site_scope=tio2-my 的既有合同位置与后续验证责任 | 不生成 Gate 7 CMS/API/部署实现包 |
| 变化与审查 | 相对上游的实际差异、对应批准；Gate 5自检、独立报告、返修与未结Finding入口 | 不复制全部审查过程或提前写 Gate 6 verdict |
| 未测与后续依赖 | 具体问题、影响、证据类型、owner、当前状态、应处理阶段及验收位置；时效性资料需复核的日期/触发条件 | 不把本地模拟写成生产证明，不恢复旧Hold |

Gate 6应能独立回答：这页负责什么；批准的事实和内容是什么；图与源是否同版；三端/状态是否完整；动作与接收方是否一致；机器语义是否有依据；哪些仍是后续依赖。上述是接收覆盖要求，不预先决定 Gate 6 的完整角色设计或审查结论。

### 5.3 就绪判定

- 文件与依赖实际可读取，源、图和当前批准组合一致，必须资产无缺失。
- 未展示状态有明确的适用判断；必须状态缺失不能仅标“后续验证”后通过。
- 所有实质上游变化有明确批准或仍待决定，不存在未声明的结构/事实变更。
- 核验范围与证据能力匹配，开放项有责任和阶段；后续运行依赖可随包交回。
- Gate 5批准后可记录 `READY_FOR_GATE6_WHEN_AUTHORIZED`；实际启动仍须另有有效授权。

缺口交回具体对象和影响，已有成果仍交付，不让 Gate 6重新猜文件位置。历史已批准页面以后进入相关修订或交接时映射等价资料，不批量补做。

### 5.4 两次审查及 Gate 7 边界

Gate 5送审针对完整视觉候选及其批准符合性；Gate 6在 Gate 5获批后，结合全部页面合同对内容、SEO/GEO、证据、视觉、移动端、内链和转化做综合总控审查。原证据可以复用，独立判断不能直接复制。

Gate 5负责形成能审查的组合，不签发 Gate 6通过；Gate 6结果与 Gate 7授权分开。Gate 7负责正式开发交付映射、实现与验收合同，Gate 5交接只提供其上游依据和已知依赖。

## 6. 风险、同步与回退

| 风险 | 本版处理 |
|---|---|
| 重做 Gate 3/4 | 锁定已有结构/规则，只完成实例和整页效果；超范围定向交回 |
| 没有溢出但内容被裁切 | 双向内容/关系核对、可读比例查看及几何/状态核验结合 |
| 普通截图携带错误hover/focus | 预检捕获条件，状态捕获后再确认实际成立，区分采集与设计问题 |
| 交接文档膨胀 | 一个简明入口引用原始合同与清单，规格/方法报告允许合并章节 |
| 将候选设计当成规范批准 | 角色、Skill和导航明确标候选，本轮不改现有方法与页面权限 |

本轮同步范围为本设计、两个候选源、Agent/Skill目录与Index的导航条目；不更改页面Manifest、Status、共享标准或已批准Gate 1–4源。若本版未采用，保留为设计历史，更新候选入口；后续实质修订升版并保留此前候选。
