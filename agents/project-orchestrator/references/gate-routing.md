# 总控 Gate 路由 V0.14

阶段顺序与批准规则由[当前工作流](../../../docs/architecture/GATE_WORKFLOW_V3.2.md)维护，本表仅定义总控如何消费阶段结果；角色及方法当前版本从根Index取得。不用此表改写现有阶段合同。

## 8. 总控质量职责：明确对象，不默认重审

| Gate | 总控的实质判断 | 谁完成专业独立审查/批准 |
|---|---|---|
| 0 | 身份、职责去重、Brief与授权准入 | 按现行准入合同；新范围提交用户 |
| 1 | 按[三路径合同](../../../docs/architecture/GATE1_THREE_PATH_EXECUTION_CONTRACT_V1.0.md)分流，检查页面适用性、实际缺口及新增判断 | 按路径独立审查；有效既有证据继承；总控或其他独立审查者完成，不叠加同范围审查，用户批准保留 |
| 2 | 直接读实际成果，核对事实权威、跨页合同、内容/机器语义与批准范围 | 独立Buyer Review保留；总控不复制语言审查，用户内容批准保留 |
| 3 | 结构范围、共享继承、未决项归属与关闭条件 | 不同于作者的结构审查；总控可承担有效独立审查，但已有他人结论不默认重复；常设关闭 |
| 4 / 新5审查 | 按[4→5交接](../../../docs/architecture/GATE4_GATE5_VISUAL_HANDOFF_CONTRACT_V1.0.md)核对候选与实际独立性，接收完整审查链后关闭一次 | 新Gate 5承接合并Gate 4唯一最终审查，保持现行生命周期映射和常设关闭 |
| 6 | 按[5→6接收](../../../docs/architecture/GATE5_GATE6_ACCEPTANCE_CONTRACT_V1.0.md)核对六项准入，按[执行合同](../../../docs/architecture/GATE6_EXECUTION_REVIEW_CONTRACT_V1.1.md)处理差异及新增合同 | 新包由不同身份独立审；总控或专门审查者二选一，不叠加重审；常设关闭 |
| 8 | 精确交接对象、回执和合同变化的责任归属 | 开发项目执行及自检；总控不越界实施D16代码 |
| 9 | 指定实现、实际证据、未测/后置边界与问题归属 | 独立只读验收；按原用户授权/批准方式，不套用3/4/6 |
| 10 | 发布范围、条件和用户决定是否齐备 | 用户明确发布授权，生产执行归有权开发/发布方 |

已知验证盲区可以要求补充QA，但必须写明触发事实、对象、责任人、最小验证和解除条件，放现有问题/控制记录，不因一次失误给所有页面永久增加一整轮审查。总控主动发现影响通过的疑点不得忽略；提出REVIEW_CHALLENGE，由合适独立身份核实，暂停受影响关闭。

自己实质修改了被审内容、视觉或开发合同后，总控不得对该对象自签独立PASS；改派不同审查者。排期、输入导航及记录批准本身不等于成果作者。


## 文章支线路由

按[文章交接合同](../../../docs/architecture/ARTICLE_D23_D22_HANDOFF_CONTRACT_V1.0.md)执行：D23选题与方向批准 → D22研究/写作/独立审查 → D23接收 → 用户正文批准 → 按授权从Gate 1开始页面流程。文章是独立工作类型，不另编号为网站Gate；总控不重复D22专业审查。未登记页面先补准入，已有页面Gate 1有效结果按变化复用，不能把文章PASS映射为Gate 1关闭。文章接入本身不改变Gate 2；后续按下述内容适配规则承接。

## 内链专项路由

使用[内链审查Agent](../../internal-link-review/agent.md)及[专项合同](../../../docs/architecture/INTERNAL_LINK_REVIEW_ACTIVATION_V1.1.md)：Gate 6提供预期链接/依赖，专项检查跨页关系与实际落点，Gate 8修复实现，Gate 9消费有效证据并核验剩余条件，总控协调及关闭。规划与运行结论分开，优化建议不自动变为必修；不是新增阶段。

总控在四个时点按有效任务范围启动：一批Gate 6交付包就绪后做PLANNING_REVIEW；一批Gate 8交回进入Gate 9时做RUNTIME_REVIEW；修复后定向复验；发布准备时对明确发布集合做全站关系与覆盖核对。默认按开发批次组织，共享导航统一核验、各页确认组装，不逐页重扫全站。复用相同版本/环境/范围的有效证据；未开发目标如实登记依赖，阻断按合同判断。已有任务授权覆盖专项时直接衔接，不重复询问；无明确对象、环境或有效授权只做准备。时点规则不自动创建定时任务或授予发布权。

三类直接归属：批准目标正确但实现链接错误交Gate 8；交付包遗漏、目标映射错误或验收要求不清交Gate 6；锚文本、正文或产品关系含义错误交Gate 2／内容负责人。其余一律交总控，包括架构/URL调整、共享导航、未开发目标依赖、优化建议、缺项及责任不明确的问题；内链Agent不得自行向其他owner派发。共享导航问题即使表现为实现错误也先交总控协调。

## Gate 2内容处理

按[交付结构V0.6](../../../docs/superpowers/specs/2026-09-08-gate2-delivery-structure-v0.6.md)§12–16区分批准内容适配、定向补齐、完整撰写，可按模块混合；与Gate 1研究路径独立判断。有效同页Skeleton继承，文章批准不自动等于页面骨架批准。全页Buyer冷读与用户批准保持，专业论证按身份/范围/时效继承；疑点交原内容owner，不新增完整专业审查链或竞争Manifest。

## Gate 0之前的网站准备

按[准备合同](../../../docs/architecture/WEBSITE_PREPARATION_HANDOFF_CONTRACT_V1.6.md)消费W1–5结果，网站准备不是新Gate。Gate 0继续核对具体页面登记/Brief/范围/授权；Gate 1仍按本页缺口分流。共享未实现依赖不能一律阻断前期策划；重大未决冲突按受影响范围处理。

W2市场、客户与竞争分析由准备合同V1.2接入，承接W1、交给W3；仅形成战略依据，不能直接批准定位或替代Gate 1逐页研究。

W3战略定位由准备合同V1.3接入，独立论证审查和用户战略决定分开。已有方向适配、实质选择比较，交W4明确定位边界，不提前完成页面架构或授予启动权限。

W4架构与采购旅程由准备合同V1.4接入，承接W3批准，交W5生产安排；不代替Gate 0准入或Gate 1本页研究。新增页面/最终URL/重大导航由用户决定，未实现依赖按owner登记。

W5生产准备由准备合同V1.5接入：六部分形成当前批次计划和输入，总控接收后核对Gate 0准入及Gate 1启动。不得以准备完成绕过批准Brief/页面授权；已有页面不重跑网站准备，批次变动按实际影响增量处理。

准备合同V1.6：W1对W2研究、W2对W3比较、W3对W4批准定位、W4对W5批准架构分别交回就绪范围，不提前要求页面批次。W5当前获授权准备批次交总控核对Gate 0；下一批需要准入/代表成果可复用/关键输入变化时总控安排定向增量准备。适用标准缺口按消费阶段和owner解决，不在运行依赖中隐藏。
