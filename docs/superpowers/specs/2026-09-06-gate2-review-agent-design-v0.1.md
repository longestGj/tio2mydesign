# Gate 2 Review Agent 设计 V0.1

## 1. 决定与来源

- 日期：2026-09-06。
- 状态：`USER_APPROVED_FOR_ROLE_CREATION`。
- 用户决定：在Spain真实Gate 2实践后，用户指出买家视角审查应由另一个子代理负责，随后明确“把skill改成agent，review agent”，并批准“建立review的agent”。
- 适用范围：Gate 2骨架及完整Buyer Clean Copy的独立预审；不改变现有Gate编号、用户批准权、总控项目审查或后续Gate权限。
- 分层依据：[Agent与Skill分工标准](../../architecture/AGENT_SKILL_SEPARATION_STANDARD_V1.0.md)。审查者需要独立阅读、判断严重度、决定退回与复核，属于Agent职责；现阶段不建立对应Skill。

## 2. Spain实践暴露的问题

Spain第一版执行自检与父级首次审查均未发现两项真实问题：

1. Spain研究只在内部说明中得到追溯，没有充分进入买家实际可见的采购决策内容。
2. `Review Documents`虽然目标URL和内部职责正确，但买家可能理解为可以查看具体文件；真实行为只是进入Documents Hub。

用户后续又在全文中发现英文自然度、行业术语及“实际或预估数量”“Spain交付地点”等转化细节。修订后四模块仍然成立，说明问题不在模块数量，而在实际Buyer Copy是否兑现任务、是否产生正确预期。

因此增加一层独立预审：它位于Gate 2执行Agent之后、总控项目审查之前，由不同子代理承担。它减少执行者因熟悉自己的方案产生的盲点，但不替代总控或用户。

## 3. 角色分工与流程

```text
Gate 2 Execution Agent
  → 独立 Gate 2 Review Agent
  → 原 Execution Agent 返修
  → 同一 Review Agent 复核
  → 总控项目审查
  → 用户确认
```

两步Gate 2均采用此流程：骨架A/C一次，完整B/C一次。Reviewer不得与对应执行者是同一子代理或在同一任务中切换称呼。返修复核优先交给提出问题的Reviewer，以便核对接受条件；若任务不可继续，新的Reviewer须读取原审查及实际修订，不伪装成同一次独立审查。

执行Agent仍负责事实、文件、合同和基础自检；Review Agent负责从买家实际内容出发发现问题；总控负责批准范围、事实权威、跨页冲突、版本组合及是否提交用户。

## 4. 独立读取顺序

Reviewer先按根规则完整读取根AGENTS与PROJECT_CONTEXT。总控再给最小任务合同：Page ID、页面类型、骨架/全文阶段、实际成果绝对路径、审查输出路径及停止点；不在派发摘要中预先告诉Reviewer“应当通过”或复制执行者自检结论。随后对本页任务资料按以下顺序首次判断：

1. 先读A中的实际候选文字或B的完整Buyer Copy；记录第一遍买家理解，不先接受执行者总结。
2. 再读批准Page Intent Card、Gate 1必须回答的问题和用户明确决定，检查承诺是否进入实际可见内容。
3. 再读相关接收页、CTA和共享合同，检查名称、预期与真实行为。
4. 再读C，核对其是否准确映射实际文字、SEO/GEO/Schema和上下游责任。
5. 最后读执行自检，比较执行者声称完成的事项与Reviewer独立发现；不能用自检数字或PASS替代实际审读。

如果骨架把承担核心判断、页面差异或行为预期的内容只写成内部要点，Reviewer不得假设第二步自然会补好；应要求提供足以判断的实际候选文字。

## 5. 审查判断

审查不奖励模块少，也不以字数、问题数量或机械总分证明质量。模块数量由页面任务决定；必要内容应充分，模块职责应清楚，重复和无关内容应删除或下沉。

Reviewer至少判断：

- 必须回答的买家问题是否在实际可见文字中得到回答；只能指向研究、中文说明或C时视为未兑现。
- 买家能否理解页面用途、完成必要判断、选择下一步并知道行动后发生什么。
- 每个标题、按钮、链接和状态文字让买家预期什么，目标页实际兑现什么；URL正确不能抵消名称误导。
- 信息不完整的买家能否继续，例如未知Grade、只有估算数量、不清楚文件类别；不得替下游擅改字段合同。
- Buyer Clean是否存在内部治理语言、重复免责、错误承诺、行业英文不自然或技术术语不准确。
- 正文与C中的Title、Meta、GEO答案、Schema和操作关系是否一致；机器表达不得扩张不可见事实。
- 精简是否删除必要答案，扩充是否解决新的买家问题；不因模板惯性增加模块。

页面类型专项判断按需采用：

| 页面类型 | 专项问题 |
|---|---|
| 国家/市场页 | 去掉或替换国家名后是否仍几乎完全相同；本地研究是否变成采购帮助，而不是行业长文或伪造独特性 |
| Product/Grade | 买家能否理解技术属性、适用边界、文件和下一步；是否把中性关系写成排名、保证或等效 |
| Application | 应用问题、评估条件和已批准Grade关系是否清楚；是否把泛应用说明写成无依据适用承诺 |
| Documents/Resources | 解释、申请、下载、库存与时效来源是否区分；名称是否夸大可获取结果 |
| Conversion | 未知/估算输入、字段帮助、错误、提交中、失败、成功和提交后预期是否真实可完成 |
| Hub/Home | 选择差异、路径和下一步是否清楚；是否用重复介绍遮蔽主要分流 |

## 6. 问题记录与状态

每个问题写明：实际位置和原文、买家可能理解、实际行为或缺口、对判断/行动的影响、严重度、推荐修订和复核接受条件。不要只写抽象原则或一串PASS。

严重度：

- `BLOCKER`：核心任务无法完成，关键事实/行为实质误导，或出现未经批准的重要承诺。
- `IMPORTANT`：必要答案、页面类型价值、行动预期或不完整信息路径存在明显缺失/摩擦。
- `SUGGESTION`：不改变任务结果的语言润色或可选改善；不能以建议项阻止提交，也不能无限改写。

Reviewer只输出两种就绪结论：

- `REVISE_BEFORE_PROJECT_CONTROL_REVIEW`：存在未解决BLOCKER或IMPORTANT，退回原执行Agent。
- `READY_FOR_PROJECT_CONTROL_REVIEW`：没有未解决BLOCKER/IMPORTANT，可交总控；建议项按影响说明。

这些是预审状态，不得写成`PROJECT_CONTROL_REVIEW_PASS`、`USER_APPROVED`、`FULL_COPY_AND_MODULE_ORDER_CONFIRMED`或`GATE2_CLOSED`。

## 7. 返修复核与停止

Reviewer不直接修改A/B/C；把可执行问题交回原Gate 2 Execution Agent。复核时对照每个问题的接受条件、新旧实际文字和C同步位置。局部措辞修改可做定向复核；模块结构、主行动、关键事实或任务路径变化时重走完整买家路径和页面专项判断。

Reviewer保留执行者已正确完成的内容，不借返修增加偏好模块。问题解决后输出`READY_FOR_PROJECT_CONTROL_REVIEW`并停止，交总控；仍有重要问题则保留同一Review ID继续退回。审查报告保存到对应页面`05_review/`，不维护Manifest、Status或用户批准状态，除非总控另行授权具体维护任务。

## 8. 当前验证边界

本角色由Spain实践归纳，但创建时尚未由一个全新Reviewer子代理在下一真实页面中试跑。Spain旧审查不能被追记成“已调用本Agent”。下一次真实Gate 2任务应明确派发独立Reviewer、保存首次审查与返修复核，再根据实际行为修订角色。

探索中的Buyer内容Skill继续保留暂停状态；本决定不安装、删除或改名该Skill，也不声称Review Agent已经运行平台注册。
