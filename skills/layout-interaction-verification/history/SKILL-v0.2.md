# 布局与交互核验 V0.2

对照权威输入与实际成果发现可读性、关系和操作问题。可用于执行自检或独立审查；使用同一方法不会使自检变成独立审查。只写核验报告和必要证据，不修改被审设计、内容、批准记录或他人审查结论。

2026-09-07定向修订：在两个真实页面试跑后采用固定核心不变量与页面专属风险两层核验，区分批准核心证据和诊断支持证据，不比较跨页PASS数量。V0.1保存在[历史快照](history/SKILL-v0.1.md)。

## 输入与范围

接收完整内容与顺序、动作/状态及共享合同、候选源与导出资产、视口与导出比例，以及 `report_path` 和必要的 `evidence_dir` 绝对路径。说明首次检查还是定向复验；复验提供原 Finding、接受条件和变化版本。

实际读取权威输入，不只采信执行方报告。缺少某类输入时只作其余可支持的检查，指出不能验证的具体结论；没有交互源时仍能检查静态图，但不能声称行为通过。已有报告不可擅自覆盖。

正式独立审查另须接收冻结记录。冻结前的协作意见属于预检观察；源、批准组合或正式核心资产在冻结后变化时停止审查并要求新冻结身份，不把旧证据挂到新候选。

## 方法

### 1. 确认被审组合

核对内容、源、图片的版本、状态和尺寸；按实际文件计算字节数与哈希，不沿抄清单。确认资产来自所声称的候选源；发现疑似旧截图时标明不一致，不能把其像素检查结果挂到新版本上。

记录实际拥有的证据：原始文案、静态全页图、状态图、可执行设计源及运行观察。清单标有某状态不证明该状态真的被展示。源与图片无法对应时，不作组合一致性通过结论。

把范围拆成两层，细目见[核心不变量与页面风险模型](references/core-risk-model.md)：

- **固定核心不变量：** 身份、批准输入、完整内容和关系、三端几何/44px、共享Chrome、适用覆盖层键盘/焦点、动作目标与本地/生产边界。
- **页面专属风险：** 从真实表格、长字段、表单、选择、FAQ、来源、媒体或特殊响应转换中产生；无此功能时标为不适用，不创造状态。

检查数量只用于说明本次覆盖，不作为质量得分，也不与其他页面比较。完成结论按“核心范围是否完整、专属风险是否逐项处理、是否仍有Finding/未测”表达。

### 2. 内容和关系双向核对

从输入查到呈现，再从呈现查回输入：

- 模块、标题、正文、表格字段、单位、CTA、帮助和公开来源是否保留且在正确位置。
- 窄屏重排后对象与指标、单位与值、脚注与限定范围是否仍对应。
- 折叠内容是否有可发现入口、完整答案和展开证据；条件隐藏是否符合合同且无空标题、遗留按钮或多余容器。
- 是否出现输入没有的文案、关系、字段或业务承诺；导航和共享法律区是否误用旧基线。

空白字符或自然换行差异可以规范化比对；不能把数值、单位、标点含义或词句变化归为无关格式差异。字串命中只证明文字存在，必须继续检查实际可见性。

当输入合同要求完整显示时，选中值、展开或错误状态也按同一完整性标准检查。已证实的裁切不能因“凭前缀可识别”或“源中有全文”降为建议；合同明确允许摘要或截断时，按该范围处理。

### 3. 查看实际图像并检查几何

每个要求的完整视口先看整体结构，再按可读比例覆盖全页；长图分段且保留足够重叠，避免漏过连接处。重点看最长字段、密集比较、提交区、状态变化和 Footer，同时核对全部模块。

可取得设计源或浏览器几何时，测量页面滚动宽度、溢出元素、容器裁切、文字与控件碰撞、实际可点击区域宽高和大块空白。按任务合同判断阈值；本项目触控目标须核对至少 44px 的宽和高，不能仅测高度。

`scrollWidth = clientWidth` 不足以证明无裁切：`overflow:hidden`、固定高度和文字截断都可能藏住内容。结合边界、样式、实际图像查证。长页面若由真实内容产生，不单凭高度报错；固定空白以其对阅读和操作的影响判断。

只有静态图片时，可依据有记录的逻辑/物理比例核对可见几何；无法证明实际命中区或焦点顺序。缩放预览中的估算不能写成精确 CSS 测量。

### 4. 按任务走通适用交互

在获准的本地交互源中，按页面合同走通主要路径和最可能失败的状态：

- 菜单打开/关闭、键盘可达性、焦点进入/返回与隐藏背景是否仍可聚焦。
- 展开后内容是否完整、状态是否对应、后续布局是否自然移动。
- 选择与取消、允许的选择数量、空值/不完整输入、长错误和提交反馈是否保持字段上下文。
- CTA 的目标与传递上下文是否符合合同；本地无法执行的接收页行为明确作为依赖。

不为完成核验添加表单或虚构状态。实际提交、发送消息及生产操作不属于本方法。成功/错误可用本地模拟验证呈现，但记录为模拟。静态状态图只能证明所示状态外观，不能代替真实菜单操作、焦点测试或数据接收。

每项证据注明`ACTUAL_RUNTIME`、`STATIC_VISUAL`、`SOURCE_INSPECTION`或`LOCAL_SIMULATION`。只有实际运行的行为才能写成运行通过；源码存在监听器、静态图显示展开或检查脚本返回字符串均不能替代操作。页面共享行为在当前冻结组合中仍须核对，但不为增加PASS数量重复生成等价断言。

### 5. 按影响形成问题并定向复验

每个 Finding 包含稳定 ID、文件/模块/视口/状态位置、预期与实见、证据、读者影响、严重度及接受条件。严重度沿用任务项目口径，不另造 Gate 状态。必要时附局部证据及其在全页中的位置；避免用整张长图让 Agent 猜问题。

确定缺陷、有依据的改进建议和未验证事项分别记录。没有缺陷无需为了证明审查深入制造 Finding；如果关键范围没测，不能总结为全面无问题。

复验读取新的实际成果，核对原接受条件及相邻回归；布局改变后检查各主要视口和受影响状态。保留原 Finding ID，并注明本次结果，不编辑旧报告或代替用户关闭 Gate。

## 输出与交回

保存简明报告至 `report_path`：

- 被审对象、版本和实际检查的视口/状态；区分静态检查、运行观察、模拟与未测。
- 最难读/比较的位置、最易失败的操作、最有风险的响应式转换，附最重要证据；无对应内容时说明原因。
- Findings、必要建议和具体未覆盖项；复验仅写本轮改变、接受结果及回归。
- 已检查资产的路径与身份信息，证据路径；原始测量可作附件，不堆逐项 PASS 表。

报告把冻结源、正式三端/状态资产和最终结论列为`approval_core`；详细测量、分段图、逐项动作、失败与复验列为`diagnostic_support`。默认直接审查执行方的正式核心图并保存观察JSON；只有资产来源可疑、渲染不一致、发现Finding或任务明确要求时，才长期保存一整套独立重复栅格图。所有历史与失败仍保留，不因分层而删除。

输出是检查结论，不是设计修订、总控 PASS 或用户批准。写完从同一路径读回并核对证据文件存在、对应正确；失败时报告真实失败，不返回预计路径冒充已交付。

返回 Agent：**报告绝对路径、主要发现摘要、未完成/未验证事项**。由 Agent 判断返修归属和交付就绪情况，独立审查者按其角色权限另行作出结论。
