已有搜索记录可以复用，保留原日期和范围，不描述成今日检索。无法准确限定地区时记录实际可确认条件。

## 3. 工具能力与分工

本Skill须覆盖以下四条路径。能力名称用于设计表达，实际执行须映射当前环境提供的工具接口，不能因为文档写了名称就声称存在同名函数。

| 能力 | 用途 | 证据记录重点 |
|---|---|---|
| `web_search` | 通用网页检索、发现相关来源与代表页面 | 查询、检索时间、返回来源；不能自动称为Google某地区前十名 |
| `web_fetch` | 读取指定URL正文，核对标题、内容、问题与行动入口 | URL、读取时间、实际可读范围、失败或截断；摘要不冒充完整正文 |
| 内置浏览器查询Google | 观察实际搜索结果页面、结果类型、可见顺序及相关搜索功能，并打开代表页面 | 查询、时间、实际语言/地区设置、观察范围，必要时截图；不把单次会话视为所有当地用户的结果 |
| 内置浏览器查询Semrush | 在可访问账号和报告中查询与本次意图分析相关的关键词、意图标签、SERP或其他可用数据 | 查询对象、报告/数据库、国家或地区、日期、筛选条件和页面实际显示的指标口径 |

Google和Semrush均须具备浏览器查询路径，不能只提供API或连接器路径就宣称已满足要求。未来若使用其他入口，应明确实际来源和执行方式，不静默替换。

四条路径是支持能力，不是每次必须全部执行的四步。通常用web_search发现来源、web_fetch阅读正文；需要实际Google结果观察时使用浏览器Google；需要Semrush数据时使用浏览器Semrush。已有有效证据足够时无需重复采集。

`web_fetch`未有独立同名工具时，可映射当前网页打开/正文读取能力，必须核实实际返回内容。正文读取不足时可用浏览器补查；仍无法读取就记录限制，不猜测正文。

Semrush的意图标签作为第三方分类输入，不等于本页最终意图结论；数值按其实际口径记录，未知不补成0。账号未登录、权限不足、额度限制或报告不可用时，说明具体受影响数据；不绕过访问限制、不擅自购买或升级、不编造取得的数据。需要用户登录时由用户完成登录，不要求将密码发进对话。

Google浏览器观察、Semrush报告和通用搜索结果分别标记来源。日期、市场、查询或采集口径不同的数据不得混成一份未标明来源的排名/需求结论。

## 4. 分析方法

1. **明确证据来源。** 区分既有记录与本轮检索，登记查询、日期、语言、实际地区范围和可读内容。
2. **先观察。** 记录结果类型、页面实际回答的问题及行动入口。代表页面打开核对，不能只凭标题贴意图标签。
3. **再解释。** 从观察形成意图解释，同时保留混合意图、其他可能和反例；不为证明原页面定位而选择性采集。
4. **提取问题线索。** 记录来源中实际出现的问题，区分资料线索和研究者推测，不替Agent排序或分配页面职责。

例如，“样本中多个页面讨论分散性”可支持提取相关问题线索，不能直接推出“分散性是所有买家的首要问题”。搜索结果内容也不能单独证明搜索者职业或真实用户需求占比。

## 5. 输出

输出由Agent整合进现有研究报告，不强制新建独立正式报告：

- 分析范围：问题、查询、时间、语言/市场和实际覆盖范围。
- 搜索观察：内容类型、问题和行动路径及来源定位。
- 意图解释：支持依据、混合或其他解释、反例。
- 问题线索：具体问题与来源，不作最终优先级决策。
- 局限与未知：不能确定的内容、访问/数据限制及其对结论的影响。

记录实际使用的工具路径；不要列出未使用工具并暗示已经采集。截图、页面地址、来源记录按可追溯需要保存，不能只交不可核对的结论。

## 6. 质量标准与角色边界

方法质量检查：主要解释是否有观察依据；是否混淆搜索页面内容与真实客户身份/偏好；是否保留反例和局限；是否越权决定读者、关键词归属、模块或CTA。

不以搜索次数、来源数量或报告长度代替质量，不承诺排名或流量。主要读者、买家问题优先级、页面职责、内容取舍、变更建议与最终交付继续由[Gate 1 Agent](2026-09-06-gate1-execution-agent-design-v0.6.md)负责。
