# Gate 4与新Gate 5联合修改方案 V0.1

日期：2026-09-07。用户决定：“可以标记为新的Gate5。然后我们Gate4和新Gate5一起考虑怎么修改。”
状态：NEW_GATE5_ROLE_NAMING_CONFIRMED / JOINT_DESIGN_FOR_REVIEW。新Gate 5命名及独立审查职责获确认；以下接口、状态与迁移是联合设计提案，未切换当前工作流或页面基线。

## 1. 与此前流程对比

| 阶段 | 旧4/5 | 合并后的当前规则 | 拟新4/5 |
|---|---|---|---|
| Gate 4 | 视觉方向 | 完整视觉制作＋内部独立审查 | 完整视觉制作、自检、证据校验、冻结及返修 |
| Gate 5 | 完整视觉制作 | 历史停用 | 独立视觉质量审查、Finding和定向复审 |
| 总控 | 按旧授权批准与推进 | 常设授权关闭Gate 4 | 校验交接与审查适用性，统一关闭4/5视觉组合，不二次完整审图 |
| Gate 6 | 总审 | 跨合同总审与交付 | 继承新Gate 5审查结论，核对差异和开发交付，不再审整套视觉 |

拟流程：0→1→2→3→4→5→6→8→9→10。7保留历史。新Gate 5是原完整Gate 4内部独立审查的显式阶段，不恢复旧Gate 5的整页制作职责，也不增加第二次视觉制作或独立审查。

## 2. 职责、输入和输出

| 对象 | 唯一作者 | 输入 | 输出与停止 |
|---|---|---|---|
| 视觉源与正式执行证据 | Gate 4执行Agent | 批准Gate 2内容、Gate 3结构、品牌/共享合同 | 冻结视觉组合、统一证据索引、自检和机器结果；提交新Gate 5后停止制作 |
| 独立判断 | 新Gate 5 Reviewer | 原始批准要求、准确Gate 4冻结包、作者身份、既有Finding | 独立报告、必要运行证据及技术结论；不修改候选、不签Gate关闭 |
| 关闭与推进 | 总控编排Agent | 原授权、两方身份、机器结果、独立结论及冻结组合 | 统一关闭/推进记录、当前Manifest和Gate 6接收入口；按下一阶段实际授权行动 |

Gate 4保留内部4A方向检查和4B完整视觉制作。4A在同一源验证代表风险，不独立批准；4B包含全部三端、长内容和实际适用状态。4A样例不能代替4B整页核验。

## 3. 联合状态流：不增加两轮批准

执行中：Gate 4 IN_PROGRESS。

源预检通过→锁定源身份→捕获正式证据→统一validator通过→冻结交付组合，Gate 4记COMPLETE_VISUAL_FROZEN / READY_FOR_GATE5（候选完成，不是APPROVED）。

新Gate 5开始独立审查，交回REVIEW_PASS、CHANGES_REQUIRED、REVIEW_INPUT_INCOMPLETE或FAILED。技术状态需在实施时与当前状态字段建立明确映射，不强改历史。

- 页面问题：总控退回Gate 4修订，更新受影响冻结身份与证据，Gate 5按Finding及相邻影响复审。
- 字段/索引问题：Gate 4更正记录，validator复算，Gate 5定向核对；原件和捕获来源可信且未变时不重渲染。
- 报告陈述问题：对应报告作者修正，独立核对相应实际证据。不得由执行者改Reviewer原报告。

Gate 5 REVIEW_PASS且全部关闭条件满足后，总控在一份记录中登记Gate 4成果获准和Gate 5审查关闭，并更新一次当前Manifest。候选就绪或局部返修不默认每次新增Manifest，独立报告版本仍保留。

建议把原Gate 4内部审查及常设关闭授权显式映射到新Gate 4/5联合关闭，保持不增加逐页用户审核。实施时必须保存新的授权解释增补，不能仅因编号为5就声称旧3/4/6授权已自动覆盖所有新情形。授权未覆盖的页面、明确暂停、外发/开发/发布边界均保持。

## 4. 新Gate 5查什么，不查什么

| 必须独立核验 | 不承担 |
|---|---|
| 完整内容及关系是否按批准源呈现 | 重写内容或重新研究定位 |
| 三端视觉层级、可读性、模块连接、品牌及共享消费 | 再制作一套整页视觉稿 |
| Menu/Cookie、hover/focus、表单等本页适用状态和实际操作 | 只看静态图声称交互通过 |
| 源、依赖、图、状态与证据陈述是否对应 | 默认复制执行方整套截图 |
| Finding接受条件及受影响回归 | 编写Gate 6开发映射或提前验收生产实现 |

Reviewer必须不同于被审成果作者。总控仅在具体挑战时要求其核实，不在PASS之后自行第二轮完整视觉审查。真实缺陷不能以减少重复为由放行。

## 5. 证据与机器校验

默认保留：三端整页、可读长页入口、差异性高风险状态图、适用运行记录、统一索引。检查范围完整，保存数量按证据需要；不设硬截图上限。独立审查读执行正式图并独立运行，只有差异/疑点/合同要求才新增图。

validator从文件读取物理尺寸、bytes和SHA；DPR来自真实捕获配置/运行记录，再检查一致性，不能从PNG猜测。颜色陈述需要computed style或图像/运行证据，普通身份校验不能代替。

源冻结与交付组合冻结分开：先有源身份才能采集，证据校验通过后才能冻结交付组合。索引或报告变更更新记录及组合身份，不因HTML未变而假称整个组合未变。Index/Status导航不作为页面冻结阻塞输入。

## 7. 历史与在途映射

| 原状态 | 处理 |
|---|---|
| 旧Gate 5完整制作记录 | 保留旧语义，不当成新Gate 5审查记录 |
| 合并Gate 4已关闭且含有效独立审查 | 视为已满足新视觉制作/审查组合的相应要求，保留原批准证据，不补造历史Gate 5执行身份 |
| Gate 4在途、已授权包含独立审查 | 明确映射该范围到新Gate 5接口，继承准确未变成果，避免重新开工 |
| 只授权制作、明确排除审查或暂停 | 不因新编号扩大；按具体原范围停下 |
| Gate 6/8/9在途 | 继承有效批准视觉输入，不因改号重审或重启 |

历史名称、Review ID、hash和页面批准不批量修改；下一次实质交接在当前Manifest注明有效等价关系即可。
