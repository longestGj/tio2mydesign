# 内链核验 V0.2

核对“批准关系—链接实例—最终落点”，返回证据、覆盖和差异；角色负责授权、语义裁决、问题归属及阶段决定。方法源未作全站实测，不假设已安装爬虫或自动化工具。

## 输入与模式

读取任务给出的审查范围、站点/语言/环境允许列表、页面登记与URL映射、计划发布集合、批准链接合同/接受条件、共享配置、实现与运行身份、既有证据和输出位置。

`PLANNING_REVIEW`只比较预期关系；`RUNTIME_REVIEW`核对实际页面。缺数据列明影响，不能把未检查标为PASS。定向复验另读原Finding、修复版本、变化及共享消费者。

## 允许与禁止

| 允许 | 禁止 |
|---|---|
| 复用身份、环境及覆盖可证明一致的结果 | 不同版本、语言或菜单状态无依据共用PASS |
| 批量解析与请求支持人工语义判断 | HTTP 200、测试数量或零断链替代语义核验 |
| 区分已发布页面、计划目标、依赖和建议 | 未开发目标一律删链，或所有404一律降为无关依赖 |
| 对共享同因问题合并报告并列实例 | 去重时抹掉各页不同锚文本、参数或实际组装 |
| 只读检查获准导航和公开页面 | 自动提交表单、跟随退出/删除/业务动作或扫描未授权域名 |
| 提出缺入口、路径和上下文优化机会 | 固定链接配额、全互链、无依据改URL或产品关系 |

## 1. 建立应检集合

用批准登记/发布集合和已知路由作为独立页面清单，再与实际导航、页面及可用sitemap对照。仅从首页爬到的页面不能证明不存在孤立页；sitemap收录不等于有买家入口。区分明确不需公开入口的功能页与应被发现的内容页，判断须有合同依据。

保存批准URL与实际预览URL的映射；保持语言、site_scope、路径及参数语义。记录缺失/未授权页面，不能以爬虫发现新URL作为创建页面批准。

## 2. 提取链接实例

规划模式读取页面及共享合同，保存预期目标和动作。运行模式从实际DOM提取a[href]、面包屑、导航、正文推荐区及已批准的客户端跳转；运行中才出现的移动菜单、展开内容或语言切换分别覆盖。

每实例记录来源页面、模块/定位符、锚文本或可访问名称、原href、目标解析依据及状态。相对URL按实际base解析；保留查询参数和fragment。可用归一化键批量去重请求，但不得合并改变语义的大小写、编码、尾斜杠、参数、语言或状态。

区分站内页面、站内锚点、文件、外链、mailto/tel及业务动作。canonical/hreflang/sitemap用于目标身份辅助，不算可见内链。发现越scope或越站目标保存证据，不自动向其发送请求。

## 3. 核验技术落点

使用当前可用工具及其说明，在任务允许范围限制并发、深度、重定向次数及访问频率；记录实际限制与未覆盖部分。身份检查和无副作用导航可执行，业务请求不得为“测链接”自动触发。

保存请求URL、每跳状态和Location、最终URL与页面身份。HEAD结果不可靠或被拒绝时按授权以GET/浏览器确认；超时、403、429和登录墙归为访问/环境证据，不武断认定断链，不无限重试。

检查404/5xx、循环及错误落点；200仍查看是否错误页、首页fallback、错误语言/站点或非预期内容。正常重定向不自动判缺陷，按批准目标和路由合同判断。浏览器锚点须确认目标实际存在并能定位，不能只比较字符串。目标可访问不能推导已获发布或最终URL批准。

## 4. 判断关系与路径

结合每个不同上下文核对锚文本承诺与目标内容，检查产品/应用关系是否有批准来源。共享相同语义组件可统一判断，各消费者仍验证实际组装及页面特有状态；不把一个控件通过推导全部控件通过。

对计划公开集合计算可见入链与从批准入口的可达性，列出无入口、环路或中断候选，再核对是否有意设计及合同要求。不以通用点击层级阈值自动判错。针对批准买家任务检查市场→应用/产品→文件/询价等实际适用路径，不强加所有页面都经过相同顺序。

缺少预期合同与可选改善分开：无法裁定时标NOT_VERIFIED或待owner决定；明确实现偏离记Finding；纯优化记建议。不擅自把另一页的产品声明或主关键词迁入本页。

## 5. 证据与定向复验

链接清单保留来源实例到目标的边；请求证据可按等价目标去重。每项关联实际时间、运行版本、环境/数据模式、状态、采集者和证明范围。截图只用于需要说明可见位置、错误内容或状态的问题；不默认逐链接留图。

共享变更检查实际受影响消费者及语言/状态；单链接修正检查原实例、最终落点和相邻路径。只有版本/环境/数据与变化分析支持时继承旧证据，沿用原ID和原时间。没有变化不能无故重扫全站，有反证不能用旧PASS回避。

交回链接清单、问题及核验记录，可合并入现有报告/索引。报告列应检、实检、跳过/失败及原因；结果按PASS/FAIL/NOT_VERIFIED/NOT_APPLICABLE逐项映射，不能因工具结束或找到首个问题停止其余授权覆盖。保存后读回链接与证据索引，清除凭据和无关个人信息。没有真实执行的数据明确标为规划或未验证。

## 任务选择与问题交回

总控在四个时点按有效任务范围启动：一批Gate 6交付包就绪后做PLANNING_REVIEW；一批Gate 8交回进入Gate 9时做RUNTIME_REVIEW；修复后定向复验；发布准备时对明确发布集合做全站关系与覆盖核对。默认按开发批次组织，共享导航统一核验、各页确认组装，不逐页重扫全站。复用相同版本/环境/范围的有效证据；未开发目标如实登记依赖，阻断按合同判断。已有任务授权覆盖专项时直接衔接，不重复询问；无明确对象、环境或有效授权只做准备。时点规则不自动创建定时任务或授予发布权。

三类直接归属：批准目标正确但实现链接错误交Gate 8；交付包遗漏、目标映射错误或验收要求不清交Gate 6；锚文本、正文或产品关系含义错误交Gate 2／内容负责人。其余一律交总控，包括架构/URL调整、共享导航、未开发目标依赖、优化建议、缺项及责任不明确的问题；内链Agent不得自行向其他owner派发。共享导航问题即使表现为实现错误也先交总控协调。 方法只标注类型、依据和建议去向，实际派发沿用已有授权及稳定Finding ID。
