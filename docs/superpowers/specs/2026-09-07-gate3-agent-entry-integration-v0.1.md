## 2. 已接通的职责与接口

| 连接位置 | 当前合同 |
|---|---|
| Gate 2 → Gate 3 | 对齐当前已批准[Gate 2交付结构V0.4](2026-09-07-gate2-delivery-structure-v0.4.md)：A解释模块职责/顺序；B为本页完整可见文案唯一编辑源；C保存稳定页面合同；精确组合与批准由Manifest提供 |
| Agent → 设计方法 | 提供批准输入、共享合同、视口/比例、写入范围、绝对output_dir/report_path；接回设计源、完整导出、内容映射、资产身份和未完成项 |
| Agent → 核验方法 | 提供原始要求、实际候选及身份、视口/状态、绝对report_path/evidence_dir；复验附原Finding与接受条件；方法只写报告和证据 |
| 方法 → Agent | 保存并读回/打开，再返回路径、摘要和未完成项；Agent实际读取报告、查看图像并判断，不能转述摘要代替接收 |
| 执行者 → 独立审查 | 提供原始批准输入、实际源/资产、渲染与状态证据、已知开放项及报告位置；自检单独标识，候选和旧报告只读 |
| 独立审查 → 返修 | 用稳定Finding ID、证据及接受条件交回；执行者只改授权范围内产物，保留旧审查，由独立方复验 |
| 总控 → 用户 | 在对话直接呈现三端及关键状态、取舍与影响；总控通过、用户批准及下一Gate授权分别记录 |

共享文字、导航、Logo、法律与接收行为继续从owner合同继承。C不重复共享全字段不算缺失，SEO/Schema内容不能自动变成新增可见模块。旧页等价成果只映射，不要求A/B/C改名或历史迁移。

本入口把四项风险摘要明确为完整检查之后的报告重点：仍须覆盖全部三端和适用状态，保存所有实质Finding；发现一个问题后继续扫描。此处落实原角色“完整检查”要求，不增设Finding数量或新审批阶段。

## 3. 首次派发时需明确的任务信息

总控在实际派发中明确要求读取`agents/gate3-execution/agent.md`，并提供或指向：

- 已登记Page ID与页面根目录；首次线框或指定Finding返修。
- 当前Manifest、有效Brief、Gate 2全文/顺序批准与Gate 3授权来源。
- 本次允许修改的范围、停止点，以及当前共享合同的查找入口。
- 正式输出位置与版本约定；设计、执行自检和独立审查各自的报告/证据位置。

由执行Agent实际核对这些原始资料，按角色接口读取并使用两项方法。不得将本入口创建授权替换成任何页面的阶段授权，不将这份信息要求变成需要用户重新填写全套Brief的表单。
