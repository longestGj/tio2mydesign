# Gate 2 通用交付结构 V0.6

母版版本：0.1.0（提取候选，尚未安装/发布验证）。运行前读取[实例绑定合同](instance-bindings.md)；本站事实、授权与进度不随方法复制。

## 2. 两步交付保持

| 阶段 | 当前成果 | 用户决定 | 停止点 |
|---|---|---|---|
| Skeleton | A + 本阶段必要的 C | 买家路径、模块职责、顺序和核心候选文字是否成立 | 用户确认前不写 Full Copy |
| Full Copy | B + 完整但精简的 C | 全部真实文案和模块顺序是否确认 | 用户批准前不关闭 Gate 2；Gate 3另行授权 |

每一步仍由 Execution Agent自检、不同 Review Agent预审、总控独立审查和用户确认。局部问题定向返修；只有事实、来源语义、行为、买家路径或结构变化才扩大复查。

## 3. A：Content Skeleton

A 只需让用户和审查者看清实际页面：

- 页面任务和必要买家路径；
- 实际 H1、Hero、模块标题与顺序；
- 每个模块承担的判断或行动；
- 足以审查方向、行为和语言的候选文字；
- CTA、目标和关键上下文；
- SEO Title、Meta、Canonical方向；
- 真正影响本轮决定的开放项。

不要在 A 重复完整 Brief、来源登记、共享合同、逐项自检或每个未采用模块的长篇解释。模块取舍只说明真正可能引起审查争议的决定。

## 4. B：Full Buyer Clean Copy

B 是买家可见文字的唯一编辑源，按最终阅读顺序连续呈现：

- breadcrumb、H1、标题、段落、表格、列表和公开来源；
- 实际 CTA、链接标签、帮助文字；
- 本页拥有的表单或状态文字；
- 页面确实需要的 FAQ、技术表或说明。

内部 Page ID、Gate状态、来源映射、字段键、路由就绪、Hold、验证数字和写作理由不得进入正文。没有真实买家任务时，不为模板增加模块。

纯文案修订只升级 B 和相应返修记录。B 是正文的唯一权威源，C 不保存竞争正文。

## 5. C：稳定的页面特有合同

C 只记录本页新增或改变的稳定合同，不重述共享 owner 的完整规则。默认包含四部分：

1. **身份与稳定内容定位：** Page ID、语言、URL、关键词及C条款对应的B位置标识；当前A/B的精确版本与hash只由Manifest记录。
2. **页面特有动作：** 正文位置、目标、此页传递的上下文、与默认行为不同的限制或决定。
3. **SEO/GEO/Schema：** 精确 Title、Meta、Canonical、实体关系及其 B 中可见依据。
4. **事实与开放项：** 只列 B 实际使用且需要追溯的命题，以及会改变合同的未决问题。

对于共享 RFQ、Documents、Header/Footer 或法律合同，引用当前 owner 文件或稳定标识，只写本页差异。Review状态、Finding、审查人员、交接过程和阶段性结论不进入 C。

### C 版本判断

以下变化升级 C：

- CTA、接收方、预填、提交上下文或动作行为改变；
- 事实命题、第三方来源范围或允许表达强度改变；
- SEO、GEO或Schema语义改变；
- 模块职责、条件渲染或页面特有共享合同差异改变。

以下变化不升级 C：

- 语法、自然度、扫读性或同义措辞修改，且语义边界不变；
- Review verdict、Finding生命周期、复审状态或下一审查人变化；
- 总控意见、用户待确认状态或仅阶段状态同步；
- B 的位置或版本更新，但动作、事实和机器语义均未改变。此时只在当前未批准工作Manifest中更新B指针，不为C制造新版本。

若难以判断，比较修改前后“买家能做什么、系统接收什么、页面声称什么、机器表达什么”。任一答案改变才升级 C。

## 6. 当前 Manifest 与版本纪律

Manifest 只回答“现在用哪一组、批准到哪里、还有什么没完成”：

- 页面身份和当前 Gate状态；
- 当前 A/B/C 的路径、版本、hash和状态；
- 当前 Review、总控决定和用户批准记录的指针；
- 当前开放 Finding 与下一责任方；
- 上一个 Manifest 的路径作为历史入口。

### Manifest 升级条件

只有阶段权威或当前权威组合发生实质变化时新建 Manifest，例如：

- Skeleton 首次形成可审候选组合；
- 用户确认 Skeleton，并授权 Full Copy；
- Full Copy 首次形成新的当前候选组合；
- 用户批准 Full Copy、关闭 Gate 2；
- Page ID、URL、关键词、Gate权限或当前批准 A/B/C 组合改变。

以下事项不新建 Manifest：发现Finding、单句返修、同阶段复审、总控Minor意见、回归检查或C未发生实质变化的B修订。在同一未批准阶段，可在当前工作Manifest中更新文件指针、hash、开放项和审查状态；A/B/C与Review文件本身保留版本记录。已批准Manifest和历史基线绝不覆盖。

Manifest不是时间线。每轮Finding全文和所有中间状态留在Review、返修与决定记录中，不逐行复制到Manifest。一个完整Gate 2通常只需少数几个代表实质阶段的Manifest，而不是为每次审查往返各建一版。

## 7. Review：完整发现，精简报告

Review Agent 使用两遍流程：

1. **Discovery pass：** 从第一个可见元素读到最后一个，检查行动负担、目标语言与扫读、页面特有价值、信息不完整路径，以及适用时的第三方来源精度。发现一个问题后继续扫描；重复问题可以合并，但不得漏掉受影响位置。
2. **Reporting pass：** 排序风险，选择最危险行动句和最弱文案句作为摘要锚点，保存全部实质Finding。无逐项PASS表，也无Finding数量上限。

具名外部公司/品牌、外链、外部产品/市场/监管/统计事实或来源归属表达会触发第三方来源精度检查。对实质命题比较实体、谓词、范围、限定词/日期和链接标签，并记录为：

- `SUPPORTED_AS_WRITTEN`；
- `SUPPORTED_WITH_WEAKER_WORDING`；
- `NOT_SUPPORTED / DECISION_REQUIRED`。

报告列出最高风险来源映射和所有不匹配项；不要求罗列每个已经准确的外链。链接存在、URL命名和网站栏目结构都不能单独证明更强的产品关系、选型、推荐或等效结论。

保存顺序：对象/verdict → 最危险行动句 → 最弱文案句 → 页面特有价值与信息不完整路径 → 条件性来源检查 → Findings/保留项/下一责任方。

## 8. 返修与完成标准

返修响应只写 Finding、前后文字、受影响合同位置和接受条件自检。Re-review验证实际新文字、接受结果和相邻回归；若事实、来源语义、结构、CTA行为或买家路径改变，重读完整交付。

完成标准：

- A/B/C各有一个明确职责，不维护竞争正文；
- Reviewer完成全页和所有适用风险类别后才给verdict；
- 所有实质Finding被报告，报告长度不被用作完整性的替代指标；
- 第三方来源的实体、谓词、范围和链接说明与原来源一致；
- C只因合同语义变化升级，Manifest只因实质阶段或权威组合变化升级；
- 用户在对话中直接看到待决定的模块或全文；
- 当前组合、批准范围和下一Gate权限可由Manifest快速确认；
- 历史版本保留，既有批准页面不因本版自动返工。

## 9. 制作深度与审查分工（V0.5）

本节细化两步流程，不取消任何有效独立审查或用户确认。已有具体批次的连续执行、统一用户审核和串行要求继续按原授权；不能把默认Skeleton等待重新加到已获连续授权的任务。

| 环节 | 应完成的判断 | 不应扩大的工作 |
|---|---|---|
| Skeleton执行与Buyer Review | 全部实际候选文字可理解；模块顺序、页面差异、核心事实和CTA预期足以决定方向 | 不扩写全部段落、全部实例和非关键状态；不要求全文级语言润色；影响理解、事实或行动的措辞必须修正 |
| Full Copy执行与Buyer Review | 所有买家可见文字、页面特有答案、适用状态、行动与来源精度；完整扫描后集中报告全部实质Finding | 不重开有效骨架，不为寻找“最弱句”强造错误或替换同样清楚的表达 |
| 总控独立审查 | 直接读实际A或完整B，核对原始批准范围、事实权威、跨页/共享合同、C与正文/机器语义一致、版本身份、Reviewer覆盖及必修关闭 | 不重写Reviewer已完成的逐句评论或四项挑战报告；有效判断精确引用，不把写作偏好变成第二轮语言编辑 |

总控仍独立形成判断，不凭Reviewer的PASS自动放行。发现实际误导、漏项、证据冲突或不自然到影响理解的文字时必须登记；发现审查覆盖不足时补足对应范围，必要时要求完整重审。总控新增的正文问题由执行方修订、不同于执行方的审查者定向复核，总控可承担该复核，不默认再增加一条完整Buyer Review链。

## 10. 集中返修、停止条件与输入复用

- 初审先完成本阶段全部实际内容及适用风险扫描，再把当前已发现的实质问题集中交回；同类问题可合并，但列全受影响位置。不能发现一句就中断全页扫描，也不能为合并返修隐瞒后来发现的问题。
- 每个required Finding必须写明理解、判断、事实、行动、合同或专业表达的具体影响。两种表达同样准确清楚时按SUGGESTION处理，不阻塞；真实MINOR仍按接受条件关闭。
- 一轮修订集中处理当前全部可处理必修项。局部语法、同义措辞、拼写修改只核对新文字、原Finding和相邻回归；事实、来源语义、结构、CTA行为或买家路径变化时重读完整交付并检查受影响合同。
- 复审沿用Finding ID，在简短版本报告中写接受结果和实际范围，不复制初审全文；可在该报告中用明确分栏保存执行方响应和审查方独立结论，标明各自作者及版本，不覆盖旧报告、不由执行者代写独立PASS。
- 同一责任人已实际读过且身份未变的输入可以复用；交接提供当前Manifest及必要原始来源定位、变化和开放项，不复制完整Brief或共享合同。新的独立Reviewer仍须按规定先读实际Buyer Copy，再读原始依据，不能用摘要替代首次读取。
- 满足阶段要求且必修关闭后即提交。没有新变化、缺口或实际风险，不再发起额外全页重读、润色或报告；用户明确指定的定向修订按其复核与关闭授权执行。

## 11. 文档纪律与轻量耗时记录

继续执行§5–6的版本规则：纯语言修改只更新对应A或B和返修证据；C语义未变不升级，同阶段工作Manifest只更新指针，不新建版本。已批准源不可覆盖。无需单独创建输入卡、四项自检报告、范围报告和效率报告；把必要内容放入既有提交、审查或交接章节。

后续获授权的新执行，在既有提交/审查记录末尾简记实际起止时间、活动类型（读取、撰写、自检、独立审查、返修、落档）和等待原因；同一活动可汇总。不要求逐工具计时，不按文件修改时间推算历史工时；缺失写“未记录”，并行时间不相加冒充单页墙钟时间。计时用于发现成本，不设置字数、Finding或审查轮次配额，不为了达到时限跳过检查。

Gate 2不新增专属Skill；两角色与本合同共同定义方法和独立边界。

## 12. 内容处理方式：决定制作差额，不决定审批

总控提供建议，执行者读取实际输入后确认。在既有提交中记录方式、依据、继承位置及本次变化，不新增准入Gate、必填独立报告或三套模板。可按模块混合使用；Gate 1研究路径不能自动映射Gate 2写作方式。

| 方式 | 条件 | 必须完成 | 禁止 |
|---|---|---|---|
| APPROVED_CONTENT_ADAPTATION 批准内容适配 | 精确正文及有效批准适用于本页 | 继承原文，检查页面组织，补标题、衔接、CTA、内链、元数据和必要合同 | 无故重写、删减、重排批准正文；重复既有专业研究 |
| TARGETED_COMPLETION 定向补齐 | 可用文案已存在，缺口明确 | 补指定内容，检查相邻及完整阅读路径 | 一个缺口扩大为整页重写或重开有效Skeleton |
| FULL_COMPOSITION 完整撰写 | 无完整正文，或原文不适用于本页 | 按现有两步流程组织完整内容并审查 | 把研究报告当正文；强套模块；重做有效研究 |

Gate 1的REUSE_CONFIRMATION也可能需要FULL_COMPOSITION；FULL_RESEARCH也可能只支持一个段落修订。未批准稿可以复用材料，但不得标为批准内容或继承其不存在的批准。只有具体冲突、适用性变化或证据缺口才扩大受影响工作；超出事实/结构等授权的变化先提交决定，不自动升级整页。

## 13. 两步批准与已有成果继承

| 已有状态 | 本次处理 |
|---|---|
| 只有文章正文批准，没有页面Skeleton批准 | A以精确正文位置引用，呈现本页组织及新增文字；用户决定页面安排，不再次批准未变正文事实。不得因文章已完整而提前新增Full Copy全部段落 |
| 同页有效Skeleton已经批准 | 直接承接Full Copy；不重新制作、审查或索取同一Skeleton批准 |
| 完整页面已批准，仅有局部修改授权 | 按原范围定向修改与复验，不自动重启两步流程 |
| 没有有效阶段成果 | 按原Skeleton→Full Copy流程，独立审查和用户确认保持 |

正文批准、页面骨架批准、Gate 2关闭及Gate 3启动分别核对；不存在的批准不得推导。既有连续/批次授权和明确暂停保持，不重复等待已有授权。用户看到完整连续页面，并在独立提交说明中看到本次新增/变化及真正待决定项；批准标记不进入Buyer Copy。

B保持唯一当前页面正文编辑源：批准文章作为不可覆盖上游引用，页面B可完整承接原文并补适配内容，Manifest绑定精确来源与批准范围。后续只在当前B修改页面候选，不并行维护两份可编辑正文；不回写写作侧批准稿。A只作结构与继承位置映射，C不复制正文。文字、顺序或衔接改变语义时按变化范围重新审查与批准，不能把机械复制称为新的专业成果。

## 14. 完整页面审读与专业审查继承

首次Buyer Review仍冷读整页实际可见内容，检查当前上下文、页面职责、买家理解和行动路径。复用既有论证不等于免读、免审；执行者自检不替代独立审查。来源表达精度要求继续适用，核对方式区分：

- 原句、精确来源、审查身份/范围和时效有效且本页使用未扩大：实际读取必要原件和有效审查，核对页面适用性及表达一致性，引用已有专业论证；不重新开展写作侧全套专业研究或逐条联网重查。
- 新标题、摘要、CTA、Meta或Schema改变主体、谓词、关系、范围、限定词或日期：对新增表达完整核验，不由原句批准推导新含义获批。
- 出现反证、时效触发、来源失效、审查缺失/错版本或语义冲突：定位受影响命题、具体证据及最小补查，不能用批准身份掩盖错误。动态监管等按当前有效来源要求处理。

批准原文有疑点时提出REVIEW_CHALLENGE，记录原句、来源、影响及关闭条件，由原内容负责人（写作侧文章交写作侧）定向判断/返修并按适用流程独立复核；事实或范围决定交总控呈用户。执行者和Reviewer均不得静默改写精确批准原文。只阻断受影响决定，继续无关获准工作。

总控直接读实际页面，核对批准、事实权威及跨合同，继承有效Buyer Review，不重复逐句润色。原第7–11节的完整发现、集中返修、独立性及版本规则保持。

## 15. Gate 1→2派发与接收

在既有交接记录中提供或精确引用六类信息，不新建一套档案：

1. Gate 1批准组合、原授权及文件/章节映射；按[三路径合同](GATE1_THREE_PATH_EXECUTION_CONTRACT_V1.0.md)接受等价成果，不强索四份新文件。
2. 批准正文、Skeleton及各自精确身份、适用范围和决定。
3. 可复用研究、来源、独立审查链与时效/局限。
4. 本页新增内容、明确缺口和页面适用性问题。
5. 允许修改范围、冲突及原内容owner。
6. 当前Skeleton/Full Copy/定向返修步骤、剩余用户决定和停止点。

这些信息从已有批准/Brief/交接解析，不让Gate 1额外制作Gate 2骨架。Gate 2读取后决定制作方式及差额；缺关键批准、来源身份或权限时返回具体缺项，不猜测、不自动重做研究。交回实际方式、继承与变化映射、独立审查入口和未决事项；页面唯一Manifest由指定总控维护，执行者只交拟用组合。

## 16. 迁移与验收
