# 模板档案与入库合同 V0.1

本合同属于独立模板资源管理，不是网站Gate。库目录通过任务的`library_root`解析，不把任何客户站点当成通用库。

## 目录与查找

```text
<library_root>/
  README.md
  catalog.json
  templates/<template-id>/<version>/
    TEMPLATE.md
    preview/
    source/              # 仅存已获准提取的资源；可改为准确来源定位
    REVIEW.md            # 或等价、带身份的实际审查记录
```

README说明查找方式与维护者；catalog.json是唯一当前版本导航，按页面任务、类型、资源层级、技术栈和成熟度检索。TEMPLATE.md保存权威档案内容，索引不复制整篇适用规则。候选允许没有source/preview/REVIEW，显式注明缺口，不造空白PASS文件。

每项索引最少含template_id、名称、PAGE/MODULE/COMPONENT、类型/任务标签、当前版本、档案路径和状态。一个ID不因使用项目变化而变化，版本发布后不覆盖旧源。

## 单个模板档案

1. 身份：ID、版本、作者、来源项目/页面、源码路径与commit或内容哈希、来源审查及读取日期。运行预览记录环境和对应实现身份，失效时明确降级。
2. 适用性：读者任务、合适/不合适场景、必需/可选/可重复模块、允许顺序与变体。不用行业名称代替适用理由。
3. 内容与行为：槽位、数据形状、实际验证数量/长文范围、表格/媒体、动作/状态、视口和响应式规则；未知单列，不填猜测上限。
4. 依赖：共享组件ID/版本、技术栈、样式/字体、数据/CMS/API约束；替换依赖时的影响。
5. 本站绑定与权利：固定URL、scope、taxonomy、事实、品牌/媒体、表单接收、缓存/SEO等的处置及允许用途。不把客户原件打入通用包。
6. 预览与取用：代表预览、准确来源或提取资源、必要使用步骤、可取得性和局限。只有源项目路径且消费者无法取得时，不标跨项目代码可用。
7. 核验：结构/视觉/实现三个维度分别记录已验证、未验证、不适用及依据；代码资源须有真实通用输入验证和依赖/业务绑定检查。原站验证范围与抽取后验证范围分别列出。
8. 维护：已知问题、必修/非阻断范围、变更、兼容性和替代版本。适用范围扩张需新增依据。

## 状态与入库条件

- CANDIDATE：已找到来源及可能价值，允许入索引供研究，不代表可直接使用。
- READY_FOR_REVIEW：档案和本次声明的验证材料完整，等待不同身份核验。
- AVAILABLE：独立核验通过、必修关闭、准确资源可取得、允许用途明确；必须注明仅结构可用、视觉可用或实现可用及实际范围，不能笼统称全能力通过。
- SUSPENDED / DEPRECATED：有阻断风险或被新版本替代；保留原因、范围和历史，不删除旧引用。

维护者基于核验结论登记状态。状态仅描述库资源，不是用户战略/事实批准或消费项目适配批准。单纯资料整理不需要新做运行测试；新增代码抽取不能只做档案审查就标实现可用。

问题返回：原件身份/来源疑点交来源owner；抽象规则错误交本角色修订；实现缺陷交获授权开发者；跨项目使用权或范围不清交用户明确。问题只阻断对应资源与用途，不默认封锁整个库。
