# Gate 6执行、独立复核与关闭合同 V1.1

2026-09-07，状态：USER_APPROVED_TARGETED_REVISION / ACTIVE。用户在Gate 6审查结论及修改范围后明确“进行修改。”本合同收紧现行Gate 6执行，不新增Gate或页面权限。总控派发、执行角色和方法共同消费。

## 1. 输入与路径选择

Gate 5上游接收必须先按[共用接收合同](GATE5_GATE6_ACCEPTANCE_CONTRACT_V1.0.md)核对批准bundle、审查链、关闭、启动授权、开放依赖和关闭后变化，记录在现有输入卡。缺关闭/授权或准入对象失配不能仅标ESCALATED_PATH后默认开始完整Gate 6执行；只继续不受影响且已有授权的准备。该合同统一异常路由，不另建接收关。

沿用[总控派发合同](../../agents/project-orchestrator/references/handoff-contract.md)：派发ID、Page/Gate、模式、实际作者/审查者、精确输入及方法基线、原始授权、读写范围、输出与停止点。输入通过当前Manifest、原批准决定、B/C或等价源、结构与视觉冻结、有效独立审查、共享/接收合同准确解析；按根规则必读资料，已读且身份未变的材料可复用。不得要求每个任务通读所有历史。

| 路径 | 条件与范围 |
|---|---|
| `FAST_PATH` | 批准内容/机器语义及结构身份有效，视觉冻结源和关键依赖匹配，有适用的独立审查及关闭，无未关闭必修、无新冲突或矛盾证据。继承上游完整质量结论，核对本次跨合同接口、开发映射、依赖和验收条件 |
| `ESCALATED_PATH` | 上游内容/源/关键依赖变化、批准范围或身份不明、文件缺失、未关闭必修、新事实/URL/机器关系/共享owner冲突，或实际证据与已通过结论矛盾。登记触发、对象、影响、责任方、检查范围和解除条件，只扩大相关检查 |

FAST_PATH不是免审新增交付合同。首次准备包也可走此路径；不能按页型或同日批准自动选择。身份不明先查明差异：角色文件变化不自动等于页面源改变，更不自动触发截图。适用历史Gate 4最终独立审查可继承；新Gate 5报告只在当前有效授权映射内作为该次独立审查依据，不追加第二次视觉审查。

复验沿用原报告、Finding和变化响应，直接检查接受条件及相邻影响，未变有效范围引用。发现关联异常可扩大相关范围并记录原因；不能机械退回全量首审。

## 2. 执行与方法接口

在唯一交付包的简短审查章节或已有报告记录：上游继承身份/覆盖、路径、触发、差异、Finding及未测；不另造范围报告。方法输出仅追加本次增量，不能各写一遍输入、依赖与PASS列表。

一致性方法检查跨合同差异，交付方法建立来源到实现要求及Gate 9接受条件的映射。两者与Agent共用一份实际自检覆盖：新增包要求逐项查回批准来源，适用批准要求逐项找到交付或有效引用。Agent核对覆盖、就绪与具体疑点，不因方法交回重新核验同一要求。

上游视觉有效且无触发时，不调用完整视觉核验、不重新渲染或导出截图、不重跑全部交互。若有实际视觉问题，记录对象并交上游执行者和独立Reviewer修复/复验；明确授权的定向核验只检查触发对象，不自行变成第二个视觉制作方。

不默认重新联网检查所有批准事实。按具体命题的新鲜度、适用日期、冲突和新证据判断；需当前外部依据的结论必须实际核查或明确未验证，不能把“同日批准”当普遍免查条件。未来Gate 9/发布前复核条件按风险登记。

## 3. 输出与独立复核

默认执行方形成一个唯一交付入口：源/原型与依赖、开发映射、差异/Finding、Gate 9条件及后置依赖。可按确有需要分章节/附件，已有表直接引用。综合审查和方法记录可纳入同一包，避免再写重复长报告；不以行数或固定条目数漏掉必要要求。

机器核验结果在已有记录或必要JSON中保存工具/命令、输入身份、实际结果和局限：路径及关键依赖存在性、冻结身份、引用、验收/依赖ID唯一性及映射、错误提前交出/批准状态。使用实际原生命令或已有脚本；统一preflight未实现时不得虚报工具PASS。机器检查不证明语义正确。

执行模式返回`READY_FOR_REVIEW`，绝不自签新包独立PASS。缺输入为`INPUT_INCOMPLETE`，确定待修问题为`CHANGES_REQUIRED`，必要环境/工具失败为`FAILED`；保留可支持的工作和恢复条件。

不同于新包作者的审查者，以`INDEPENDENT_REVIEW`核对同一输入/输出身份、上游继承是否成立、全部新增/修改实质合同、Gate 9覆盖及依赖、所有必修处置。可合并相同规则，但不能仅抽查新增语义。实际读取相应批准源和包，不接受作者自检代替独立判断；不重做有效上游视觉或复制整包报告。复验使用`TARGETED_RECHECK`。

无未关闭必修、无未解决合同冲突、必需范围已覆盖、身份可信、后置项有责任方和接受条件才返回`REVIEW_PASS`。允许后置的生产行为登记依赖，不冒充已测；真实上游违约不得改名后置放行。

## 4. 总控接收、Manifest与停止

Gate 6执行方及Reviewer均不得创建候选/最终当前Manifest；总控核对后统一维护一个当前权威组合。局部返修更新包/审查版本，不默认每轮新增页面Manifest。历史文件保留。

独立复核由身份合格的总控或另一审查者承担，两者择一。已有有效独立PASS时，总控只核对授权、角色分离、输入/成果身份、覆盖结论、必修关闭、依赖及交付入口；发现具体疑点发`REVIEW_CHALLENGE`，不再次重审整个包。若总控实际修改了新合同，必须由另一身份复核。

独立复核与常设授权关闭可在同一记录明确分节记录，角色事实和对象必须可区分；不得为了减少文件省略必要结论。关闭后由总控更新最终Manifest。`APPROVED_FOR_HANDOFF`只是就绪；未实际交出且无回执不记`HANDED_OFF=YES`，不因关闭启动Gate 8、外发或发布。

本合同是总控Gate 6路由的现行增补。[总控初版生效记录](PROJECT_ORCHESTRATOR_ACTIVATION_V1.0.md)中“FAST_PATH尚未实施”仅描述其初版时点；本次启用上述规则路径，没有实现自动编排或统一validator。其他Gate职责与授权保持。
