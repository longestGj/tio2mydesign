## 3. 文件交接合同

设计方法接收 `output_dir` 与 `report_path`；核验方法接收 `report_path` 与必要的 `evidence_dir`。均为 Agent 指定的绝对路径，附允许写入和覆盖范围。缺少路径或关键语义时返回具体缺口，不生成空壳交付。

两项方法均先保存，再读回文字/打开资产，最后返回“绝对路径、结果摘要、未完成事项”。Agent 必须实际读取，涉及图像还要实际查看；不能仅采信方法摘要。

设计资产清单记录尺寸、状态、字节数和哈希，是支持资料，不建立第二份页面当前 Manifest。报告以引用保留输入位置，不复制正文或共享合同。长期正式页面资料按页面目录存放，隔离试验资料与正式页面结果分别管理。

## 4. 方法选择与具体判断

- 布局依据内容关系选择模式：技术表转卡片须保留单位、脚注和比较对象；表单提示与字段/提交位置相邻；长文保留完整答案，页长不作单独失败标准。
- 核验从输入到呈现、从呈现回查输入，兼查遗漏与新增。源里有文字、没有横向滚动或截图已导出，均不足以证明买家完整看得到。
- 静态图、可交互源、实际操作和本地模拟分别记录。触控目标检查宽高，焦点与隐藏背景需实际交互证据；不从截图推出行为通过。
- 用户确认文案有布局问题时先调整结构；必须改变文案/字段语义时交回 Agent 按批准流程处理，不由 Skill 自行修正文案源。
- 表单、表格与长文是适用分支；无真实功能不增加对应状态。不创建第三个截图 Skill，不把单页检查数字写为通用要求。

## 5. 验证方案与当前限制

下表是待执行的验证设计，不是已经获得的测试结果。历史活动只用于选取真实问题，不复制当时的 PASS。

| 场景 | 验证行为 | 失败判据 |
|---|---|---|
| 长技术比较 | 三端转换后逐项检查对象、指标、单位和限定条件 | 数值完整但关系/脚注丢失，或用缩字/截断掩盖拥挤 |
| 表单长说明与错误 | 检查隐私链接、错误与字段关系、表单闭合；有交互源时走通本地状态 | 链接被截断/移到 Footer、错误错配、用静态图宣称焦点已测 |
| 长文与展开 | 检查真实全文、展开后的自然流和完整 Footer | 为缩短页长删文案、展开覆盖后文、只看缩略图 |
| 旧截图/遮蔽缺陷 | 对照候选源与图像；检查零横向滚动却存在裁切的情况 | 只信清单/哈希声明或把 scrollWidth 相等写成全面通过 |
| 文件交接 | 实际保存、读回/打开，Agent 再检查文件 | 预计路径当完成，正文/资产未写入，报告与资产版本不同 |

初次方法试验建议使用隔离的代表性材料：保留原始输入、候选版本、实际产物、失败和修订；构造缺陷须明确标为合成，不混入真实页面权威。设计方法须实际生成资产，核验方法须实际检查；纸面案例推演只证明可解释性。独立前向验证应给予最小原始输入，不提前透露预期答案；若启动独立子代理，按当时任务授权处理。

本轮只执行 Skill 结构校验及文件读回/本地引用检查，尚未证明渲染工具链可用、两项方法可稳定完成任务或完整 Agent 流程有效。后续方法验证不得自动升级成正式页面执行或发布授权。
