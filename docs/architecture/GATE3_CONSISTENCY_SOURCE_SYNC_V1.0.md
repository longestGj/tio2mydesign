## 有限场景验证

依据writing-skills方法，由只读子代理`/root/gate3_sync_probe`在改前直接读取Agent、设计Skill、核验专项和交接正文，未读本轮讨论或项目增补：

- 对四列改两列的判断原文：“按当前交接合同直读，四列改两列须定向交回，不能由Gate 4自行改。”确认直接入口与批准决定冲突。
- 同类模块检查原文：“未要求主动比对所有同类模块。”本轮改为实际相关页面/模块对照，不扩大为全站通读。
- 原有不默认首页、共享owner约束和三端完整内容保障已经存在，予以保留。

修改后同一代理重新实际读取四份正文及Gate 4 Agent、两项制作Skill，五个场景结果：

1. 四列改两列、内容关系和语义不变且无专属几何约束：Gate 4决定并复验，不自动退回Gate 3。
2. 同类Hub的FAQ/后续入口不同：先核对共享规则及相关同类页面，记录差异依据；共享设计缺口交Gate 4/owner，行为矛盾不当作纯视觉差异放行。
3. 文章：不强套首页结构。
4. 已批准共享owner明确几何值：按原范围继承，变化走合同机制。
5. 三端线框与完整内容：不得取消，不得借改布局删除信息。

复测另发现品牌样例Skill的“移动动作”禁止项可能误禁视觉位置调整；已定向改成“改变批准模块顺序、动作职责或行为关系”。代理读回后确认：同一操作区域内、语义/关系/目标不变的按钮位置调整允许由Gate 4处理并复验。

这是小范围规则理解与应用测试，不是独立真实页面制作、视觉验收或普遍可靠性证明。三项修改SKILL.md通过quick_validate格式检查；首次运行因Windows默认GBK读UTF-8失败，使用`python -X utf8`后全部通过，未修改校验器。机器身份与链接检查结果见[验证记录](GATE3_CONSISTENCY_SOURCE_SYNC_VALIDATION_V1.0.json)。

修改前逐字节快照和前后身份见[归档清单](../../90_archive/project-governance/2026-09-20-gate3-consistency-source-sync/source-identities.json)。旧版本合同、标准及基线原样保留。回退须有有效决定；按清单定向恢复本轮规则和指针并重新建立基线，保留并行任务与页面进度，不整库恢复。
