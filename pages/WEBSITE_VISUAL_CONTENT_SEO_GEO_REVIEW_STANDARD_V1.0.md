## 1. Purpose

This document defines the mandatory review standard for all website visual drafts, page mockups, page copy, and front-end implementations in this project.

The goal is not merely to determine whether a page is visually attractive. Every page must simultaneously support:

1. Correct strategic positioning
2. Professional B2B credibility
3. Clear information hierarchy
4. Commercial conversion
5. SEO discoverability
6. GEO / AI-search readability and citability
7. Consistency across the whole website

All future page reviews should use this standard unless a later version explicitly supersedes it.

---

# 2. Core Review Principle

Every page should satisfy four primary criteria:

> **Positioning Accuracy + Professional Credibility + Information Clarity + Inquiry Conversion**

In addition, every page must be structured so that both traditional search engines and AI systems can accurately understand:

- Who the company is
- What the company supplies
- Where the product originates
- Which applications the products serve
- Which markets the company serves
- Which product is relevant to which need
- What factual evidence supports the claims
- What action the visitor should take next

---

# 3. Review Outcome

Every page receives one overall status:

### PASS
The page meets strategic, visual, commercial, SEO/GEO, and credibility requirements. Only optional refinements remain.

### PASS WITH CHANGES
The core direction is correct, but specific issues must be corrected before release.

### FAIL
The page has fundamental problems involving positioning, credibility, information architecture, commercial logic, SEO/GEO structure, or visual-system consistency and should not move to production in its current form.

---

# 4. Issue Priority Levels

All review findings must be classified as follows.

## P0 — Mandatory Fix

Issues that can materially damage:

- Brand positioning
- Product or origin accuracy
- Buyer understanding
- Credibility
- SEO intent
- GEO/entity understanding
- Conversion
- Legal/trade claim safety
- Cross-page architecture

A page with unresolved P0 issues cannot pass review.

## P1 — Recommended Fix

Important improvements involving:

- Information hierarchy
- UX
- CTA visibility
- copy clarity
- internal linking
- component consistency
- content density
- responsive behavior

A page may remain structurally valid, but should normally be revised before release.

## P2 — Optimization

Refinements involving:

- spacing
- image crops
- icon sizing
- microcopy
- typography details
- minor visual polish
- optional enhancement modules

These do not normally block release.

# 5. Mandatory Review Dimensions

Every page must be reviewed across the following nine dimensions.

---

## 5.1 Brand & Visual Standard Consistency

### Review objective
Ensure every page feels like part of one coherent Malaysia-origin titanium dioxide B2B website rather than an isolated template.

### Checkpoints

- Logo usage follows the approved brand standard
- Brand colors and supporting colors are consistent
- Typography, font sizes, weights, and hierarchy are consistent
- Button styles are consistent
- Border radius, shadows, borders, dividers, and card styles are consistent
- Icons use one coherent visual language
- Photography / rendering style is consistent
- The page feels industrial, professional, international, and credible
- The visual language does not feel like a generic chemical-industry template
- The visual language does not become excessively futuristic, decorative, consumer-like, or "AI generated"

### Gate question
> Does this page immediately look like it belongs to the same trusted industrial brand as the rest of the website?

---

## 5.2 Information Hierarchy

### Review objective
Ensure the visitor can understand the page in the correct order.

### Required hierarchy

The reviewer must determine:

1. What the visitor sees first
2. What the visitor understands second
3. What the visitor is expected to do next

### Checkpoints

- H1 is visually dominant and semantically clear
- The hero has one primary message
- Malaysia origin is shown at the correct level of prominence
- Product, application, market, and corporate messages do not compete unnecessarily
- Important supporting copy is visible without overwhelming the hero
- Sections follow a logical decision-making sequence
- Visual emphasis corresponds to business importance
- Decorative modules do not outrank commercial or technical information

### Gate question
> Can a qualified buyer understand the purpose of the page within a few seconds?

---

## 5.3 Page Role & Business Task

### Review objective
Ensure the visual structure supports the specific role of the page in the website architecture.

### Typical page logic

#### Home
Who we are → What we supply → Why Malaysia → Applications / Markets → Proof → Contact

#### Product Page
Product → Key properties → Applications → Technical information → Documentation → RFQ

#### Application Page
Application need → Required TiO2 properties → Selection logic → Recommended grades → Technical support / RFQ

#### Market Page
Market context → Relevance of Malaysia origin → Product / application solution → Supporting facts → Inquiry

#### Resource / Pillar Page
Search intent → Direct answer → Structured explanation → Evidence → Relevant product/application → CTA

#### About Page
Company identity → Malaysia presence → Capabilities → Credibility → Supply / service relevance → Contact

### Gate question
> Does the page perform the commercial and informational job assigned to it in the site architecture?

---

## 5.4 Conversion Path & CTA

### Review objective
Ensure the user has a clear path from information to commercial action.

### Standard CTA family
Prefer a controlled set of actions such as:

- Request a Quote
- Contact Sales
- Request TDS
- Discuss Your Application

Additional CTA wording should only be introduced where there is a clear user-intent reason.

### Checkpoints

- Hero contains an appropriate CTA when the page intent requires one
- Primary and secondary CTAs are visually distinguishable
- Too many CTA variants are avoided
- CTA copy matches page intent
- Long pages provide appropriate mid-page conversion opportunities
- Final CTA exists near the end of the journey
- Product/TDS/RFQ paths are easy to find
- Forms ask only for commercially useful information
- CTA placement does not interrupt technical reading unnecessarily

### Gate question
> After understanding the page, is the buyer's next step obvious?

---

## 5.5 Credibility & Evidence Design

### Review objective
Make the site feel like a real, technically competent Malaysia-based B2B supplier rather than a marketing shell.

### Checkpoints

- Company identity is explicit where relevant
- Malaysia presence/origin is represented credibly
- Product imagery looks technically plausible
- Packaging, production, laboratory, logistics, and application visuals are accurate
- Certifications are only displayed where verified
- Technical claims are supported by approved evidence
- Product specifications are presented professionally
- Contact information is real and visible where appropriate
- Unverified vanity metrics are avoided
- Unsupported claims such as "best", "leading", "No.1", "20+ years", "50 countries", etc. are not used
- Trade, tariff, anti-dumping, origin, customs, or preferential-treatment claims are not made without reliable support

### Important project rule
Product facts, grade positioning, application claims, and technical parameters should be based on:

1. Approved content from mytio2.com
2. Current verified TDS / SDS
3. Approved internal evidence

When evidence is missing, claims must be softened, removed, or flagged for verification.

### Gate question
> Would an experienced international titanium dioxide buyer regard this page as credible and evidence-based?

---

## 5.6 Images, Graphics & Icons

### Review objective
Ensure every visual element proves, explains, or improves comprehension rather than simply filling space.

### Checkpoints

- Product images are technically appropriate
- TiO2 powder imagery looks realistic
- Application images correspond to the stated industry
- Industrial scenes do not contain obvious factual inconsistencies
- AI-generated images are checked for technical errors
- Excessive generic stock photography is avoided
- People/lifestyle imagery does not overwhelm an industrial B2B site
- Icons are visually consistent
- Diagrams communicate real information
- Charts use meaningful data rather than decorative numbers
- Image captions / nearby text clarify relevance when needed

### Test
> If the image is removed, is any useful information, proof, or comprehension lost?

If not, the visual may be decorative and should be reconsidered.

---

## 5.7 Responsive / Mobile Experience

### Review objective
Ensure commercial and technical usability remains strong across desktop, tablet, and mobile.

### Mandatory views

- Desktop
- Tablet
- Mobile

### Checkpoints

- Hero height remains reasonable
- H1 line breaks remain readable
- Primary CTA does not disappear below unnecessary visual content
- Tables remain usable on smaller screens
- Product and application cards remain scannable
- Header/navigation remains simple
- Long paragraphs are broken appropriately
- Forms remain easy to complete
- Images crop correctly
- Sticky CTAs are used only when useful
- Technical information is not hidden purely for visual cleanliness

### Gate question
> Can a mobile visitor understand the proposition, evaluate the offer, and contact the company without friction?

---

## 5.8 Global Component Consistency

### Review objective
Ensure the site operates as a design system, not as a collection of independently designed pages.

### Components to compare across pages

- Header
- Footer
- Hero
- Buttons / CTA
- Product cards
- Application cards
- Market cards
- Specification tables
- Comparison tables
- FAQ
- Download / TDS blocks
- Contact forms
- Breadcrumbs
- Resource/blog cards
- Trust/evidence modules

> Are repeated content types represented by repeated visual patterns?

# 6. SEO / GEO Review Gate

SEO and GEO must be reviewed at the visual-draft stage, not added after design is complete.

A visually attractive page can still fail if its layout prevents search engines or AI systems from understanding the page.

Each page must receive a separate status:

**SEO/GEO Gate: PASS / NEEDS REVISION**

---

## 6.1 SEO Structural Review

### Checkpoints

- One clear primary H1
- Logical H2/H3 hierarchy
- Primary topic appears naturally in the H1 and early page content
- Supporting entities and terms appear naturally
- Core information is available as crawlable text, not only embedded in images
- Important technical content is not hidden in inaccessible visual elements
- Product/application/market/resource relationships have internal-link opportunities
- The page is not an orphan page
- Anchor text describes the destination meaningfully
- Page sections support the intended keyword/search intent
- Content avoids unnecessary keyword repetition
- Similar pages are sufficiently differentiated to avoid search-intent cannibalization

### Review question
> Can a search engine clearly determine the main topic and purpose of this page?

---

## 6.2 Search Intent Match

### Review objective
A visitor arriving from search must immediately recognize that the page addresses the query.

Examples:

- A visitor searching **titanium dioxide for plastics** should quickly see plastics, relevant TiO2 properties, selection logic, and appropriate grades.
- A visitor searching **Malaysia titanium dioxide supplier** should quickly confirm company identity, Malaysia relevance/origin, product capability, and a commercial contact path.

### Checkpoints

- Hero matches intended search intent
- Introductory copy answers the search need rather than beginning with generic company language
- Supporting sections deepen the answer progressively
- Commercial product relevance appears naturally
- The page avoids bait-and-switch between keyword and actual content

### Review question
> Would the search visitor immediately believe they landed on the right page?

---

## 6.3 GEO / AI Search Readability

### Objective
Make the page easy for systems such as Google AI Overviews, ChatGPT, Gemini, Perplexity, and other answer engines to understand, extract, compare, and cite.

### GEO-friendly content patterns

Prefer modules that provide:

- Clear definitions
- Direct answers
- Explicit entity relationships
- Product/application mappings
- Selection criteria
- Tables
- Structured factual statements
- FAQs
- Comparisons
- Supported specifications
- Sourceable claims
- Concise summaries

### Important entity relationships to make explicit where relevant

- IKHLAS TITANIUM (MALAYSIA) SDN. BHD. → company
- Company → Malaysia
- Company → titanium dioxide
- Titanium dioxide grade → application
- Application → required performance characteristics
- Market → commercial/trade need
- Malaysia origin → relevant sourcing consideration
- Product → TDS / technical evidence

### Avoid

- Vague marketing language
- Claims without evidence
- Important facts communicated only through decorative graphics
- Ambiguous pronouns where named entities would be clearer
- Large text blocks without extractable structure
- FAQ content written only for keyword stuffing
- Artificial "AI optimized" phrasing that reduces human readability

### Review question
> Could an AI system extract a precise, factual answer from this page without guessing what the company, product, origin, or application relationship is?

---

## 6.4 Evidence & Citability

### Review objective
Improve the probability that factual content can be trusted and cited.

### Checkpoints

- Important factual claims have an identifiable evidence basis
- Product specifications align with current approved TDS
- Trade-related statements use reliable/current sources when needed
- Numbers include context
- Comparison statements define what is being compared
- Company claims are specific and verifiable
- Dates are included where freshness matters
- FAQ answers are factual rather than promotional

### Principle

> GEO is not keyword repetition. GEO depends on clarity, structure, evidence, entity definition, and answer quality.

---

## 6.5 SEO/GEO-to-Conversion Connection

The desired content flow is:

> **Search Query → Direct Answer → Evidence / Explanation → Relevant Product → CTA**

### Checkpoints

- Informational content connects to the relevant product/application page
- Product pages connect back to application guidance where useful
- Market pages connect to appropriate products/applications
- Resource pages do not become SEO dead ends
- CTA appears after enough information has been provided to justify action
- Commercial links do not undermine informational credibility

---

# 7. Malaysia-Origin Special Review Gate

Because the strategic positioning depends heavily on Malaysia origin, all relevant pages must undergo a dedicated origin-credibility check.

### Checkpoints

- The exact meaning of "Malaysia origin" is internally consistent
- Company identity and product origin are not conflated incorrectly
- Manufacturing, production, supply, export, or origin claims use approved wording
- No visual or wording implies unsupported Malaysian manufacturing activity
- Country flags, maps, factories, certificates, or customs graphics are not used to imply facts that have not been verified
- Anti-dumping, duty, customs, or tariff advantages are not presented as universal guarantees
- Market-specific claims are reviewed against current rules before publication

### Gate question
> Does the page communicate Malaysia origin confidently without overclaiming what has actually been verified?

Unresolved origin-related factual issues should normally be classified as **P0**.

# 9. Copy Review Inside Visual Drafts

Visual review must also flag copy problems visible in the mockup.

### Review for

- Generic marketing language
- Repetition
- Awkward non-native B2B English
- Excessively long headings
- Headings written for decoration rather than meaning
- Copy that does not match the page's search intent
- Unsupported technical claims
- Unsupported trade/origin claims
- Inconsistent terminology
- Inconsistent product names
- Inconsistent company naming
- Weak CTA wording
- Copy blocks that are too dense for the layout
- Critical SEO/GEO content omitted for visual simplicity

Copy should be concise where possible, but never reduced to the point that search engines, AI systems, or buyers lose the factual context required to understand the offer.

# 11. Release Rule

A visual/page draft should not be considered production-ready when any of the following remains unresolved:

- P0 issue
- Incorrect product fact
- Unverified high-risk origin/trade claim
- Broken core search intent
- Unclear page role
- Missing main commercial path
- Major deviation from the approved visual system
- SEO/GEO Gate marked NEEDS REVISION for a core commercial or organic landing page

---

# 12. Working Principle for This Project

Do not review pages based on subjective preference such as:

> "This looks good" or "This looks modern."

Review them based on whether they achieve the site's strategic job.

The final standard is:

> **A successful page must be visually coherent, commercially useful, technically credible, search-discoverable, AI-understandable, and capable of moving a qualified buyer toward inquiry.**
