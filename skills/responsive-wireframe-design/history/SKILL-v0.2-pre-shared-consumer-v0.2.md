# 响应式线框设计 V0.2

把完整内容转成可检验的响应式结构。方法提出并制作布局候选，Agent 对方案取舍、整合和阶段提交负责。

2026-09-07定向修订：在两个真实页面试跑后增加正式渲染前硬预检、候选冻结、核心/诊断证据分层及页面中立共享消费。V0.1保存在[历史快照](history/SKILL-v0.1.md)。

## 输入与交付位置

接收以下输入，可引用既有文件及章节，不要求重新整理为指定模板：

- 页面任务、确认的完整买家文案与模块顺序；明确文案唯一编辑源。
- 本页操作合同及所依赖的共享合同：目标、上下文、选择规则、状态、导航和资产。
- 所需逻辑视口、导出比例、可用设计/渲染工具及允许修改范围。
- `output_dir`：设计源与导出资产的绝对目录；`report_path`：方法说明的绝对文件路径；已有输出的版本/覆盖约定。
- 当前页面中立共享消费包、真实状态矩阵，以及预检记录和候选冻结记录的绝对路径。

缺少内容源、关键语义或路径时，将具体缺口交回 Agent；先完成不依赖该缺口的工作。不得用短占位文案替代完整内容、覆盖未获准替换的文件或推定关键控件含义。项目正式成果不放在 Skill 源目录或仅存临时目录。

## 方法

### 1. 建立内容与结构的对应

按批准阅读顺序列出模块，沿用已有模块标识或章节位置，标明它解决的判断、必须保留的内容关系及适用状态。映射只记录位置与关系，不再抄一份完整正文。

从中选出最可能失效的布局：密集比较、长字段、长按钮或链接、多个选择、状态展开。先识别结构风险，不先套固定网格、页长或卡片数量。

### 2. 保留语义地分组和重排

在已确认模块顺序内安排标题、解释、数据和行动。用内容驱动高度；换行、列数与间距服从可读性。先调整结构，再向 Agent 提出确有必要的内容变更，不能静默缩写、删除或改变事实与行为。

按实际内容选择分支：

| 内容 | 做法 | 必须保留的关系 |
|---|---|---|
| 技术/比较表 | 先判断窄屏是否仍可读；需要时转对象卡片或带标签的记录，不固定所有表都用同一种方案 | 对象、指标、数值、单位、限定条件及脚注对应，避免数值脱离表头 |
| 长文/FAQ | 维持阅读顺序与完整答案；按已确认合同使用目录或折叠；展开后让后续内容自然下移 | 问题与答案、来源与命题、入口与完整展开内容 |
| 表单/选择区 | 标签、必填说明、帮助与错误靠近对应字段；提交说明和反馈属于相关操作区域 | 字段与帮助/错误、选项与选择数量规则、动作与结果；不改字段类型或必填性 |
| 条件模块/无图片 | 按当前合同展示或移除，检查剩余内容自然连接 | 被隐藏的内容及其依赖控件、关联说明、占位容器同步处理 |

例如比较表转卡片，不能只保留卡片标题和数值而丢掉单位；隐私说明换行后，其链接仍应完整出现在提交区域。这些是关系检查例子，不规定所有页面必须有比较表或表单。

### 3. 分别完成各视口和适用状态

TiO2 Malaysia Gate 3 按当前项目标准交付 1440、768、390 逻辑宽度。每个视口完整展示正文及共享组装；Tablet 独立决定列数和密度，Mobile 按完整单列重排。780 物理宽导出只标为 390 logical @2x，不作为 Tablet 证据。其他任务按其提供的视口合同处理。

为页面实际拥有的功能制作初始与关键变化状态；至少包括要求的移动菜单。选择、展开、空值、错误、提交中和结果状态按合同适用，不机械全部添加。不能因为需要演示状态而新造选项、承诺、字段或接收动作。

共享组件消费提供的当前基线，保留固定行动与导航映射。发现共享合同问题交回 Agent，不另造本页版本。内部测量、文件名和状态说明放在页面框外或方法报告中。

TiO2 Malaysia页面后续默认读取[页面中立共享消费包](../../docs/architecture/gate3-shared-consumer-v0.1/SHARED_GLOBAL_CHROME_GATE3_CONSUMER_MANIFEST_V0.1.md)。传入当前一级导航与批准Logo路径，从包生成Header/Footer/Cookie；不得以另一个业务页面的HTML或依赖目录作为新页面母版。包只是规划消费源，具体文字、品牌和行为仍服从其列出的owner合同。

### 4. 正式渲染前硬预检与冻结

先做诊断渲染和实际操作，全部满足后才生成正式资产。完整判据与记录格式见[预检、冻结与证据分层](references/preflight-freeze-evidence.md)。至少确认批准输入与共享来源身份、耐久依赖、B双向内容关系、三端可见性与44px命中区、覆盖层退出/背景恢复，以及本页专属高风险状态。

输出`PASS_FOR_FORMAL_RENDER`记录前，可运行[scripts/check-preflight-record.mjs](scripts/check-preflight-record.mjs)复算候选与依赖hash、拒绝核心源依赖`99_workspace`或其他业务页面，并检查所需判据均有实际结果。该脚本只检查记录和文件身份，不能代替浏览器操作或人工图像查看。

预检通过后记录冻结源的路径、字节、SHA-256、批准输入、共享包和预检记录。冻结之后才导出正式三端和状态图。源发生任何变化即产生新冻结身份；旧图片和旧核验不能继续绑定。

### 5. 渲染、查看并修正设计

选用当前可用且获准的本地 HTML/CSS、SVG 或等价设计源及渲染能力。只用于策划表达；不修改站点实现，不调用 Superdesign。已有可靠源优先复用，不为工具偏好重建内容或品牌。

等待实际字体和素材就绪再导出；记录渲染器、逻辑视口、物理像素、比例和所展示状态。缺字体、缺素材或渲染失败说明影响，不能把替代结果冒充原样还原。

保存完整导出后实际打开查看。长图先看整页结构，再按可读比例分段检查，覆盖首屏、密集区、操作区和 Footer。核对真实文字、关系、触控目标、裁切、异常空白和状态展开。不能以源文件含有文字或截图成功代替视觉检查。

静态状态板仅证明布局；可交互源中实际执行的操作单独记录。演示请求停留在本地模拟，不实际发送表单、邮件或请求外部业务系统。模拟不能被报告为真实接收成功。

## 输出与交回

在指定位置保存可编辑设计源、完整视口导出与适用状态证据。`report_path` 保留：

1. 输入精确版本、内容至布局映射及少量关键取舍。
2. 资产清单：路径、角色、逻辑/物理尺寸、比例、状态、字节数和 SHA-256；注明共同来源版本。把当前冻结源、三端全页、适用关键状态和必要报告标为`approval_core`，把诊断渲染、分段检查、失败、旧候选及详细测量标为`diagnostic_support`。
3. 实际查看/操作范围、仍有问题及需要 Agent 决定的具体变更。

资产清单是方法输出目录，不代替页面当前 Manifest；不登记自身哈希或修改页面批准状态。核心清单引用诊断证据目录，不把每份诊断文件重复列为用户审阅资产。保存后读回报告并打开核心资产，按风险打开诊断证据，确认路径、清单与实际输出一致。文件不足时交回已有成果和缺口，不声称完成全部交付。

返回 Agent：**已保存的绝对路径、结构与关键取舍摘要、未完成事项**。Agent 需实际读取并查看后再综合。设计源变化后更新受影响导出与证据；涉及布局时复查三个主要视口及相关状态。
