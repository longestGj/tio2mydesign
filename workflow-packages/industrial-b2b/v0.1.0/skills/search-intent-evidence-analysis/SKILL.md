# 搜索意图证据分析 V0.2

母版版本：0.1.0（提取候选，尚未安装/发布验证）。运行前读取[实例绑定合同](../../contracts/instance-bindings.md)；本站事实、授权与进度不随方法复制。

把“搜到了什么”与“可能意味着什么”分开。输出供 Agent 综合，不替 Agent 决定主要读者、问题优先级、关键词归属、模块、CTA 或阶段状态。

## 适用性与复用

仅当任务存在影响决定的搜索意图证据缺口时使用。调用方先提供具体问题、已有证据身份/口径、缺失部分及结束条件；已有批准内容或简单工具页没有该缺口时返回不适用理由，不执行搜索、不创建空报告。技术事实缺口不自动要求重做商业SERP；路径由Agent决定，方法不授予Gate权限。

有效原词观察与来源可核对后复用，保留原时间和范围；只有需要更新或缺少对应关系时补查。下文“先原词查询”适用于新采集，不要求重采已有有效原词样本。每轮扩展须对应尚未回答的问题；证据足以支持所需判断、继续搜索不会改变结论时停止。复杂/时效问题按实际要求补查，不用时间上限掩盖关键缺口。

## 输入与工具选择

接收研究问题、原始查询、语言/目标市场、页面背景及已有材料。页面背景不是必须证明的答案。缺少会改变研究范围的条件时向 Agent 确认；无法控制的条件写明实际范围。

同时接收 Agent 指定的 `output_path`：本次 Markdown 方法报告的绝对保存路径。路径由 Agent 按页面目录、任务范围和版本规则确定，不放在 Skill 方法目录。缺少路径时向调用 Agent 请求补充；已有文件但未授权覆盖时，请 Agent 指定新版本或确认更新范围，不自行替换批准成果。

| 路径 | 用途与必须保留的口径 |
|---|---|
| web_search | 发现来源；保留逐条查询及各自返回结果。通用检索不冒充 Google 当地排名。 |
| web_fetch | 打开 URL 核对正文、问题与行动入口；记录读取日期、位置和实际可读范围，摘要不冒充全文。 |
| 内置浏览器 Google | 实际执行查询，观察结果类型、顺序与搜索功能；记录语言、地区、登录/个性化及观察范围，不把一场会话当作全国用户结果。 |
| 内置浏览器 Semrush | 在账号报告实际查询；记录查询、报告、数据库/国家、日期、设备、筛选和指标口径。意图标签是第三方输入，不是最终结论。 |

四条路径均可使用，不要求每次全用。按当前工具文档映射接口：没有同名 web_fetch 时可用网页正文打开能力；浏览器路径不可静默替换为 API 并声称已完成浏览器查询。已有记录保留原采集时间，不重标为今天。

需要登录时请用户在官方浏览器页面输入账号和密码，不在对话或文件收集凭据。超时后先检查当前状态，操作可能已成功；根据状态换读取方式或重试，不盲目重复相同操作。确认登录、权限、额度或服务障碍后说明影响；不绕过限制或擅自购买。未能读到的数据保留未知，不补零。

## 方法

### 1. 原词与扩展查询分层采集

- 先保留原词的实际返回样本及可确认条件，再按问题扩展查询；给扩展标注用途，如技术解释、供应商资料或反例。
- 原词先单独调用检索并保存该次返回，不与扩展词同批提交。只有工具明确逐查询保留结果归属时，扩展查询才可批量执行。若已经拿到混合结果，补做一次独立原词查询；无法补查时只能报告探索线索，不能完成原词分布判断。
- 制造商 site 查询、supplier、TDS 等定向扩展适合找问题线索，不能拿其结果比例证明原词的主导意图。
- 记录实际观察范围和来源选择理由；覆盖不同结果类型，合并同源重复时留痕。不能只挑支持既定定位的页面。
- 旧资料没有逐查询对应关系时如实标记不可追溯；不可倒填来源，也不可用合并样本支持原词的排名、频率或主导性结论。

### 2. 建立可检查的观察链

保留最小链条：`查询及口径 → 返回 URL/标题/可见顺序（若有） → 选择或排除理由 → 正文位置及观察`。原词、扩展、直接访问、历史材料分别标记；正文同一 URL 可引用共用记录，不重复计算。

读代表页面核对实际回答的问题和下一步入口。区分标题/摘要、正文和实际链接：Contact、TDS access 不自动等于 Request a Sample。未记录的入口不能写成已观察；可作为待查问题。

### 3. 解释证据，不推定搜索者

分别写页面内容类型、可能搜索任务及支持程度。供应商页面出现可以支持商业调查这一解释，不能单独证明搜索者职业、采购阶段或当地需求占比。背景中的 B2B 定位不替代研究证据。

至少检查有无其他合理解释或反例；若未发现，说明搜索覆盖，不编造反例。数据不足时保留混合意图或待验证假设，不强行给唯一主标签。结论中的“主要、普遍、多数、反复、优先”等词须有同口径、可数的样本支撑。

Semrush 原词与变体、当地与全球、日期与设备分别记录；不可用不等于 0，单个词的 0 不等于没有需求。搜索页面、第三方标签与正文证据冲突时并列解释，不任选一个覆盖其他来源。

### 4. 提取问题线索

每条线索写具体问题、来源定位及性质：来源明确提出 / 据来源内容概括 / 分析者提出待验证。供应商产品事实不扩成通用事实或本公司的能力。这里只提供线索与局限，由 Agent 决定后续研究和页面取舍。

## 文件输出、检查与交接

复用已有观察时引用其准确位置，仅追加本次差额与解释，不逐条重抄；不能以摘要代替实际读取。Agent综合报告引用观察链，不再复制同一查询/来源表。无新增搜索任务不制作本节报告；确有方法工作时，先将本次方法结果保存为 `output_path` 指定的 Markdown 报告，包含：

1. 分析范围与实际使用路径、日期/语言/市场。
2. 可追溯搜索与正文观察；来源选择及缺失链条。
3. 有依据的意图解释、其他解释与反例。
4. 带来源和性质的问题线索。
5. 未知、访问局限及对结论的具体影响。

使用当前环境允许的文件写入工具保存，然后从同一路径读回，确认文件存在、可读，且上述内容确实已写入。仅提供聊天正文、预期路径或写入工具成功提示，不等于完成文件交付。资料不完整时，报告保存已有结果及明确未决项；写入或读回失败时，说明实际失败，不把预期路径当成已交付报告。

成功交回 Agent 的信息固定为三项：

- **报告路径：** 已保存且读回核对过的绝对路径，可附可点击链接。
- **结论摘要：** 本次主要发现和适用范围，简短概括，不代替报告正文。
- **未完成事项：** 仍未知、未读取或需补查的具体内容；没有则明确无。

该文件是可追溯的方法研究资料，不替代 Agent 的 Gate 1 综合研究报告。Agent 读取文件后负责判断、整合与引用；Skill 不改写其最终页面决策或批准状态。

交回前检查：原词结论是否偷用了定向扩展比例？入口是否真的观察到？内容类型是否被偷换成用户身份/阶段？不同查询、市场与指标是否混算？线索是否冒充读者优先级或页面决定？只声称实际完成的采集与核验，不用次数或篇幅代替质量。
