# Gate 1 输出结构

用于执行前明确成果，以及提交时组织输出。复用当前项目文件结构；这些是信息组成，不要求每个表单独建文件。已有 Brief、研究记录和 Manifest 能容纳时直接沿用。CSV 只在数据规模值得独立维护时使用。

## A. Page Intent Card

| 字段 | 应填写的具体内容 |
|---|---|
| Audience | 主要角色、所处阶段及已知条件 |
| Buyer problem | 这次访问最需要完成的判断 |
| Core message | 一句拟表达的页面核心信息，标明是否已确认 |
| Must include | 用户指定及任务必需内容，保留决定来源 |
| Must exclude | 用户否决、职责排除及有明确依据的禁止内容；不把暂缺资料当作否决 |
| Primary CTA | 做什么、去哪里、对读者的意义 |
| Secondary CTA | 有需要才设置；没有则说明无 |
| Ownership boundary | 本页回答范围、邻页承接内容 |

用户确认状态与 Gate 研究完成状态分别记录。不要为了填满卡片而虚构买家访谈、业务能力或用户决定。

## B. 买家问题与研究结论

每项包含以下字段，可写成紧凑表格或短段落：

`问题 ID / 买家问题 / 问题来源 / 对决策的重要性 / 本页或邻页负责 / 回答要点 / 证据 ID / 内容建议 / 未解决部分`

好例子（说明写法，不是任何真实产品的批准事实）：

“如何判断候选颜料是否适合我的母粒体系？”来自任务中的技术评估目标。回答应区分浓缩体系加工表现和最终制品表现；如资料只覆盖其中一项，另一项列为待研究。页面应解释买家需要提供哪些体系条件，并导向有依据的候选产品信息。不能把工艺标签直接写成性能排名。

差例子：“研究分散性。建议加强专业性。”这里没有实际答案、来源适用条件或可执行的写作建议。

## C. 来源与命题

来源记录：`来源 ID / 类型 / 文件路径或直接 URL / 精确定位 / 发布或资料日期 / 本次读取日期 / 对象与适用范围 / 实际访问结果`。

命题记录：`Claim ID / 拟使用的具体说法 / 关联买家问题 / 来源 ID 与定位 / 来源实际支持什么 / 条件或相反证据 / 用户批准范围 / 当前决定状态 / 对内容的影响`。

将来源事实、用户批准和研究者推断分列。来源没有印日期就注明未提供，不用文件修改日期冒充发布日期。必要的引用遵守来源使用要求，优先写有归属的准确概述。

## D. 搜索与邻页关系

- 当前身份：Page ID、页面类型、URL/暂定状态、语言与关键词归属。
- 新做搜索时：实际查询、日期、观察范围、代表性页面及意图判断依据。
- 相邻页面：重叠问题、各自回答深度、合理的上下游入口。
- 目标链接：Page ID、登记路径、用户任务；真实可用性留给对应阶段验证。
- GEO：主要实体、关系命题、来源和回答候选。不要在 Gate 1 承诺某种富结果或未经核验的 Schema 字段。

## E. 用户决定与后续输入

把待决事项分成影响当前页面方向、影响后续完整文案、后续实施验证三类，注明原因和责任人；优先提出会改变当前工作的决定。状态清单不替代实际内容。

给用户的对话摘要应直接包括：

1. 建议的读者定位、核心信息和主要行动。
2. 页面准备回答的关键问题，以及有依据的答案方向。
3. 相对原输入的实质变化和理由；没有变化就说明沿用。
4. 需要判断的精确表达、适用对象、已知资料与缺口、建议和影响。
5. 批准后的具体下一步，以及已有阶段授权。

写作语言遵循用户偏好；英文页面的关键拟用句子同时展示英文原文和简洁中文说明。参考文件链接放在具体内容之后，不要求用户自己读文件才能判断。

## 提交边界

- 研究任务完成可以提交，不等于 Page Intent 已获批准。
- 用户已确认意图时记录原决定；总控/用户未完成所需审查时不自行关闭 Gate。
- 项目没有要求的重复审计、证明图片或哈希文件不额外创建。项目要求的 Manifest、来源原件和批准留痕按其规则维护。
- 后续 Gate 的详细字段尚未形成时，写明所属阶段，不把它们虚填为完成，也不因此阻止合格的 Gate 1 提交。
