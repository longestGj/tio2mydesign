## 2. 输入处理落到什么程度

角色§2要求先明确Page ID、当前交付步、有效输入、批准范围及停止点，再实际读取Gate 1答案和依据。输入分三类：直接继承、定向补查、冲突或需决定。

已批准答案不重新研究；只对会影响本次内容的问题补查。能依明确权威解决的冲突记录依据；无法解决的具体命题呈交决定，不扩大为整页停工。共享依赖未完成按最终体验设计，留在正确阶段实现与验证。

## 3. 方法选择与交接落到什么程度

角色§3规定按路径/重复、表达/行为、上下文、事实、机器表达五类问题选择必要工作。这是选择条件，不是五个Skill的创建决定。四项质量自检每次交付都做，扩展调查只针对实际缺口。

当前没有Gate 2专属Skill，执行者可直接完成必要判断。使用已有适用方法前核实源文件并读取；支持报告采用绝对输入/输出路径，保存→读回→返回摘要和未完成项→Agent实际读取并综合。文件失败或内容不足时修复交接、补做必要工作或明确缺口，不靠摘要宣称完成。

## 4. 交付与返修怎样收敛

角色§4–6保持先骨架、后全文，两步各自自检→总控独立审查→用户确认。已有有效骨架时直接承接，不重开已完成步骤。

返修按问题定位，检查正文、行动/上下文、SEO/GEO/Schema和基线的连带影响。局部表达直接修订并复查；实质结构或主行动变化按批准范围定向重审。已批准源保留，新候选不覆盖旧批准。满足质量标准即提交，不以增加报告或重复润色代替完成。

## 5. 本轮规则覆盖核对

以下是作者对角色条款的静态核对，不是独立审查、模型试跑或真实买家测试。核对对象是流程能否说明如何处理这些情况，尚不能证明执行效果。

| 情形 | 本版对应处理 |
|---|---|
| 已有批准答案，但本地少一份证据文件 | §2继承准确批准范围，不自动恢复禁止公开 |
| 两模块反复解释同一文件用途 | §3选择取舍去重，§5检查删除是否损失必要答案；不限定所有页四模块 |
| 入口只把产品带入申请却称“找到文件” | §4名称对应实际行为，§5核对目标与预期 |
| 上游想写死单选，下游合同未确定 | §4仅定义意图/上下文，交有权owner决定；已有正式合同则继承 |
| 方法返回成功摘要但报告未保存 | §3修复交接或补做，未读到实际结果不宣布完成 |
| 全文出现需要改变已批准主行动的发现 | §6呈交差异与影响，只重审相关范围，保留旧批准源 |
| 只改一句措辞，其他任务路径有效 | §6局部复查，不重启整页骨架 |

本轮还核对文件引用和历史保留。真实任务行为验证仍未开展，不把文件结构通过写成效率、转化或搜索效果已提升。
