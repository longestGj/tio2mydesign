## 1. Direction

The page is a calm controlled-request utility, not a document catalogue. The visual hierarchy leads from task and receipt boundary to minimum inputs, human review and a single page-primary submission action.

## 2. Shared visual system

- Reference approved shared Global Chrome; do not fork Header, Menu or Footer.
- Desktop Header 84px; Mobile Header 64px; 390px targets at least 44px.
- Preserve `Home | Markets | Products | Applications | Documents | Resources | About | Request a Quote`.
- Request Documents is not a first-level item and has zero false current markers.
- Deep Navy supplies structural trust; white surfaces provide form clarity; Mist separates the transaction from Chrome.
- Teal is reserved for the page action, selected controls and shared terminal RFQ; the two actions stay semantically distinct.

## 3. Page components

- Receipt boundary: translucent Navy panel with a Teal left rule; no file icon, download arrow or approval symbol.
- Step cue: three compact numbered cards; non-clickable and not a wizard.
- Prefill: pale Teal panel with visible removable chips; entire panel disappears when empty.
- Form: centered white card, explicit group titles, persistent labels and restrained spacing.
- Five Document Types: stacked checkbox cards with text descriptions; selection uses checkbox plus border/background, never colour alone.
- Controlled-request note: neutral grey surface, not success or warning styling.
- Review: pale Teal summary immediately before the privacy gate and submit action.
- Privacy: amber dashed internal annotation in review artifacts only; never presented as approved buyer privacy copy.
- Error/failure: red rule, heading and explanatory text; no colour-only meaning.
- Success: Teal rule with receipt-only language; no delivery celebration or download affordance.

## 4. Typography and responsive density

- Compact literal H1; English body copy remains real length.
- Desktop Hero copy is two-column; 768px and 390px are one-column.
- Labels, helpers and error text retain readable contrast at 390px.
- Long company names and five long category labels wrap within controls.
- Form stays single-column at every required breakpoint to protect scan order and error association.

## 5. Interaction language

- Focus: Navy border, white separation and amber outer ring.
- Validation: focusable summary and adjacent messages; entered values remain.
- Submitting: visible progress and duplicate-submit prevention; global RFQ stays enabled as navigation.
- Server failure and retry: preserve values and state that receipt is not confirmed.
- Success: exact heading `Document Request Received`, business-email follow-up and explicit no-document-outcome boundary.
- Other Documentation remains neutral and does not make clarification required.

## 6. Prohibited visual implications

- No download icons, file inventory, available/approved badges, seals, country flags or market-version selector.
- No factory, stock, shipment or certificate imagery.
- No independent regulatory/compliance category, preset or hidden option.
- No Contact fallback, unverified email/phone or response-time badge.
- No page-local Header/Footer link, RFQ OFF state or empty conversion slot.

## 7. Gate 4 result and stop

The V0.3 complete visual set demonstrates this direction. Gate 4 remains `DRAFT_FOR_PROJECT_CONTROL_REVIEW / NOT_APPROVED`; explicit execution authority is not recorded as project-control or user visual approval.
