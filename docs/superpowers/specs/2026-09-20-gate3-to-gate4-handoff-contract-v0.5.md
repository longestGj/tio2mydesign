## 1. 文档控制

- 日期：2026-09-07。

本合同遵守[页面Gate 1–4统一标准](../../architecture/PAGE_GATE_1_4_STANDARD_V2.3.md)和[Agent与Skill分工标准](../../architecture/AGENT_SKILL_SEPARATION_STANDARD_V1.0.md)。Gate 3明确模块顺序、信息优先级、内容/操作关系与跨页复用；Gate 4据此确定共享视觉、列数、尺寸、间距、响应式布局及状态表达。

## 2. Gate 4接收的五类核心成果

| 核心成果 | 必须包含 | Gate 4怎样使用 |
|---|---|---|
| 1. 当前批准入口 | 当前Manifest、Gate 3总控依授权关闭记录、Gate 4授权状态 | 确认Page ID、URL、批准对象、冻结版本与可开始范围 |
| 2. 上游内容与行为指针 | 批准Brief及A/B/C或等价源的精确路径、版本、hash；B仍是可见正文唯一编辑源 | 读取真实文字、事实、CTA、状态和共享合同；不使用交接文件复制出的竞争正文 |
| 3. 冻结结构源 | 可编辑Gate 3线框源、源hash、复现所需正式依赖和资产清单 | 从可编辑源读取内容/操作关系与复用依据，确定完整视觉布局；不凭PNG猜语义关系 |
| 4. 正式结构证据 | 1440、768、390完整线框；必要移动菜单证据；本页结构/操作关键状态；共享完整验证按条件引用，不默认重复三端Cookie图 | 直接查看三端密度、模块连接、真实长内容和状态位置 |
| 5. Gate 3→4交接表 | 锁定项、组件/状态/三端映射、共享owner、可由Gate 4决定的视觉问题、风险与后续依赖 | 成为Gate 4的工作导航，避免重新阅读全部执行历史才知道能改什么 |

五类成果允许直接引用既有文件。每页Gate 3获批后应提供一份简明交接导航，可保存为页面 `05_review/` 下的 `{PAGE_ID}_GATE3_TO_GATE4_HANDOFF_V0.1.md`，也可使用已有报告中包含同等信息的明确章节；当前Manifest指向唯一入口，不重复创建同内容文件。旧页面已有交接无需重做。

状态使用 `READY_FOR_GATE4_WHEN_AUTHORIZED`。文件就绪不等于Gate 4已授权；Gate 4授权仍由页面当前Manifest和用户决定控制。

## 3. 标准交接表内容

### A. 身份与权限

- Page ID、页面名称、语言、URL与 `site_scope`。
- 当前Gate 3批准Manifest、总控依授权关闭记录、冻结线框源及hash。
- Gate 4状态：未授权、已授权或定向返修；明确停止点。

### B. 内容、行为与共享约束清单

- 批准模块顺序、每个模块的读者任务和信息优先级。
- Header、Footer、CTA、目录、表单、表格、FAQ、来源或媒体等实际组件的位置。
- Desktop、Tablet、Mobile的内容与操作关联；列数和视觉排列记录为验证方案，折叠行为按批准合同继承。
- 主要交互的位置与结果语义；哪些行为由共享或接收页owner控制。

这里记录内容与操作关系，引用B/C原文，不复制整页正文。列数、尺寸、间距、视觉位置及响应式排列由Gate 4在共享设计体系内确定并复验；Gate 3线框中的这些值仅为结构验证时的当前方案，不新增为锁定项。保留批准内容顺序、对象/字段关系、信息优先级、行动目标与行为语义。单纯布局变化不自动退回或重开Gate 3；既有页面专属批准或共享owner明确的几何约束仍按原范围继承，确需改变时按合同变更机制处理。

### C. 组件、视口与状态矩阵

| 区域/组件 | 1440结构 | 768结构 | 390结构 | 必要状态 | 正式证据 | owner/继承 |
|---|---|---|---|---|---|---|
| 页面实际区域 | 内容/操作关系与当前验证布局 | 内容/操作关系与当前验证布局 | 内容/操作关系与当前验证布局 | 仅列实际适用状态 | 对应全页/状态图或适用共享证据；注明本页实测 | 页面、Global Chrome、法律、接收页等 |

矩阵用于Gate 4选择代表样例。它不规定视觉颜色、阴影或表面处理，也不要求每个模块单独出图。每个额外状态证据注明解决的结构/操作问题；已被同一证据覆盖的要求直接引用。共享证据必须列出原始报告、来源身份、覆盖和本页实测范围，不能只写“继承PASS”。

### C.1 跨页一致性、视觉基准继承与差异

在既有报告/交接中记录“页面家族—参照页面及批准身份—共享组件/同类模块—本页应用—必要差异及依据—Gate 4待解决事项”。先核对全站共享规则，再比较相关同类页面；不以最新截图、首页或最近完成页自动作为模板。不同表达无法由有效合同裁决时，登记具体缺口和owner，交Gate 4在共享层解决，不另建页面私有变体。

引用任务指定基准的权威路径/版本、批准依据与范围、源/资产身份及适用模块/状态；未指定则明确记录并引用实际品牌/共享合同，不默认首页。交接现有“基准规则—本页应用—继承方式—差异及依据—责任阶段”映射，区分明确锁定项、受控变体、本页专属结构和Gate 4待完善参数。

截图只作对照，不能因更新而覆盖owner；业务页HTML不作母版。共享包和当前批准合同冲突须交owner解决。Gate 4继承明确批准约束并完成完整视觉；不重新发明已锁定规则，不要求Gate 3先完成纯视觉打磨。

### D. Gate 4可决定与不可决定

Gate 4可在批准品牌系统内决定：

- 列数、宽度、响应式视觉排列，以及颜色用途、字体层级、行高、间距尺度和表面层级；调整后核验完整内容、语义顺序、关系和操作；
- 卡片、表格、按钮、表单、引用、图标及适用状态的视觉表达；
- 代表性媒体方向、裁切、替代文本方向和无图片回退；
- 不改变结构关系的自然换行与内容高度；
- 哪些真实区域最适合证明视觉方向。

Gate 4不可自行改变：

- 正文、事实、批准模块顺序、对象/字段关系和信息优先级；
- 控件所属区域、CTA目标、字段类型、必填性、选择数量或结果语义；
- 页面职责、URL、关键词、Schema事实边界及共享owner合同；
- 用视觉暗示未批准的性能、推荐、认证、来源或运行状态。

若视觉制作确需改变不可决定项，按问题归属定向交回Gate 3或内容/行为owner。

### E. 视觉风险与代表样例建议

只写会影响Gate 4取样的真实风险，例如最长技术字段、最密集比较、复杂选择、来源归属、深浅背景切换或无图片分支。每项说明：风险位置、需证明的视觉问题、建议视口/状态。它是任务输入，不预先指定视觉答案。

### F. 共享与后续边界

- 当前品牌、Logo、Global Chrome、法律/CMP及适用同类页面的owner入口。
- 本页导航当前项、固定CTA和共享组件连接规则。
- Gate 3未验证的生产路由、接收、真实设备、读屏等后续事项。
- 视觉阶段仍需完成的全页视觉验证及待处理的纯视觉建议；其编号/衔接按已并行批准的[Gate工作流V3.0](../../architecture/GATE_WORKFLOW_V3.0.md)，完整视觉由Gate 4负责。

## 4. 支持证据不作为默认成果包

下列资料必须保留并可追溯，但Gate 4默认不需要逐份加载：

- 执行自检全文、总控独立审查全文和原始测量JSON；
- 分段查看图、焦点过程图、逐链接检查和身份复算明细；
- 已修复attempt、旧候选、失败截图和返修过程文件；
- 与最终冻结组合重复的独立重渲染图片。

当前Manifest和交接表必须给出这些资料的位置及仍有效Finding。Gate 4遇到身份争议、结构疑问或相关风险时再打开。历史资料不删除，也不进入买家页面或被包装成视觉要求。

## 5. 交接完成标准

Gate 4执行Agent只读核心成果后，应能明确回答：

1. 哪个Gate 3源和哪些三端/状态图已经批准？
2. 本页模块顺序、信息优先级和跨视口内容/操作关系是什么，哪些布局待Gate 4确定？
3. 本页属于哪个家族、参照哪些页面/共享组件、哪些差异有依据，哪些共享设计缺口待解决？
4. 哪些文字、事实、行为和共享组件不能改变？
5. 哪些视觉决定尚未作出，Gate 4应拿什么真实区域来证明？
6. 哪些属于Gate 4完整视觉或后续实现/验收事项？

任何一项只能通过翻查历史尝试或猜测得到，交接尚未完成。缺少关键输入时Gate 4指出具体缺口并继续不依赖部分，不自行补造结构或视觉事实。

## 6. 版本与变更

- Gate 3候选送用户前可先准备交接表草稿；只有独立审查通过、总控依常设授权关闭对应冻结组合后，才标记 `READY_FOR_GATE4_WHEN_AUTHORIZED`。
- Gate 3批准后发生内容/行为或共享约束变化，旧交接表保留历史，按受影响范围升版并重新获得所需批准；未获新批准前旧批准基线继续有效。
- Gate 4从批准结构开展方向与完整视觉制作，不反向覆盖Gate 3批准源。
- 当前Manifest仍是页面唯一阶段入口；交接表是工作导航，不建立第二个状态权威。

## 7. 兼容与审查使用

旧交接、批准图与Manifest原样保留，不因本版要求重做。未来获授权工作按本版交接；旧页显式锁定的约束不自动放宽。纯视觉参数与结构约束存在歧义时读取原批准范围，不由新字段推定用户解除锁定。

Gate 4审查纯视觉建议不反向要求Gate 3清零；若确需改变结构约束，按实际影响定向交回。Gate 6总审继续核对合同一致性，Gate 9按批准最终视觉与行为验证开发结果，不能把Gate 3共享证据继承作为生产免检依据。
