# D16模板库首轮建库与盘点任务书 V0.1

日期：2026-09-12。依据：用户指定模板库放在D16，并要求执行下一步。本文是供D16开发项目接收的任务书；D23仅维护规范，未向其他任务发送消息，未在D16建库或修改代码。

## 对象、入口与授权范围

- 项目：`D:/16Wordpress_nextjs`。
- library_root：`D:/16Wordpress_nextjs/template-library`。
- 来源范围：TiO2 Malaysia首版、`site_scope=tio2-my`的页面与其实际消费组件；其他站点不列入候选。
- 角色源：[页面模板库Agent](../../agents/page-template-library/agent.md)及[入库合同](../../agents/page-template-library/references/catalog-contract.md)。先读取D16根与适用子目录规则。
- 本轮模式：INVENTORY。仅建立库导航和候选盘点资料，不修改业务源码、CMS、路由、缓存、运行配置，不抽取通用代码、不合并或发布网站。

## 执行步骤

1. 检查当前Git分支、HEAD、工作区和已有模板库。保留他人修改，不重置、不清理；若已存在库，先比较合并，不覆盖。记录本轮读取的源commit及有关未提交文件身份，不把整个工作区当作同一个已验收版本。
2. 依据当前站点注册、路由、页面和组件引用定位实际页面，核对有效设计/交付/验收证据。先恢复已有预览入口；入口或运行身份无法核对时标明未观察，不为了盘点重启或部署生产系统。
3. 全范围建立轻量映射，按任务、模块结构、内容类型及行为归组；对代表页和必要差异页定向阅读源码及可用预览。不能只按URL相似分组，也不逐页重新渲染全部截图。
4. 分别识别PAGE/MODULE/COMPONENT候选，记录源码位置、来源身份、共性与差异、共享依赖、固定品牌/URL/scope/数据/表单绑定、许可与验证局限。共享组件引用唯一实现，不复制第二套代码。
5. 给出推荐先提取、暂缓、不值得单独建模板的理由。数量由实际证据决定，不预先规定页型数或模板数。
6. 完成自检后由不同身份定向核对候选分类、代表来源和关键复用判断；不重新审全站，不把盘点PASS写成模板AVAILABLE。核验意见直接写在同一盘点文件的署名部分，若审查制度要求独立文件则引用即可。

## 固定交付

全部写入`template-library/`：

- `README.md`：库入口、来源范围、维护角色、查找方式及当前盘点链接。
- `catalog.json`：按入库合同维护索引；尚无完整档案时使用空entries并链接候选清单，不能填虚假的档案路径或可用条目。
- `TIO2_MY_TEMPLATE_CANDIDATES_V0.1.md`：唯一首轮候选清单，记录覆盖、未读范围、来源身份、分组、代表例、变体、依赖、本站绑定、已有验证/未知、建议及审查。

本轮不强制每个候选创建TEMPLATE.md、preview、source或REVIEW，先做清单再确定提取范围；不预建所有模板空文件。实际进入建档时才创建`templates/<template-id>/<version>/`。原始代码、设计和证据留原位。

## 交回与停止

交回实际绝对路径、作者/审查者、来源身份、盘点结论及未决项。按D16有效Git规则仅提交本轮核验变更，不夹带他人工作。到候选清单和优先提取建议完成即停止；代码抽取、通用化验证、批量建档与AVAILABLE入库不由本轮自动启动。

若源页面不存在或实现身份不清，指出具体缺项并继续其余可定位范围；运行入口不可用不伪造视觉结论。模板库独立于W1–W5和Gate，不更改原页面状态。
