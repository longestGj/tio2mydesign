# 本地 Git 版本管理 V1.0

日期：2026-09-07。用户要求对当前项目开始使用Git。

## 范围

仓库根为 `D:\23MySec`，初始分支为 `main`。首次提交保存引入Git时的文件快照，包含根入口、agents、skills、brand、docs、pages、research和90_archive。它不代表所有候选已获批准，也不能恢复引入Git之前未保存的修改过程。

当前只建立本地仓库，不创建远程、不推送、不公开资料。Git提交不等于页面Gate关闭、用户事实批准、开发授权或发布。WordPress/Next.js独立开发项目的仓库保持独立。

## 字节、忽略与备份

`.gitattributes`禁止换行规范化及内容过滤，保留已有文件精确字节和Manifest的SHA-256。不得未经核对运行批量换行转换、格式化或Git renormalize。

`.gitignore`排除99_workspace、tmp、test-results、工具缓存、依赖、虚拟环境和本地凭据；正式图片、原型及历史归档纳入。被忽略文件保留本地但不受Git备份保护；历史资料若引用临时诊断文件，这些引用不会因为建立Git而自动成为可移植依赖。Git本地仓库与原资料在同一磁盘，不代替异地备份。

## 后续工作

每次修改前检查`git status`和适用项目规则。按具体任务路径暂存，查看`git diff --cached`再提交；初次全量基线之后，不用全库暂存混入其他任务的在途工作。提交说明标明改了什么及原因，页面阶段批准仍以原记录和Manifest为准。

多任务共享工作区时，不覆盖其他任务的修改，不用reset --hard、clean或整份恢复清理他人工作。需要隔离时按任务范围使用独立分支/工作树，并核对原型绝对路径与共享依赖。Git不替代现有版本化批准文件；旧批准源和历史记录继续保留。

Git身份沿用电脑已有配置，不修改全局身份。远程仓库、可见性和上传范围在有明确目标与授权后再配置。
